# 会话即刻沉淀（Session Sediment）— xingtu 版

> 定位：会话结束/阶段性完成时，把**本次会话的全部价值**沉淀进行途素材库，便于后续复用与跨会话断点续传。
> 来源：磐石 harness 版（session-sediment ultracode）+ 行途素材库实践（元宝对话挖掘/黄金会话萃取）本地化适配。
> 原则：**先查后写**｜**单一事实源**｜**增量沉淀**｜**不破坏**（禁 rm，追加式）。

## 跨会话通用沉淀偏好（写记录时遵循）

| 偏好 | 要求 |
|------|------|
| 统一 frontmatter | name/description/metadata(type, originSessionId, modified) |
| Why + How to apply | 每条记忆记原因 + 可执行动作 |
| 索引登记 | 新增即登记到对应索引（MEMORY.md / 归档索引） |
| 纠偏即时机械化 | 高频纠偏 → 沉淀为铁律/清单，错只犯一次 |
| 决策链记 Why | 记推理依据，不只结论 |
| 断点续传清单 | 待办 + 环境备忘，供压缩恢复 |
| wikilink 双链 | [[name]] 形成记忆网络（Obsidian 友好） |
| 会话原始索引 | 附 originSessionId 路径可溯源 |
| 中文 + 简明 | 中文输出，省 Credits |
| 诚实讲局限 | 不夸大成败，数据双向交叉 |
| 时间戳纪律 | 精确到秒，写前 date 取真值禁编造 |
| 不擅自产出文档 | 先询问用户再建总结/说明 |

## 触发条件

以下任一触发：
- 用户说：沉淀会话 / 会话沉淀 / 总结会话 / 记录会话 / 反哺 / 关闭会话 / 复盘本次 / 保存偏好 / 入库素材 / 萃取会话
- 会话压缩前、长任务阶段性完成、有新偏好/设计/想法值得复用
- **内容创作任务完成时自动触发**（图文版定稿 / 听友好版派生 / 发布完成 / 完结检查通过）
- **每日结束时自动触发**（更新 memory 日志，对齐 PUB-026 完结检查）

## 核心流程

### Step 0: 前置侦察（先查后写）

```
grep 已有 04_会话与复盘 + 素材库/黄金会话萃取* 相关 → 判断本次是否新增价值
确认沉淀落点（会话复盘 / 素材卡 / 选题池 / 元宝素材），避免重复造
```

### Step 1: 盘点成果（交付物清单）

逐项列：`交付物 | 位置（绝对路径）| 状态（✅/🔵/⬜）`
涵盖：代码改动 / 文档 / 分析卡 / 工具脚本 / Skill / 模板 / 数据验证结果

### Step 2: 提炼关键决策链（Why 优先）

从对话提取**决策**（不只结果）：`决策 | 依据 | 备选弃用原因`
例：抓元宝全文用 curl 伪装 UA 而非登录态——理由本地零 token 且无需维护登录态

### Step 3: 提炼 AI 协作模式（跨会话复用）

识别本次用了哪些协作模式 + 用户的纠偏偏好：
| 模式 | 本次实例 |
|------|---------|
| 批量操作 / 流水线 / 蒸馏提炼 | 具体到操作 |
| 用户纠偏（格式/术语/表述/设计） | 每条一句话 |

### Step 4: 提炼沉淀资产（可复用物）

识别本次产出的**可复用资产**：`资产 | 位置 | 用途`
（脚本/表索引/SOP/模板/看板——后续会话可直接复用）

### Step 5: 提炼 UI-UX / 设计偏好

若涉及海报/HTML/前端/看板，提取设计决策（认可 vs 否掉），关联到：
- 看板设计偏好（如行途蓝 #056DE8 / 低饱和清透色 / 深空近黑底）
- 素材卡排版偏好

### Step 6: 踩坑教训（BCI 候选）

识别本次踩坑：`坑 | 根因 | 应沉淀铁律/红线`
有价值的提炼为清单条目（如 `素材库/避坑清单.md`），防复发。

### Step 7: 沉淀到落点（追加式，不覆盖）

| 落点 | 更新方式 |
|------|---------|
| `04_会话与复盘/会话记录_{日期}-{主题}.md` | 新建 |
| `素材库/黄金会话萃取_{日期}.md` | 追加（今日已有则续写） |
| `01_灵感与选题池/2026-选题池.md` | 追加新选题行 |
| `素材库/素材卡_{主题}_{日期}.md` | 按需新建 |
| 时间线主索引 | 追加重要节点 |

### Step 8: 产出「继续会话提示词」

```
# 继续会话 — {任务名}
## 任务上下文 → ## 已完成（勿重做）→ ## 关键文件 → ## 待办 → ## 当前问题
```

### Step 9: 输出沉淀报告

```
## 会话沉淀报告
### 成果（N 项）→ 位置
### 关键决策（N 条）
### AI 协作模式 + 纠偏（N 条）
### 沉淀资产（N 项）→ 可复用
### UI-UX 偏好（N 条）→ 反哺看板/素材卡
### 踩坑教训（N 条）→ 避坑清单候选
### 继续会话提示词（已产出）
```

### Step 10: 内容创作专项沉淀（仅当本次会话涉及内容创作时执行）

如果本次会话产出了文章/成稿/听友好版/短视频脚本，额外执行：

```
## 内容创作沉淀
### 成稿清单
| 编号 | 标题 | 形态 | 位置 | 状态 |
|------|------|------|------|------|
| B11 | 技术人的复利 | 图文版 | 素材库/成稿/ | ✅ 定稿 |
| B11 | 技术人的复利 | 听友好版 | 素材库/成稿/ | ✅ 已派生 |

### 完结检查（PUB-026 七项 Gate）
- [ ] 图文版定稿
- [ ] 听友好版已派生
- [ ] 短视频脚本版已派生
- [ ] 平台差异化适配
- [ ] 隐私扫描全绿
- [ ] session 沉淀已执行（本步骤）
- [ ] CHANGELOG 已回写

### 内容创作决策链
| 决策 | 依据 | 备选弃用原因 |
```

### Step 11: 每日 memory 维护（每日结束时执行）

更新 `.workbuddy/memory/YYYY-MM-DD.md`，append-only 追加：

```
## YYYY-MM-DD 工作日志
### 今日完成
- [成果1] → [位置]
- [成果2] → [位置]

### 关键决策
- [决策] → [依据]

### 明日待办
- [待办1]
- [待办2]

### 内容创作进度
- [文章编号] [标题] [状态：草稿/定稿/已发布/已沉淀]
```

> 🔴 **断更修复铁律**：如果发现 memory 日志有断更（某天没有记录），必须在下次沉淀时补写断更日的摘要，从 WorkBuddy jsonl / 豆包 session / git log 中回溯重建，不允许出现空白日。

## 输出格式

```
① 沉淀了啥（清单+位置） → ② 反哺到哪（vault/素材库/选题池） → ③ 可复用偏好 → ④ 继续会话提示词
```

## 多工具 session 对接（WorkBuddy + 豆包工作 + Claude Code 统一挖掘）

> 目标：不管用户在哪个 AI 工具里做内容创作，session 都能被统一挖掘和沉淀，不遗漏。

### 各工具 session 文件位置

| 工具 | session 文件位置 | 格式 | 挖掘方法 |
|------|-----------------|------|---------|
| **WorkBuddy** | `~/.workbuddy/projects/Users-${AUTHOR}-工作室-xingtu/*.jsonl` | jsonl（每行一条消息） | `ai_collab_miner.py` 增量扫描 + `ai_history_indexer.py` 建索引 |
| **豆包工作** | `~/Library/Application Support/DoubaoWork/Default/`（浏览器内核，session 在 Local Storage / IndexedDB） | 二进制 + JSON | 需通过豆包工作的"导出会话"功能或 `conversation_search` 工具获取；当前会话直接在内存中沉淀 |
| **Claude Code** | `~/.claude/projects/<项目名>/*.jsonl` | jsonl | 同 WorkBuddy，可用 `ai_collab_miner.py` 扫描 |
| **Codex** | `~/.codex/sessions/` | jsonl | 同上 |

### 豆包工作 session 对接方案（当前环境）

由于豆包工作基于 Chromium 内核，session 存储在浏览器 Local Storage / IndexedDB 中，无法直接读取文件。对接方案：

1. **当前会话实时沉淀**：在豆包工作中完成内容创作后，立即触发本 skill（session-sediment），把当前会话的成果/决策/资产直接沉淀到 xingtu 工作区
2. **历史会话回溯**：通过豆包工作的"导出对话"功能导出为文本/JSON，放入 `xingtu-vault/02_内容仓库 (Content Hub)/06_元宝对话挖掘/` 或专用目录，再用 `ai_collab_miner.py` 扫描
3. **跨工具断点续传**：在沉淀报告中记录"本次会话来源工具"（WorkBuddy/豆包/Claude Code），下次在其他工具中继续时可通过 originSessionId 溯源

### session 挖掘优先级

1. **当前会话内存**（最优先，直接沉淀）
2. **WorkBuddy jsonl**（`ai_collab_miner.py` 每日自动扫描）
3. **豆包工作导出文件**（手动导出后扫描）
4. **Claude Code / Codex jsonl**（按需扫描）

> 🔴 **不遗漏铁律**：内容创作成果必须在"产生的那个会话"里立即沉淀，不能依赖后续回溯——回溯会丢失决策链和上下文。

## 铁律

1. 先查后写（grep 已有，不重复造）
2. 单一事实源（同事实只落一处，会话记录指路不复制）
3. 增量沉淀（只写本次新增）
4. 禁 rm / 不覆盖已有重要文件（追加式）
5. 决策链 Why 优先（不只记结果，记依据）
6. 敏感信息脱敏（当前雇主/薪资/入职年限等按用户偏好模糊化）
