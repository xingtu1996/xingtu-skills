## 模型分档与分工（boss 09-18 定，省 token）

一份发布任务里，**判断/设计**与**机械执行**用不同档位模型，强模型不浪费在跑脚本上：

| 档位 | 干什么 | 典型步骤 |
|---|---|---|
| **Turbo / 大模型**（豆包 PRO turbo 等） | 规划、异常排查、需要审美的排版判断、标题/选题决策、撞题研判、封面文案、合规灰度判断、战略与排期 | Step 2 事实研判、Step 3 标题决策、Step 6 排版**方案设计**、任何报错根因排查、Spike/spec 编写 |
| **Flash / 普通模型** | 规格已定后的照做：跑脚本、重渲、grep 计数、dry-run、建稿、draft/get 回查、批量字符串替换、按操作单填表、回收旧稿 | Step 6 四连后处理（规则已定）、Step 8 门禁复跑、Step 9 dry-run/建稿/回查、Step 10 留痕 |

纪律：
1. **规格先行**：Turbo 把方案/规则/验收口径写进 spec 或操作单（含可直接复制的命令、grep 断言、期望计数），Flash 照跑、只回报命令输出，不做开放式判断。
2. **遇异常升档**：Flash 跑出错、断言不符、出现规格外情况 → **停下，提示 boss 切回 Turbo 排查**，不自行发挥、不试错硬绕（Flash 自由发挥是返工之源）。
3. **处理完降档**：Turbo 定位/设计完，明确告诉 boss「方案已定，可切回 Flash 执行」，后续机械步骤交回 Flash。
4. agent 自身在交付物里标注「本步建议档位」，让 boss 知道何时该切模型。

## 十步 SOP（按序，每步有闸门与凭证）

### Step 1 包结构就绪
发布包六目录齐（`01_正文/ 02_排版HTML/ 03_封面/ 04_配图/ 06_发布参考/ 00_标题摘要/`）。正文 MD 唯一 SSoT 在 `01_正文/` 最高版本号文件。缺目录=停下补齐，不带着缺陷往下走。

**frontmatter 须含中文 `状态:` 键**（如 `状态: 成稿 v1 · 待定时发布`）——门禁 `tools/publish_brief.py` 只认中文键，写英文 `status:` 会判「状态未标注」把候选卡在排期外。FDE-03 / FDE-07 双案同源坑，见坑位 17 与 reference §10.1。补键 snippet 就地跑一次即可（原英文 `status:` 保留，追加一行中文 `状态:`）。

### Step 2 事实回源
产品名/榜单名次/外部硬数据逐条 WebSearch 回源，grep 全载体（正文 MD+封面 HTML+每张配图 HTML 源+已渲 PNG）核错名。调用 `mp-prepublish-draft-verify` Step 1。凭证：错名计数=0 全载体。
坑：名字错在配图/封图源上时只改正文=没改（AGENT-03「千问工作」印在图上实例）。

### Step 3 标题撞题核查
WebSearch 双查（带引号精确框架词 + 去产品名结构词）取并集。同题含大媒体 ≥3 = 🔴 回炉 → 交 `mp-title-collision-rename` 全管线（出三候选交 boss 拍板 + 六载体同步 + 封面重渲）。1-2 篇小媒体=🟡 提示。0=✅。
凭证：同题计数+大媒体名单写入操作单。

**标题普世化自检（boss 09-17 拍板入闸门，SSoT=`outputs/账号战略决策_标题普世化与定位_2026-09-17.md`）**：中文钩子前置 + 英文专名至多留 1 个吃长尾（AI 视同通用词不计）；英文专名 >1 或朗读有门槛 = 回炉重起标题。反例：FDE-07《Palantir 的 FDE 拆成两个人：Echo 懂、Delta 造，AI 落地最后 100 米》4 个英文专名，boss 09-17 反馈「标题不太好、人家不好弄」（阅读 pace 对比须同窗口时长，禁拿当日半天 vs 前篇全天直接比）。普世化只动表达层（标题/摘要降门槛），内容层绝不稀释。

### Step 4 图文密度
`图数/千字 ≥1`（PUB-048），A 档长文 8-12 张、每大节≥1 张。不达标交 `pub-infographic-supplement`（文字墙节补信息图，非均匀撒；素材只取正文原文不编造）。
凭证：密度数值 + 补图逐张 Read 眼见。

### Step 5 法律合规
`python3 tools/legal_compliance_scan.py <发布包>`（或 `bash tools/content_gate.sh <包>` 第⑦项）。🔴 阻断必须改后重跑；🟡 是人工核清单给 boss，不自动改稿、不出具法律意见。

### Step 6b 文末（tail_v5，🆕 09-27 起 render_wechat.py 自动拼，不手抄）

> **文末结构由 `render_wechat.py` 自动拼接，不再从 MD 手抄。** MD 正文只写到最后一节"我的判断/核心结论"结束，**不要**在 MD 里写 `## 关于行途` / `## 下一篇预告` / `## 欢迎关注` / `## 延伸阅读`——脚本会自动删这些块并拼上标准 tail_v5。

tail_v5 标准结构（SSOT 在 `tools/render_wechat.py` 的 `TAIL_V5_TEMPLATE`，以 FDE-13 实发成品为基准）：

28. **官方名片 ≠ 模拟卡**：`appmsg_card_context`/`wx_tap_card`/`wx_root` 是 CSS 画的假名片（点击不跳主页，boss 09-17 当场识破「你这不是骗人么」）；真组件 = `<mp-common-profile data-pluginname="mpprofile" ...>`（微信前端 JS 渲染）。SSoT 在 `tools/wx_draft_api.py` 的 `WX_PROFILE_CARD` 常量，**不手抄、不重建**。
29. **名片替换残留垃圾**：用字符串替换旧卡时若只换外层 section 不删内层 div，会残留 `</section>>`+旧卡 div 拼成坏结构（09-17 实测 441 字节垃圾）。**处置**：替换后必 grep `</section>>`、`flex:1;min-width:0;`、`appmsg_card_context` 全为 0；回查草稿 content 名片后应直接接版权行/blockquote，中间不得有旧卡残骸。

31. **md2wechat 渲空段 = 手机端大空行真凶**（09-18 FDE-04 第4节实锤 5 连空 `<p style="margin:0 0 22px"></p>`，boss 反馈「质量保障部分很大空行、挤得变形」）：MD 图片/列表前后空行被渲成空 p，每个占 22px+行高。渲完必删空 p（正则见 Step 6 四连①），grep 空 p=0；draft/get 回查微信端空 p 也必须=0。
32. **嵌套图片占位 p**：`<p style="margin:0 0 22px"><p>【配图：x】</p></p>` 嵌套 → 图片上下多余间距；段中图片（外层 p 同时包占位和正文）→ 占位被夹在段落里。处置见 Step 6 四连②，grep `<p[^>]*><p>【配图`=0，9 张图都应是独立居中图片段。

34. **md2wechat 不认 `<font>` 标签**（09-18 实锤）：`<font size color>` 被转义成 `&lt;font&gt;` 文本显示。所有小字/灰字样式用 `<p style="font-size:..;color:#A8ADB3">`，MD 源同样不写 font；渲完 grep `&lt;font`=0。
35. **文末 tail_v5 定版（09-18，取代 tail_v4 三行）**：分界实线 → 互动+星标一行灰字（`点赞、在看、转发；星标「行途」，第一时间收到下一篇`）→ 红字 `谢谢你看我的文章，下篇见。` → 版权两行（独立 p 不用 br）→ **关键词一行（叫「关键词」不叫「搜索关键词」，3 个词、390px 一行放下，服务 SEO/GEO+合集标签）** → 文末名片。详见 Step 6b。
36. **微信 API 入库样式保留实测（09-18 FDE-04 回查）**：内联 `p style`、h2 `border-bottom`、文末 `border-top`、`margin/padding/font-size/color` 均保留；会被清洗/出问题的是「空 p、嵌套 p、`<br>` 堆在 div 里、非白名单标签 font」。**预判上传变形优先查这四类**，而不是怀疑内联样式本身。
37. **总览图放错位 = 章节被切成几段（09-18 FDE-04 第4节实锤）**：三层门禁总览图错放在引入段与点题句「我们的体系有三层」之间，boss 手机端读感「质量保障很多地方是断开的」。铁律：图在点题句后、展开前（详见 Step 6 图文顺序铁律）；遮图读文字，点题句不得在图之后。MD+HTML 同序。
38. **目录与 h2 序号不一致 / 收尾实质章节漏目录（09-18）**：核心结论是有 h2+配图+五条内容的实质章节，必须进目录且 h2 带序号「8.」；曾误删目录第 8 条导致地图缺章。判据：有 h2+配图+独立内容=进目录；纯文末致谢/版权/名片块=不进。详见 Step 6 目录收录规则。
39. **文末分界线太浅等于没加（09-18）**：`#e3e7ec` 在白底手机端肉眼几乎不可见，boss 反馈「需要分隔线」（线其实在）。统一用 `#d8dce1`；加了分隔类样式必须本地 390px 渲染亲眼确认「看得见但克制」，不能只看源码里有。
40. **🔴 通道选择：禁止用 UI 自动化（computer_use_tool/bu 模块）建稿**（09-19 FDE-05 实锤）：豆包工作里曾用 `computer_use_tool` 的 bu 模块直接操作浏览器塞 HTML 进公众号编辑器——结果塞了整个预览框架、图片成灰框、纯旧 pure 主题、无引子图、无行途导读，boss 当场抓出「不是 UI 自动化，是走 API 的 skill」。**本 SOP 唯一建稿通道 = `tools/wx_draft_api.py`（微信官方 API：token→uploadimg→add_material→draft/add）**。任何 agent 不得用浏览器自动化/DOM 注入/Playwright 操作公众号编辑器来建稿。
41. **🔴 引子图是首屏必选项，不是可选项**（09-19 FDE-05 实锤）：首屏公式「名片→引子图→行途导读→结论→目录」中的引子图，照 FDE-04 成品风格做（白底+左上角红色合集 tag+黑色大标题+红色强调词+灰色副标题+右下角公众号水印），用 `tools/fig_fit.py` 渲 PNG。**不做引子图就不要往下走**——boss 看到没有引子图直接打回。引子图文件名统一 `00-引子图-<主题>.png`，放在 `04_配图/`，正文 MD 开头第一张占位就是它。
42. **🔴 文末 tail_v5 照抄 FDE-04 成品 HTML，不要自己从 MD 重渲**（09-19 FDE-05 实锤）：md2wechat 渲出来的文末是旧版（「关于行途」块+旧致谢+模板 footer），不是 tail_v5。**正确做法**：渲完后直接把 FDE-04 的 tail_v5 HTML 块（`outputs/发布包_2026-09/FDE-04_小团队AI交付方法论/02_排版HTML/公众号_发布版.html` 末尾那个 `<div style="margin-top:30px;padding-top:18px;border-top:1px solid #d8dce1;...">` 整块）复制过来，只改关键词那一行。**不要从 MD 重渲文末**——MD 里的「关于行途」块和旧致谢文字不会自动变成 tail_v5 结构。
43. **删模板 footer 正则不要用 `.*?` 跨标签匹配**（09-19 实锤）：`re.sub(r'<div[^>]*>.*?排版引擎.*?</div>', '', s, flags=re.S)` 这个正则太贪婪，会从前面某个 `<div` 一直匹配到 footer 的 `</div>`，把大段正文删掉（文件从 24KB 缩到 2KB）。**正确做法**：先 `grep -n "排版引擎"` 定位行号，再精确删那一行 div；或用更精确的匹配（含 `border-top:1px dashed` 和 `排版引擎` 两个特征）。
44. **🔴 建稿前必须 boss 本地 HTML 点头，禁止建完再改**（09-19 FDE-05 三建三废实锤）：这次连续建了 3 稿（UI 自动化版/pure 版/缺引子图版），每版都被 boss 打回，草稿箱堆了一堆废稿。**Step 9 本地验收闸门是硬规矩**：改完 HTML → `present_files` 给 boss 看 → boss 说「可以了」→ 才跑 `wx_draft_api.py`。**点头前的建稿 = 未授权动作 + 污染草稿箱**。


45. **🔴 extract_body() 只取 `<section>...</section>`，tail_v5 和核心结论必须包在 `<section>` 内**（09-19 FDE-05 实锤）：`tools/wx_draft_api.py` 的 `extract_body()` 从第一个 `<section>` 提取到最后一个 `</section>`。tail_v5 如果放在 `</section>` 外面（比如直接放在 body 末尾），整个文末块会被切掉——包括"核心结论"整节、互动星标、致谢、版权、关键词全部丢失。**正确做法**：tail_v5 + 核心结论必须包进一个 `<section>` 块里（如 `<section style="margin:0;padding:0;">...tail_v5...</section>`），确保被 extract_body 覆盖到。建稿后验证：正文字符数应该包含 tail_v5 内容（检查"谢谢你看我的文章"是否在构建输出里）。
46. **金句块样式降权（boss 09-19 拍板）**：不要红色 callout box（浅红背景+左边 4px 红竖线+"个人观点："标签）——太抢眼，喧宾夺主。**定版样式**：`<p style="margin:16px 0;padding:10px 0;border-left:2px solid #F2644F;padding-left:12px;font-size:15px;line-height:1.7;color:#2b2f36;"><strong>金句内容</strong></p>`——左边 2px 细红竖线 + 正文黑色加粗 15px，视觉权重低于 h2 标题，像正文里的重点句。**禁写"个人观点："前缀**——好的金句不需要标注"这是我的观点"，观点本身就有力量。
47. **封面网络图不要加文字标签（09-19 FDE-05 实锤）**：黑底封面右侧加节点网络装饰是对的（像 FDE-04），但**网络图上不要加文字标签**（客户现场/Java/硬门槛/驻场等）——手机端缩略图里这些字太小根本看不清，反而显得杂乱。**正确做法**：网络图只留节点+连线做装饰，所有文字信息（标题/副标题/tag/footer）全部放在左侧文字区，确保手机端清晰可读。
