## 模型分档与分工（boss 09-18 定，省 token）

一份发布任务里，**判断/设计**与**机械执行**用不同档位模型，强模型不浪费在跑脚本上：

| 档位 | 干什么 | 典型步骤 |
|---|---|---|
| **Turbo / 大模型**（豆包 PRO turbo 等） | 规划、异常排查、需要审美的排版判断、标题/选题决策、撞题研判、封面文案、合规灰度判断、战略与排期 | Step 2 事实研判、Step 3 标题决策、Step 6 排版**方案设计**、任何报错根因排查、Spike/spec 编写 |
| **Flash / 普通模型** | 规格已定后的照做：跑脚本、重渲、grep 计数、dry-run、建稿、draft/get 回查、批量字符串替换、按操作单填表、回收旧稿 | Step 6 四连后处理（规则已定）、Step 8 门禁复跑、Step 9 dry-run/建稿/回查、Step 10 留痕 |

纪律：
1. **规格先行**：Turbo 把方案/规则/验收口径写进 spec 或操作单（含可直接复制的命令、grep 断言、期望计数），Flash 照跑、只回报命令输出，不做开放式判断。
2. **遇异常升档**：Flash 跑出错、断言不符、出现规格外情况 → **停下，提示 boss 切回 Turbo 排查**，不自行发挥、不试错硬绕（Flash 自由发挥是返工之源）。
3. **处理完降档**：Turbo 定位/设计完，明确告诉 boss「方案已定，可切回 Flash 执行」，后续机械步骤交回 Flash。
4. agent 自身在交付物里标注「本步建议档位」，让 boss 知道何时该切模型。

   ## <时间> · v<N> <一句话变更>

### Step 1b 正文价值导向与血肉完善（boss 10-14 拍板，🆕 v1.17.0）

**目的**：正文不是「罗列工具/现象」，是「读者能带走的东西」。每篇成稿建稿前过一遍本步，内容深度不够就回炉，不带「干瘪稿」往下走。

**七问检查清单（姜胡说结构，SSoT 素材=元宝卡片姜胡说视频稿 2026-09-28 入库）**：

1. **这篇能给你什么**（开头价值导向段）：2-3 句直接说清读者看完能得到什么，分 ①②③ 列点（如：知道是架构问题不是你的问题 / 三条解法路线与取舍 / 一个判断框架）
2. **文章要表达什么**（主题一句话）：通读后能用一句话转述核心观点；转述不出=主线模糊，回炉
3. **给读者带来什么价值**（可带走结论）：结尾给 2-3 条「实操判断」（别人看完能拿去用的），再给一个「这周做一件事」式行动钩子（姜胡说风格：具体、可执行、数据会说话）
4. **历史文章超链接**：同主题前篇已发文章内嵌为可点击链接（公众号支持站内链接），让读者顺着看；无前篇则跳过
5. **调研与实测**：文中引用的工具/方法有社区实测数据的，补「他人实测/作者自述」转述（含真实数字），并**明确声明本人是否实测**（未实测=现象引用，禁假装用过）
6. **项目文档截图**：提到开源项目时，截 GitHub 首页/README 渲染图内嵌正文，让读者一眼知道项目是干嘛的（GitHub 页反爬失败时用 raw README 本地渲染）
7. **事实口径**：星标数等硬数据标注来源与日期；涉及工具星标写「周增量」与「总星」两个口径，避免口径打架

**闸门**：七问任一答不出 = 🔴 回炉补内容再进 Step 2；全部通过 = 把「价值导向段已加 + 行动钩子已加 + 超链接 N 处 + 转述来源 N 条」写入操作单作凭证。


产品名/榜单名次/外部硬数据逐条 WebSearch 回源，grep 全载体（正文 MD+封面 HTML+每张配图 HTML 源+已渲 PNG）核错名。调用 `mp-prepublish-draft-verify` Step 1。凭证：错名计数=0 全载体。

### Step 3 标题撞题核查

### Step 7b 封面决策链（boss 10-12 ADV-02 拍板沉淀，v1.14.0 起强制）
