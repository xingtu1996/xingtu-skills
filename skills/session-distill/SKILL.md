# 历史会话蒸馏（Session Distill）

> 把「历史会话档案」变成「内容素材」的挖掘管线。解决：内容创作时不用把整段历史会话再喂给 AI——直接引用蒸馏产物。
> 与 `session-sediment` 分工：彼管**单次会话结束时的即刻沉淀**；此管**历史会话档案的批量挖掘**（已有 jsonl 语料库，按主题/时间任意检索）。

## 输入源（会话档案）

| 源 | 路径（各机器按实际替换） | 说明 |
|---|---|---|
| Claude Code | `~/.claude/projects/-Users-<user>-<项目>/*.jsonl` | 目录名带 `-` 前缀 |
| WorkBuddy | `~/.workbuddy/projects/Users-<user>-<项目>/*.jsonl` | 多为当前主力，千级文件，先按 mtime 排序 |
| 豆包/千问记忆 | `~/.qwenworkcn/awareness/main/` | 记忆层，配合跨工具接续 |

> 若环境带会话检索工具（如 session-search：统一检索多仓会话并出高价值候选清单），先检索定位再蒸馏，省 token。

## 蒸馏五步

### 1. 定位会话子集

按主题关键词 / 时间范围 / 文件 mtime 过滤候选 jsonl（先 `ls -t` 看 mtime 或 `grep -l` 命中文件，**不裸扫全库**——千级文件全扫费 token）。

### 2. 抽取用户消息（过滤注入）

只取 `role == user` 且 `type == input_text` 的文本；**剔除** `<system-reminder`、`<cb_summary`、`<conversation_history_summary`、`<task-notification` 注入段——这些是框架/任务注入，不是用户原话，混入会污染蒸馏结论。

### 3. 主题聚类与词频

对用户原话做词频统计（2-6 字中文连续串）+ 主题关键词计数，识别反复出现的需求/痛点/决策场景。词频结论须能回指具体会话（附会话 ID）。

### 4. 蒸馏产出（对齐内容护城河）

- **选题卡**：拍前三问（对谁有帮助/什么场景能用/当不当资产留下）+ 反常识点 + 数据钩子 → 追加选题池
- **素材卡**：单条高价值素材（方法论/金句/可复用思路），**带出处**（会话 ID + 时间戳）→ 素材库
- **踩坑细节**：优先提取真实一线项目细节（**时间点/排查时长/独有解法**）——这是内容护城河（拒绝 AI 流水线二创套话），可配 1 张真实界面截图（打码）
- **方法论沉淀**：反复出现的流程/规则 → 视价值沉淀为新 skill（先跑 `skill-naming-evidence` 第 0.5 步查用户实际用词）或团队铁律

### 5. 落盘 + 登记

| 产物 | 落点（按各项目实际仓库结构） |
|---|---|
| 选题卡 | 内容仓库 `01_灵感与选题池/` |
| 素材卡 | `素材库/素材卡_<主题>_<日期>.md` + 素材库索引 |
| 会话复盘 | 内容仓库 `04_会话与复盘/` |
| 留痕 | 项目 `CHANGELOG` + 产出索引 |

## 纪律

- **只读挖掘**：不改会话档案、不删文件（结构性删除走项目安全删除工具，禁 `rm` 硬删）
- **诚实讲局限**：抽取不到就写「无」，不编造会话内容
- **事实可溯源**：每条素材附会话 ID 路径可回溯，数字标注来源+验证程度
- **脱敏**：蒸馏产物若上公网/开源，先过隐私扫描（如 `privacy_scan --fail-fast`），真名/手机号/邮箱/雇主信息一律模糊化
- 适用范围：工作区专属技能须带范围守卫（读根 `AGENTS.md` 含空间标识才执行），其他项目不适用
