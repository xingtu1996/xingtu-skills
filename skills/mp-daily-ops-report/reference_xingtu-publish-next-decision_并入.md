# 行途「明天发什么」排期决策 playbook

> **本 playbook 的灵魂**：排期建议必须建立在**本轮独立重跑的门禁凭证**上，而不是 CHANGELOG 里"门禁全绿"的文字记录或模型自述。本轮实测就是靠这条抓到两处 CHANGELOG 未记的缺陷——① v5 正文有 31 个超长段落被判"需修改"，CHANGELOG 却记为"门禁全绿"；② 草稿箱 appmsgid=100000597 注入早于 v5 重构，直接定时发布会把旧立意/旧错名发出去。二者都不是"翻文件翻出来的印象"，是现跑脚本 + 比对时间戳拿到的硬凭证。

## 〇、适用范围守卫（先做，别跳）

读当前工作区根 `AGENTS.md`。**含「行途」二字才继续**；否则本 playbook 属个人 IP 项目专属，在其他仓（如公司项目）零业务文件读取、直接停止并声明不适用。这是无 hook 兜底下的自补洞。

## 一、何时用本 playbook

- 主理人问"今天/明天发什么""推荐发布内容""待发太多选哪个""排期怎么排"。
- 需要把 CHANGELOG/看板/后台数据/舆情融合成一份带凭证、带取舍理由的**决策单**。
- 与相邻 skill 的边界：本 skill 只做**决策与取凭证**；把选定稿导入草稿箱/设封面原创合集走 `wechat-mp-publish`；拉后台只读数据走 `wechat-mp-analytics`；成品外发矩阵归 `qw-distributor` / `workflows` 多平台分发；**选定稿的"发前凭证闭环"（名字错/榜单漏/图静默消失 → 建稿 API 回查 → 回收缺陷稿）已独立成 `mp-prepublish-draft-verify`**，本 skill 第五节的时序核对只判"草稿是否早于正文终稿、需不需要重建"，细节不在此复述。

## 二、底座（先跑，别裸翻文件）

```bash
cd <工作区根>
python3 tools/publish_brief.py --date <目标日 YYYY-MM-DD> --top 5   # 默认明天(Asia/Shanghai)、5 个 gate 候选
cat outputs/发布决策简报_<目标日>.json   # 只读聚合：候选、库存、门禁状态、战绩引用
```

底座**只聚合事实、不出建议**（建议是主会话的判断职责）。若某候选缺实测数据，先补齐再进下一步。底座输出的任何"全绿/FAIL"结论，进入下一步都要被独立复核，不作豁免。

## 三、四源交叉读取（互不信任，冲突如实并列）

按路径直读，不粘正文（省 token，METHOD-006）：

1. `CHANGELOG.md` 顶部（最近变更总表，倒序）——取"挂着什么待拍板 / 哪篇刚重构"。
2. `outputs/发布日历与待发内容看板_<最新日期>.html`——待发池与状态位。
3. `outputs/发布包_<月>/本周发布计划_<起-止>.md` + `outputs/运营台账/1个月发布日历_*.md`——既定排期与封面深浅底交替（**交替只看后台实际发出序列，不采信包内过期备注**）。
4. `outputs/舆情日报_<最新>.html` + 发布日志战绩（`data/stats_*.json`、历史阅读数）——近期什么钩子有阅读、赛道有无新变量（如竞品榜位变化）。

四源口径打架时（状态位互相矛盾是常态）：**并列呈现冲突**，不擅自择一，交给 boss 或下一步凭证裁定。

## 四、对每个候选独立重跑门禁取凭证（核心，不可省）

对进入候选名单的**每一篇**，现跑两道门禁，以脚本退出码/输出为准：

```bash
python3 tools/de_ai_flavor_check.py "outputs/发布包_<月>/<包名>/01_正文/正文_v*.md"   # 加粗/引用/超长段/AI腔词，exit 1=有违规项
python3 tools/privacy_scan.py --fail-fast                                            # 🔴/🟠 残留即 exit 1
```

**判读纪律（关键，别把脚本红字当真理）**：
- **历史"门禁全绿"一律不豁免**：改过稿、换过会话、mtime 晚于 CHANGELOG 那条记录的，必须现跑。完成判定查凭证，不问模型（B-009/B-046）。
- **超长段落数是"关注项"非硬闸门**：本轮实测该指标与真实阅读**零相关**（占比最高的 FDE-02 反而是近期最好成绩；僵尸门禁 `LONG_PARA_MAX` 与流水线 100–230 字段脱节）。所以"红 ≠ 一定不发、绿 ≠ 一定可发"——超长段超标要报出来并给判断，但**不因此单票否决**；加粗>8、AI 腔词、privacy 🔴/🟠 才是真拦截项。
- 若发现门禁结论"太整齐"（多候选同一原因全 FAIL），**先怀疑检测器/口径本身**再怀疑稿件，用已发布稿的真实阅读做相关性回验。

## 五、草稿箱 appmsgid 时序交叉核对（发前必做）

若候选已建过草稿，**核对草稿注入时间 vs 正文终稿 mtime**：

```bash
stat -f "%Sm 正文终稿" "outputs/发布包_<月>/<包名>/01_正文/正文_v*.md"   # 或 ls -l --time-style=full-iso
# 草稿箱侧：用 tools/wx_draft_api.py 建稿时打印的 update_time / appmsgid，或后台草稿列表更新时间
```

- **草稿更新 < 正文终稿** → 判"直接定时会发旧立意/旧错名"，**必须用最新正文重建草稿**（`wechat-mp-publish` 第九节 API 通道：dry-run→建稿→回查→回收中间稿），不能拿旧稿定时。
- 草稿箱同名多份、media_id 前缀相同无法区分时，**靠"更新时间"认稿**并在决策单写死"发 09-15 22:02 那份 / 删掉旧稿"。

## 六、输出决策单（结论先行，选项制）

```
【主推】<篇名> —— 理由：数据钩子(引用战绩) + 门禁本轮凭证 + 时序结论(草稿需重建/可直接定时) + 契合定位/蓝海
【备选】<篇名> —— 何时顶上
【多平台外发·不占公众号额度】<已发内容的矩阵分发时序，走 distributor>
【待 boss 拍板】列清阻塞项与不阻塞项，各附一句判断 + 选项
```

每条建议都指向**字段/凭证**（哪个脚本、哪个时间戳、哪条阅读数），无凭证不下结论。角色委派参考根 `AGENTS.md`「千问办公接入」路由表：`qw-pub-chief`（决策）、`qw-pub-check`（齐套核对）、`qw-data-diag`（数据复盘）。

## 七、收尾留痕（不回写 = 变更未发生）

```bash
python3 tools/changelog_append.py --type "⚖️" --path "outputs/发布决策简报_<目标日>.json + 相关包" \
  --desc "排期决策：主推X，因<数据+门禁+时序>；抓出<缺陷>" --tool qwenwork
```

同步登记 `产出索引.md`；若新建/改动了 skill，跑 `python3 tools/skill_ledger.py` 重生 LEDGER。
