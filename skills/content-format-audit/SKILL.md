# 内容格式策略评估（content-format-audit）

> **v1.1.1（2026-09-16 上午）**：对 v1.1.0 清点与复跑机制做三处实测修补（凭证：对 AGENT-03 现行正文双版脚本对照跑）——① 标签行正则**假阴性**修复（旧式 token 不容空格，`WorkBuddy / … / AI Agent推荐 …` 实测漏检报 0，现报 1）；② 清点脚本支持**多篇入参**，系列级评估逐篇输出并排成「元素×篇目矩阵」，目录条目数与编号行数分开报数防双算；③ `reference.md` §五新增**复跑回填与翻转义务**（P0 效果以数据回流凭证回填、判定翻转必写依据）。首屏公式定版口径不动（仍唯 `DESIGN.md` §五 是从）。
>
> **v1.1.0（2026-09-16）**：① 判定表与路线图补「首屏公式」默认项（口径以 `DESIGN.md` §五 02:29 定版为唯一 SSoT，本技能只引用不复制正文）；② 修正与首屏公式打架的旧默认「blockquote 摘要并进首段」；③ 收口合并近重复技能 `mp-format-trace-audit`（09-16 01:3x 平行会话双副本，B-010 同源实例），其独有增量（清点脚本泛化与病灶附加项、对标账号档案卡、拆拐杖坑）已并入本文件与 `reference.md`。

## 适用前提（范围守卫，必读）

> **守卫规则**：本技能承载「行途」个人 IP 的格式策略判断（51 粉冷启动阶段、黑红灰家族、PUB 系列规则口径）。开工前先读工作区根 `AGENTS.md`，**含「行途」才继续**；否则声明不适用并停止——不套用本流程评估其他项目的文案格式，避免个人定位口径渗入非本空间会话。

- 评估对象是**成稿 MD**（发布包 `01_正文/` 或 `outputs/内容稿件/` 下），不是排版 HTML——排版问题归 `mp-prepublish-draft-verify`。
- 必备工具：`tools/changelog_append.py`（留痕）、grep/python3（元素计数）。
- 必备规则底座：PUB-027（去 AI 味门禁）/ PUB-032（本文导航要求）/ PUB-048（图文密度）/ PUB-049（禁硬预告）；视觉与首屏定版 SSoT `DESIGN.md` §五。细则在 `rules/RULES.d/01_PUB`，**本技能只引用编号，不复制条文**。
- 核心原则一：**只评估不动手**。本技能产出 = 评估报告 + 路线图；任何对正文的修改在 boss 对路线图拍板后另起执行轮。
- 核心原则二：**完成判定查凭证，不问模型自述**——元素计数必须有可复跑的 grep/脚本输出为证；对标样本必须标注验证程度。

## 边界（与相邻技能分工，不重叠）

| 关注层 | 归属 |
|---|---|
| 词级 AI 味（套话/口癖/形容词替代证据） | `de-ai-flavor` / PUB-027 门禁 |
| 图文密度（该不该补图、补哪节） | `pub-infographic-supplement` |
| 标题撞题（同题淹没） | `mp-title-collision-rename` |
| 单篇文风审查 | `writing-guidelines` |
| 发前闸门（嵌图 N/N、错名、建稿回收） | `mp-prepublish-draft-verify` |
| **跨篇策略级：篇级结构元素 × 对标参照系 × 格式策略判定 + 路线图**（存删改判定的唯一承载处） | **本技能** |

**交接点**：本技能判「删/改造」的元素，boss 拍板 P0 后改稿走 `xingtu-content-craft`（或 surgical 小改），改完回 `mp-prepublish-draft-verify` 走发前闭环。**首屏公式本身不逐轮重评**——它是定版默认项（见 Step 4），新轮评估只查「是否被违规」。

## Step 0 定范围与定调（先确认再动手）

1. 确认评估对象：单篇成稿 or 系列级（多篇抽 2~3 篇代表）。
2. 确认 boss 定调：`现阶段只评估` 还是 `评估+指定项直接试`。默认只评估。
3. 把 boss 提出的问题**原话**与对标样本写进报告「触发」引言。
4. 若 boss 在对标中提到未知实体（语音转写常发生：如「BBPOS」「奇迹之心」），**不许猜**——列出「待 boss 补链接/正名」，报告中该样本不纳入判定（BUL-003、B-009）。

## Step 1 格式元素清单（先量化，再判断）

对最新版主稿跑元素计数脚本（python 片段见 `reference.md` §一），产出清单表：

| 元素 | 定位方式 | 本稿计数 |
|---|---|---|
| 首屏结构（定版合规检查） | 文首 blockquote 摘要是否 ≤60 字、是否位于引子图前、目录是否在位（口径 `DESIGN.md` §五） | |
| blockquote 信源摘要 | `^> ` 行（区分文首摘要块与正文引语，引语是人设痕迹另计） | |
| 「我是谁」独立段 | 段首关键词 | |
| 目录块 | `目录：` + 连续编号行（**必须跳过空行**），数节数 | |
| 信息说明块（信源透明） | `**信息说明**` 等固定标记 | |
| 标签行（词罗列） | 文末 `词 / 词 / 词` 行 | |
| 延伸阅读 | 段标题 | |
| 合集状态块（含「待发布」） | 段标题 + 条目状态词 | |
| 关于 X / 求赞句 | 段标题 / 关键词 | |
| 图注来源 | 图片行下方来源注 | |
| 节标题病灶附加项 | `^## ` h2 数——为 0 而编号行多 = 目录与节标题**渲染同形** | |
| 配图数 / 总字数 / 节数 | wc + 目录条目数 | |

**凭证要求**：每个计数附 grep/脚本命令，报告里注明「可复跑」。

## Step 2 双参照系对标

两个参照系**分开记账**，不混判（这是本管线 09-16 首案的核心修正）：

- **机构媒体支**：APPSO、机器之心、量子位——编辑部级「干净」：无我是谁、无目录、无标签行。样本验证程度必须标注：截图实证=高 / 第一方链接=高 / 既有认知=中。
- **强人设个人号支**：半佛仙人、差评、卡兹克——满篇是「我」（口头禅、自嘲、立场押注），但无 Markdown 结构痕迹。

**关键判断**：个人 IP 的更对参照通常是个人号支，不是机构支——抄机构的「干净」会抄丢个人的「可信」（详见 `reference.md` §二对照表 + §六对标账号档案卡）。boss 指定的对标对象照查，但参照系修正意见要**主动给**（操盘手角色预设，RULER.md）。

## Step 3 根因诊断：两变量检查

格式差异先归因到两个变量，再谈改法（顺序不能反）：

1. **身份阶段**：大 V「无我是谁」是品牌溢价的**结果**不是原因。冷启动号读者第一次来必须 3 秒知道「这人凭什么讲这个」——删自我介绍 = 转化归零。报告如实写本号当前粉丝量级 + 来源与验证程度。
2. **篇幅**：机构媒体 2000–3500 字故无目录。**目录是篇幅的症状，不是格式偏好**；8000+ 字的目录是完读率拐杖，要消目录先控篇幅——篇幅没降先删目录 = 拆拐杖。

## Step 4 逐项三档判定

总原则：**人设痕迹要加，结构痕迹要减**。人设痕迹 = 会话引文、项目数字、踩坑记录、立场押注、信源透明（信任资产，对冲反 AI 情绪）；结构痕迹 = Markdown 写作习惯残留的容器形态（灰底引用块、编号目录、标签行、手写合集块）。判据只有一条：**删掉它会不会丢信任资产**——同元素可能两者兼有（如摘要块：信息=信任资产、灰底形态=结构痕迹），走「改造」。

对 Step 1 清单逐元素判三档，每项给「理由 + 具体改法」（模板见 `reference.md` §三，首案历史判定见 §五勘误段）：

| 元素 | 默认判定 | 改法要点 |
|---|---|---|
| **首屏顺序** | **保留·定版默认**（不作逐轮重评项） | 标题→一句话摘要（≤60 字：翻了谁+跑了什么+判断）→引子图→先说结论→我是谁一句→目录。唯一 SSoT `DESIGN.md` §五（09-16 02:29 boss 定版），**本技能不复制正文**；新稿只查「是否被违规」，违反 = 改回定版，不重新论证顺序 |
| blockquote 信源摘要 | **保留（v1.1 修正旧默认）** | 独立一句话摘要 ≤60 字、置于引子图**前**；信源透明细节下移信息说明块。**旧默认「灰底并进首段一句加粗」作废**——那是 02:00 首案中间态，02:29 定版已改回「摘要独立且图前摘要」，照旧判 = 拆首屏公式 |
| 我是谁独立段 | **改造** | 压一句进首段（正例即最好的一句自我介绍），位置保持定版顺序第 5 位 |
| 目录 | **条件保留**（定版：在位） | 长文保留当拐杖（boss 认知：给读者心理预期，扫目录命中才往下读）；8-12 节长文无目录=劝退；要消先控篇幅 |
| 信息说明块 | **保留** | 差异化信任资产，位置可后移、精简为两句 |
| 标签行 | **删** | 搜一搜不认文末标签行，纯 Markdown 残留 |
| 合集状态块（含「待发布」） | **删** | 暴露库存（PUB-049 精神同源）；合集功能自动展示，手写块冗余 |
| 延伸阅读 | **保留精简** | 只留已发布、≤2 条 |
| 关于行途 + 求赞句 | **保留** | 人设收口；求赞已精简为一句 |
| 图注来源 | **学 APPSO** | 外部图必注来源（机构名+期数），自制图印「行途·系列名」 |

## Step 5 路线图与落盘

报告结构（模板见 `reference.md` §四）：触发与对标样本（含验证程度）→ 根因两变量 → 核心判断 → 逐项三档表（含首屏合规行）→ 路线图 → 待 boss 补的输入。

- **P0**：下一篇即可试的最小改动集（不动已定稿/已进草稿箱的稿），注明预期效果（如「减 traces 4 处、不减信息量」）。**首屏公式为默认执行项直接列入 P0**（新稿自动按 `DESIGN.md` §五 执行，不进「待试」清单，违规定版才列修复项）。
- **P1**：可 A/B 的结构性试验，注明数据回流管道是否已建。**固定观察项：首屏公式篇 vs 旧顺序篇（摘要在图后/超 60 字）完读率、分享率对比**——管道已建（`tools/mp_daily_report.py` + `wechat-mp-analytics` 只读回流），逐篇累积样本，不达标再回炉顺序判定。
- **P2**：规范化与对标库建设（对标账号档案卡随实读扩充，见 `reference.md` §六）。
- **不动红线**：信源透明信息、立场押注、会话引文——**只换形态不丢信息**，逐字写进报告。

落盘：`outputs/格式策略评估_<主题>_YYYY-MM-DD.md`（或单篇评估可落发布包内，系列级落 outputs/ 根）。收尾三件套：

```bash
cd ${WORKSPACE} && python3 tools/changelog_append.py --type "📊" \
  --path "outputs/格式策略评估_<主题>_YYYY-MM-DD.md" \
  --desc "因为<触发问题>做了格式策略评估：元素清单→双参照系→三档判定→路线图，核心判断<一句话>；只评估未动稿" \
  --tool qwenwork
```

并在 `产出索引.md` 登记该报告行。报告中「待 boss 补的输入」在对话里逐条列出请 boss 拍板，**不留口头结论**。

## Pitfalls

- **拿旧默认「摘要并进首段」判首屏**：该判定是首案 02:00 中间态，boss 02:29 已定版改回（摘要独立 ≤60 字、在引子图前）。复跑时照 `reference.md` §三历史表原文判 = 拆掉信任资产的独立摘要位。定版与历史冲突时以 `DESIGN.md` §五为准，历史表只作校准不作豁免。
- **把引子图放摘要前（02:00 中间态）**：曾实测「图在前」后被 boss 澄清改回；顺序依据虽含首屏优先级图>大字>小字，但摘要承担信源透明须先于图出现。勿凭直觉重开此判。
- **把机构号的「干净」当普适最优**：不同身份阶段/篇幅的格式不可平移抄作业——先跑 Step 3 两变量再判。
- **在篇幅没降时先删目录**：目录是篇幅的症状，拆拐杖不看字数 = 完读率崩。先控篇幅（P1 A/B），目录自然消失。
- **对标未识别实体凭猜测写进报告**：语音转写常有误名（BBPOS/奇迹之心案），查不到就标「待补」，编一个对标对象进报告 = 污染整份判定（B-009）。
- **只换容器丢了信息**：「改造」档的判据是信息量不降——删之前先问「这行的信息在正文其他地方有吗」，没有就不是删，是搬。
- **评估轮顺手改稿**：boss 说「先评估」就只落报告；改稿是拍板后的另一轮，混做会破坏「已定稿不轻动」的发布链路状态。
- **计数凭目测不跑脚本**：每类元素都要有可复跑命令输出，防「感觉没有目录」（BCI 同源教训）。

## Verification

- 元素清单每行有计数与命令凭证（grep/脚本可复跑），含首屏结构合规检查行（摘要 ≤60 字判定 + 摘要/引子图相对位置 + 目录在位）；
- 首屏公式按 `DESIGN.md` §五 定版判为默认保留项，报告未出现「摘要并进首段」「引子图在摘要前」等作废判定；
- 对标样本每条带验证程度标注（高/中/待补），未识别实体出现在「待 boss 补」而非判定依据里；
- 三档表覆盖 Step 1 清单全部元素，每项有理由与改法；
- 路线图 P0 含首屏公式默认执行项、P1 含「公式篇 vs 旧顺序篇」完读/分享 A/B 观察项（注明回流管道），红线逐字列出；
- 报告已落盘（`ls` 可见）+ CHANGELOG 行已回写（脚本退出码 0）+ 产出索引已登记；
- 正文 MD 与草稿箱**零改动**（git status / 不建稿为证）——除非 boss 明确要求进入执行轮。
