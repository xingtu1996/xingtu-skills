# 零成本画面层 — Iconify 图标 + 离线缓存

## 核心判断（先做这一步，能省掉几小时）

**用户给一个「插画/风格」资源时，先分辨它是哪一类 —— 成本差两个数量级：**

| 类型 | 例子 | 代价 |
|---|---|---|
| **现成素材** | SVG/PNG 图标集、插画库 | ¥0，直接渲染 |
| **提示词库** | 「N 种绘画风格 prompt 包」 | 需**图像模型**才能出图：本地 SD 要下 5–8GB、单图 30–60s；云 API 要钱 |
| **模型权重** | LoRA / checkpoint | 同上传 + 显存/磁盘 |

> 「216 种手绘插画风格」这类**是提示词库，不是素材**。别直接承诺「接进来就有图」。

**默认答案：Iconify 图标。** 20 万+ 图标、许可干净（Tabler MIT / Phosphor MIT / Carbon Apache-2.0）、
可任意上色、单图几 KB、离线缓存后**边际成本恒为 ¥0**。

## 标准链路

```
中文关键词 → 关键词表命中 → Iconify SVG API（?color=品牌色）
                            ↓ 未命中
                        兜底图标（稳定散列选一个，保证每张卡都有画面）
                            ↓
                    SVG → PNG（rsvg-convert 优先，cairosvg 退路）
                            ↓
                    本地 assets/icons/ 缓存（离线优先，命中即用）
```

## 关键实现要点

### 1. 渲染 SVG → PNG

```bash
brew install librsvg        # 提供 rsvg-convert
```

```python
# 优先 rsvg-convert（无 Python 依赖）
subprocess.run(["rsvg-convert", "-w", str(size), "-h", str(size), str(svg), "-o", str(png)])
```

**坑**：`cairosvg` 在 macOS 上会报 `no library called "cairo" was found` ——
因为 `ctypes.util.find_library` 搜不到 brew 的 `.dylib`。
**必须在进程启动时**注入环境变量（不能 import 后再设）：

```python
env = os.environ.copy()
env["DYLD_LIBRARY_PATH"] = "/opt/homebrew/lib"   # 缺这行必失败
subprocess.run([sys.executable, "-c", "import cairosvg,sys; cairosvg.svg2png(...)"], env=env)
```

### 2. 图标 API

```bash
# SVG 端点可用（PNG 端点已下线，别再试 .png → 404）
curl "https://api.iconify.design/tabler/keyboard.svg?color=%23056DE8"
# 搜索（英文关键词效果最好）
curl "https://api.iconify.design/search?query=token&limit=8"
```

### 3. 兜底图标必须用稳定散列

```python
import zlib
FALLBACK_ICONS[zlib.crc32(keyword.encode()) % len(FALLBACK_ICONS)]
```

**坑**：**绝不能用内置 `hash(keyword)`** —— Python 字符串 hash 每进程随机化
（PYTHONHASHSEED），同一个词在不同次运行里会换图标，用户会以为出 bug 了。

兜底池至少 16 个，且选**语义中性**的几何图形（圆点/六边形/火花…），
**不要**从语义表里借词 —— 否则「自省」会错配成「金币」这类硬伤。

### 4. 品牌一致性（比"好看"更重要）

- **线描单色图标 + 品牌色**（`?color=%23品牌色`）通常比彩色图标更稳
- **不要用 emoji**：字号/字体会随系统变、观感廉价、且常与品牌军规冲突
- 主视觉区给图标一个**浅色圆角面板**（如品牌色 8% 透明度的浅底），画面立刻"成形"

## 语义层：受控词表前置（治本，★ 优先级最高）

**先记住这个区分 —— 它决定你做的是治标还是治本：**

| 指标 | 含义 | 常见误判 |
|---|---|---|
| **有图率** | 每张卡都有图标 | 用兜底散列就能做到 100%，但**没意义** |
| **语义命中率** | 图标与文案**意思相符** | 才是用户真正感知的「有画面」 |

### 实测事故（2026-09-15 · 12 张卡 · 实图核对）

首版流水线**有图率 12/12**，日志漂亮、程序无报错；把卡片拼成总览图逐张看才发现：

- **12 张卡只出现 6 个不同图形**（拼图撞 3 次、菱形 2 次）
- 语义相符**不到 1/3** —— 「心态」被散列成六边形，「表达 / 应用 / 改变」三张同为拼图

**根因不是词表不够大，是架构错位**：让 LLM 自由生成关键词、再事后查表翻译成图标。
LLM 出的是**叙事型抽象概念**（心态 / 观察 / 动机 / 案例），而关键词表是按**主题词**建的
（省 token / 缓存 / 管线 / 部署），两者交集极小 → 全部落兜底 → crc32 散列 → 撞车。

### 药方：把受控词表前置进 LLM 的输出约束

```python
# 1) 建受控清单：叙事高频概念 → 图标（60 个足够覆盖）
CONCEPTS = {"定义": "tabler:book-2", "心态": "tabler:mood-smile",
            "观察": "tabler:eye", "动机": "tabler:bolt", ...}

# 2) 清单直接注入 prompt，并要求「必须从中选」
prompt = f"""...每句配两个标签：
  keyword：画面大标题，自由发挥、要有信息量
  concept：图标语义，必须从上表选一个最贴近的，不要自造新词
【concept 可选清单】{'、'.join(CONCEPTS)}
..."""

# 3) 取图顺序：受控 concept → 自由 keyword → 兜底
icon_id = resolve(concept) or resolve(keyword) or fallback_for(concept or keyword)
```

**关键设计：`keyword` 与 `concept` 解耦。** keyword 仍让 LLM 自由写（做标题，读起来自然），
concept 只负责选图。同一次运行内兜底图标要**去重**（维护 `_used_fallback` 集合）。

### 效果

| 指标 | 修前 | 修后 |
|---|---|---|
| 12 卡出现的不同图标数 | 6 | **12** |
| 语义相符 | 不到 1/3 | **12/12** |
| 重复图标 | 拼图×3、菱形×2 | **0** |

**代价**：缓存图标 93 → 118 张（约 +400KB），一次性 ¥0。

### 三条纪律

1. **别指望本地小模型吐英文 icon 名。** 8B 级模型给 `"shield"` / `"layers"` 这类英文标签时
   飘得厉害、还常编造不存在的图标名（→ 静默落兜底）。
   **给中文受控清单让它「选」，比让它「编」稳得多。**
2. **必须实图核对，不能只看文件名 / 日志 / 有图率。**
   ```bash
   ffmpeg -y -v error -pattern_type glob -i 'card_*.png' \
     -vf "scale=270:-1,tile=4x3" -frames:v 1 /tmp/overview.png && open /tmp/overview.png
   ```
3. **同一 concept 重复出现时图标会重复**（两张卡都叫「技巧」→ 同一张图标）。
   这是语义正确的，不是 bug；若视觉上介意，给 concept 配一组近义备选图标轮换。

### 补表（治标，仅作补充手段）

跑一遍真实素材、把未命中的词列出来补表**仍然有用**，但要知道它**永远追不上 LLM 的自由发挥**
—— 真正解法是上面的受控清单。补表时注意收**抽象短语的组成部分**（「隐性」「沉淀」「分层」），
不能只收名词（「键盘」「配置」）。

## 反面清单

- ❌ 一上来就接文生图 API（贵、慢、可能触合规红线）
- ❌ **只验「有图率」就宣布完成** —— 必须拼总览图实图核对语义（§语义层）
- ❌ **让本地小模型自由编英文 icon 名**（它会编造不存在的图标名，静默落兜底）
- ❌ **把「事后补关键词表」当解法** —— 治标，永远追不上 LLM 的自由发挥；正解是受控词表前置
- ❌ 用 `hash()` 做散列
- ❌ 假设字体/图标库一定存在 —— **一律给候选链 + 缺失告警**，
  静默降级会把"功能失效"伪装成"审美问题"（最难排查的一类 bug）
- ❌ 用 emoji 当图标
- ❌ 每次运行都联网取图（应缓存 + 离线优先）
