# 口述定调入宪 SOP

## 何时用

boss 用**口语**给出一条**长期原则**（不是一次性指令）。
典型句式：「记得这个理念」「根本底牌就是 X」「还是需要克制的」「我们不做 Y」。
> 判据：这条话**下次还适用**吗？适用 → 入宪。只针对当前任务的 → 不入宪，直接干。

## 六步

### 1. 先核实触发场景（别照抄口述）

boss 的定调往往挂在**一个具体诱因**上（某个 Skill / 某条消息 / 某次事故）。
**先查这个诱因的真相，再写规则** —— 否则规则里写的是误解。

> 实证：boss 提「216 种手绘插画风格」→ 实为**文生图提示词库**（不含任何图片，
> 要喂图像模型才出图）→ 规则里写的必须是这个事实，不是"有个现成风格包"。
> 而且该文件（`doc/08`）**早就分析过** —— 先搜仓库，别重复劳动。

**判据**：规则里的证据必须能回挂一条真实命令或文件。

### 2. 找宪法的缺口 —— 这条新理念补的是谁的**反向闸**？

**这是最有价值的一步。** 绝大多数「新理念」不是新东西，
而是**给已有一条规则补上刹车**。

- 已有「优先复用成熟开源」→ 缺「**什么时候不该复用**」→ 这才叫「克制」。
- 已有「能跑通就行」→ 缺「什么时候该重做」。

**一条只会踩油门的规则 = 半个规则。**

问自己：这条理念**否定了现有哪条规则的无条件性**？
把答案写进新条目的**第一句**（否则下一个人读不懂它为什么存在）。
> 若确实是全新领域，才独立成条。

### 3. 备份

走工作区自带脚本（**路径别写错，写错会静默漏备**）：

```bash
<xingtu>/tools/safety/backup-before-op.sh '<描述>' <文件1> <文件2> ...
```

同时确认这些文件在 git 里**改动前是干净的** —— **git 本身就是第二层备份**。

### 4. 入宪

- 条目格式：`## 铁律N · <四字名>（<一句话限定>）`
  → 引用 boss **原话**（带日期）→ 判据 → 正反例表 → **判据一句话收尾**。
- **编号追加，不重排** —— 旧文档/看板会引用「铁律六」这类编号，重排即制造断链。
- 默认追加为新条；只有明确是某条的附属才写成「铁律N·补」。

### 5. 联动同步（最容易漏，漏了就"版本漂移"）

| 位置 | 改什么 |
|---|---|
| `README.md` | 设计哲学/特性列表增一条，让闸门出现在**第一屏** |
| `AGENTS.md` | 硬约束列表 —— **⚠️ 别忘改标题里的数字**（"N 条硬约束"） |
| `HANDOFF.md` | 合规红线区 + **订正陈旧的"（N 条）"计数** |
| `doc/README.md` | 相关流程改为"先过闸，再登记" |
| 专属文档 | 该理念针对的模块文档补一节（如画面策略 / 分发 SOP） |
| `CHANGELOG.md` | 新条目放**顶部**，格式 `## [宪法] · 日期 · <标题>` |

### 6. 提交

- 本地 `git commit` 可做。
- **`git push` / 公开发布必须先拍板**（多数项目 `AGENTS.md` 硬约束里有这条）。
- 提交信息写清四件事：**动因（boss 原话）+ 影响面 + 有无代码变更 + 备份路径**。

## 两个高频坑

- **陈旧计数漂移**：标题/正文里的「（5 条）」「N 个铁律」是**硬编码数字**，入宪后必漂。
  改完 grep 一遍计数类表述。→ 与 `hidden-contract-audit` 同源（派生表述不随源更新）。
- **把敏感词当示例写进规则**：写「不要出现 X」本身就把 X 留在文件里。
  反面例必须**打码或换词**。

## 反模式：为一条理念专门做一份 HTML 看板

boss 偏好 HTML 看板，但**若该理念的载体已存在**（如 `doc/08` 是 MD 选型记录），
就在原地补一节 —— 新建看板 = **增加手段数量 = 违反"克制"本身**。

> **用新规则审自己的交付物。规则的第一适用对象是写规则的人。**

## 同源 skill

- `ponytail` —— 个人级「最简 / 最少依赖」的 ladder；宪法里的「克制」闸是它在**引入依赖**这一面的项目化实例。
- `hidden-contract-audit` —— 陈旧计数 / 派生表述漂移属隐形契约缺陷。
