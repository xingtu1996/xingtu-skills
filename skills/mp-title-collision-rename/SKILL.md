# 公众号标题撞题核查与换题执行（mp-title-collision-rename）

## 适用前提（范围守卫，必读）

> **守卫规则**：本技能专为「行途」工作区的发布包结构（PUB-031 六目录）与专属工具设计。开工前先读工作区根 `AGENTS.md`，**含「行途」才继续**；否则声明不适用并停止——不拿这套流程去操作其他项目的公众号链路。

- 必备目录：发布包六目录 `00_标题摘要/ 01_正文/ 02_排版HTML/ 03_封面/ 04_配图/ 05_合集/ 06_发布参考/` + 工作区 `md2wechat/`。
- 必备工具（相对工作区根）：`tools/fig_fit.py`、`tools/wx_draft_api.py`、`tools/privacy_scan.py`、`tools/legal_compliance_scan.py`、`tools/changelog_append.py`、`tools/safety/safe-delete.sh`。
- 必备规则底座：PUB-001 / PUB-014 / PUB-014-补 / PUB-023 / PUB-031 / PUB-045（封面）/ PUB-048（图文密度）。细则在 `rules/RULES.d/01_PUB_发布与运营.md`，**本技能只引用编号，不复制条文**。
- 核心原则：**改前先列全载体清单**；**boss 拍板才动六载体**；**完成判定查凭证，不问模型自述**。

## 与相邻技能的边界（互补，不重叠）

| 事项 | 归属 |
|---|---|
| 撞不撞题的阈值口径（双查方式、≥3 大媒体判定） | **本技能 Step 1**（唯一承载处；`mp-prepublish-draft-verify` Step 3e 已收缩为指针） |
| 换成什么（候选生成、摘要体检、boss 拍板） | **本技能 Step 2** |
| 落地改哪些载体、封面文案与字号、图与排版重渲 | **本技能 Step 3~6** |
| dry-run 嵌图 N/N 预检、建稿、`draft/get` 回查、回收旧稿的**操作细节与 API 片段** | `mp-prepublish-draft-verify` Step 4a~6（本技能交棒，**不复制 API 代码**） |
| 图文密度补图、`@@PH@@` 标记法脚本 | `pub-infographic-supplement` |

**交接点**：本技能 Step 6 结束（六载体改完、封面与排版重渲并亲眼看过），Step 7 显式走 `mp-prepublish-draft-verify` 收口；换题专属凭证（旧标题残留 0）在本技能 Step 7 追加。

## Step 1 撞题核查（双查取并集，先量化再决策）

**为什么必须查**：① 公众号原创审核比对全网相似内容，同题+同对象+同结构增加审核摩擦；② 搜一搜里小号会被大媒体同题淹没；③ 最亏的一条——**自己独有的论点被用滥的框架词埋没**（壳是别人的，货是自己的）。

两次 WebSearch，取并集去重：

```
① 带引号精确查「核心框架词 + 对象名」      例："办公 Agent 三国杀"
② 查标题去掉产品名后的「结构词 + 对象名」  例：WorkBuddy 豆包 千问 三国杀 怎么选
```

同题认定：同对象组合 / 同框架词 / 同「怎么选 · 横评 · 对比 · 盘点」结构。逐条记 **来源 + 日期 + 标题**，并统计其中大媒体（澎湃 / 虎嗅 / 腾讯新闻 / 网易 / 36氪 / 掘金 / CSDN / 知乎专栏等）篇数。

| 结果 | 处置 |
|---|---|
| 同题含大媒体 **≥3 篇** | 🔴 撞题严重 → **标题回炉，不建稿**，进 Step 2 |
| 同题 1–2 篇且均小媒体 | 🟡 知会 boss，不阻断 |
| 0 篇 | ✅ 放行 |

**前置更佳**：选题池取号时对「X 三国杀 / X 怎么选 / X 横评 / X 对比」结构的题先跑本步，别等发前夜才发现。凭证：「撞题核查：同题 N 篇（大媒体 M）+ 名单」写进操作单。

## Step 2 三候选 + boss 拍板

候选先过硬约束（逐条自查，不过就回炉）：

- **钩子进前 13–15 字**（公众号列表页截断位，PUB-001 / PUB-014-补）；
- 专有名词/英文缩写 **≤2 个**，超了正文首段必须人话解释（PUB-014-补）；
- 四选一钩子：**具体数字 / 读者痛点 / 冲突反差 / 反常识判断**（PUB-014-补）；
- 标题讲道、一眼专业，**不堆纯数据钩子**（PUB-014）；
- 没打磨到「特别好」就不往外放（PUB-023）——三候选都不满意时宁可再迭代一轮。

三候选固定形态（各配摘要，一句话讲清取舍）：

1. **独有判断前置版**（默认推荐）：把正文里最独特的判断做成钩子放前面，产品名保留吃长尾；
2. **反常识悬念版**：更挑点击，但立场强度弱一档；
3. **反差/数字钩子版**：最不可能撞题，但可能丢产品名搜索词——丢之前先问自己：「搜一搜活路变窄，boss 接受吗？」

**产品名原则**：同题大词打不过大媒体，「<产品> 怎么选」这类长尾精准词竞争少，是小号在搜一搜的活路。**未经 boss 明确取舍，候选里不丢产品名。**

用 AskUserQuestion 交 boss 拍板（选项里必须含完整标题 + 配套摘要 + 权衡，不能只给标题）。

**摘要同步体检三条**（换题必顺手核，旧摘要常带这三病）：① 与标题重复度高；② 多论点挤一句；③ 把作者判断写得像事实陈述（如「决定八成体验」的「八成」）。

## Step 3 载体清单盘点（先数后改，改完对得上数）

```bash
cd "<发布包目录>"
grep -rln "<旧标题全文>" . 2>/dev/null | grep -v _archive   # 旧标题出现在哪些文件
grep -c  "<旧标题全文>" 01_正文/正文_vN.md                    # 正文有几处（frontmatter/H1/合集块…）
grep -n  "<框架词>" 01_正文/正文_vN.md | head                  # 内文比喻保留判定
grep -oE 'class="title[^"]*">[^<]{0,40}' 03_封面/封面_*.html   # 封面 title/title2/subtitle 实际内容
```

**六载体清单**（一处不改 = 后台与图上还印着旧题）：

1. `01_正文/正文_vN.md`：frontmatter `title` + `# H1` + 合集/引用块里的标题串（**常有多处，先 grep -c**）；
2. `00_标题摘要/标题摘要.md`：frontmatter 标题 + 正文「## 标题」+「## 摘要」；
3. `05_合集/合集规划与选题卡.md`：合集卡引用的标题；
4. `04_配图/00-引子图-*.html`：引子图主标（图上的字也是标题载体）；
5. `03_封面/封面_*.html`：`title` / `title2` / `subtitle` 三层；
6. `02_排版HTML/公众号_发布版.html`：**不手改**，Step 6 由正文重渲得到。

**内文比喻保留**：撞题只发生在**标题与搜索层面**。正文行文里把撞题框架词当比喻用（如「这场"三国杀"才刚刚开打」）可保留，但要记下保留处数，作为 before/after 凭证写进留痕。

## Step 4 六载体同步替换（表驱动 + assert 实测计数）

改前打快照：`bash tools/safety/backup-before-op.sh`。然后一次性表驱动替换，**每条带 assert**：

```python
NT = "<新标题>";  NA = "<新摘要>"
edits = [
  ("01_正文/正文_vN.md",            [(OLD_T, NT, 3)]),          # 数字 = Step 3 实测 count，不是猜的
  ("00_标题摘要/标题摘要.md",        [(OLD_T, NT, 2), (OLD_A, NA, 1)]),
  ("05_合集/合集规划与选题卡.md",    [(OLD_T, NT, 1)]),
  ("04_配图/00-引子图-xxx.html",     [(OLD_T, NT, 1)]),
  ("03_封面/封面_终版.html",         [(OLD_T, NT, 1)]),
]
for f, rs in edits:
    s = open(f, encoding="utf-8").read()
    for old, new, n in rs:
        assert s.count(old) == n, (f, old[:20], s.count(old), n)   # 计数不符即停，不静默漏改
        s = s.replace(old, new)
    open(f, "w", encoding="utf-8").write(s)
```

三个必踩坑：**assert 计数来自 Step 3 实测**（写死 1 而正文实际 3 处，第一跑就炸——这是好事，别绕过断言）；**待替换串先 `sed -n` 看原文**（包内旧文件的字段常与记忆不一致，尤其摘要）；**frontmatter `slug` 属英文内部标识、不进搜一搜，可保留**，但要在留痕里写明「slug 未改」，免得下轮以为漏改。

**摘要 SSoT 从此立一**：Step 7 建稿的 `--desc` **从 `00_标题摘要/标题摘要.md` 读取**，不再凭记忆传参（历史坑：该文件摘要字段存的是更旧版本、从未与 `--desc` 同步）。

## Step 5 封面：改文案 + 字号断行自检 + 重渲看图

标题变长，封面必**眼见确认**，不许看源码猜：

```bash
grep -o 'class="title2".\{0,80\}' 03_封面/封面_终版.html      # 先拿到实际 class 名与文本
```

- **残留高亮 span**：旧标题的强调色常以 `<span class="em">…</span>`（**未必是 `hl`**）留在 `title2`/`subtitle` 里，与新主标拼成怪串。删前先 grep 实际 class 与文本，`assert count==1` 再 replace。
- **字号-字数自检**：900px 版式下主标约 **9 字以内可 46px；10–13 字降到 38px；>13 字再降或改两行结构**。超宽会在句中崩出孤字（实测：12 字 @46px 断出孤零零一个「态」字）。用正则定位 `.title{font-size:Npx` 后 assert 再改。
- **重渲 + 看图**（从工作区根跑，相对发布包全路径）：

```bash
cd "<工作区根>" && python3 tools/fig_fit.py \
  "outputs/发布包_YYYY-MM/<包名>/03_封面/封面_终版.html" --width 900 --bg "#FFFFFF"
```

> `--bg` 只是截图兜底色，**实际底色由封面 HTML 的 `body{background}` 决定**：白底 = 纯白 `#FFFFFF`、黑底 = 纯黑 `#1a1a1a`（`DESIGN.md` §二；纸白 `#F7F5F2`、深灰 `#1F2225` 均已弃用）。黑白交替哪篇用哪底查 `python3 tools/cover_next.py`，不凭记忆、不信包内旧备注。

然后 **Read 渲染出的 PNG**，逐项核：主标单行不断孤字、三家名/关键词无残留 span、logo 齐全、比例 2.35:1（如 1800×766）、深浅底与发布日志最近一篇**反色交替**（PUB-045，查台账不凭记忆）。不合格回本步重来。

## Step 6 排版 HTML 重渲（@@PH 标记法）+ 门禁 + dry-run

正文改完，排版 HTML 由 md2wechat 重渲得到。`@@PH@@` 标记法脚本 SSoT 在 `pub-infographic-supplement` Step 6e，**本技能不复制**，只按序执行并核三计数：

```bash
grep -c "公众号后台此处插入" 02_排版HTML/公众号_发布版.html   # 必须 0
grep -c "@@PH:"             02_排版HTML/公众号_发布版.html   # 必须 0
grep -c "<p>【配图："        02_排版HTML/公众号_发布版.html   # 必须 = 正文占位数
```

门禁：`python3 tools/privacy_scan.py --fail-fast` 全绿；`python3 tools/legal_compliance_scan.py "<发布包>"` 无 🔴（或一键 `bash tools/content_gate.sh "<发布包>"`）。dry-run 预检与「嵌图 N/N」判定按 `mp-prepublish-draft-verify` Step 4a 执行。

## Step 7 建稿 → 回查 → 回收旧标题稿 → 留痕

建稿、`draft/get` 回查、`draft/delete` 回收的操作片段与坑表在 `mp-prepublish-draft-verify` Step 4b~6，本技能**只追加换题专属三项**：

1. **旧标题残留 = 0**：对 `draft/get` 返回的 `title` 与 `content` 双 grep 旧标题串，命中必须为 0；
2. **新标题逐字一致**：草稿 `title` 与 `00_标题摘要/标题摘要.md` 的标题字段**字符串相等**（不是"看着差不多"），`--desc` 同样取自该文件；
3. **操作单表驱动同步**：`06_发布参考/开箱操作单_*.md` 里的旧标题、旧 `media_id`、认稿时间一并替换（改后 grep 旧值残留 = 0）。回收旧稿**只认 `update_time`**——同批草稿 `media_id` 前缀可能相同。

留痕：`python3 tools/changelog_append.py --type "✏️" --path "<发布包路径>" --desc "因为标题撞题（同题 N 篇/大媒体 M）换题为《…》，六载体同步 + 封面重渲 + 重建草稿，回收旧标题稿 <MID>" --tool qwenwork`，并同步 `产出索引.md`；临时验证目录走 `bash tools/safety/safe-delete.sh`（禁 `rm`）。

## Pitfalls

- **不查就发 = 拿账号去和大媒体抢同一个词**：本轮实测一题至少 10 篇同题、含四家大媒体，发前夜靠 boss 直觉才拦住。选题池取号时前置跑 Step 1。
- **只改标题、不改图上文字**：封面 `title/title2/subtitle`、引子图主标、合集卡、排版 HTML 全都印着旧题。Step 3 清单没跑完就动手 = 必漏。
- **assert 计数拍脑袋**：正文里旧标题常有 2–3 处（frontmatter / H1 / 引用块）。先 `grep -c` 再写进 edits，断言失败要放开重跑而不是删断言。
- **凭记忆猜待替换串**：包内文件的摘要/标题字段常比你以为的更旧，先 `sed -n '1,20p'` 看原文。
- **摘要字段长期滞后 `--desc`**：`00_标题摘要/标题摘要.md` 的摘要与建稿实际用的摘要不是一个东西——换题时一并统一，此后 `--desc` 从该文件读。
- **封面主标超宽断孤字**：新标题比旧标题长，原字号必溢出；字号下调 + Read 看图是唯一凭证。
- **残留 span 的 class 名猜错**：实测是 `class="em"` 不是 `hl`，替换串不匹配时**先 grep 实际文本**，别加宽匹配范围乱替换。
- **内文比喻被一起改掉**：撞题在标题与搜索层面，正文行文里的框架词当比喻可留；改干净反而丢了活人感。
- **手改排版 HTML**：排版 HTML 只能由正文重渲得到，手改会在下次重渲时被覆盖。
- **换题后直接 `draft/update`**：换 thumb/标题易报 40007，不折腾——重建新稿 + 回收旧稿（同 `mp-prepublish-draft-verify` 坑表）。
- **完成判定查凭证不问模型**：历史"门禁全绿"记录不作豁免，每轮现跑。

## Verification（本技能自身的成功凭证）

- 撞题凭证：同题 N 篇（大媒体 M）+ 来源/日期/标题名单，已写进操作单；
- 拍板凭证：AskUserQuestion 有 boss 选定记录，选定标题与最终落地**逐字一致**；
- 六载体计数：`grep -r "<旧标题>" . | grep -v _archive` = 0 命中；`grep -c "<新标题>"` 与 Step 3 实测数一致（引子图/封面 HTML 各自命中 1）；
- 内文比喻：框架词保留处数已记录（before/after 各几处）；
- 封面：Read 亲眼看图通过（单行 / 无残留 span / 2.35:1 / 深浅底交替对台账）；
- 排版：`公众号后台此处插入` = 0、`@@PH:` = 0、`<p>【配图：` = 正文占位数；
- 门禁与建稿：`privacy_scan --fail-fast` 全绿、`legal_compliance_scan` 无 🔴、dry-run 嵌图 N/N、`draft/get` 回查旧标题 0 + 新标题逐字一致 + 封面逐字节一致；
- 草稿箱：旧标题稿已 `delete` 且 `batchget` 复查不在列，认稿时间（精确到分）写入操作单；
- 留痕：CHANGELOG 已回写（`--tool qwenwork`）、`产出索引.md` 已登记、临时目录已 `safe-delete.sh` 回收。
