# xingtu-orchestrate（行途动态编排入口）

把「一个 AI 串行慢慢干」升级为「主会话当编排器，子代理池并行干」。
主会话（ZCode）= 编排器：拆任务 → 定依赖 → 派发 → 收口；子代理 = worker。

## 自然语言目标解析（入口，先跑这步）

boss 说人话即可，不需要记模式名。解析三步：

```
1. 意图分类：从目标句提取 {对象（哪篇/哪些稿）, 动作（成稿/打磨/分发/发布/调研/诊断）, 平台或范围}
2. 模式匹配：查下方「任务性质→编排模式映射」表 → 得 DAG 与派发清单
3. 自动执行：逐站派发 + 闸门核对，只有两类事停下来找 boss——闸门不过 / S6 发布动作
```

**解析不了就问一句**（缺对象、缺平台），一次问清，不挤牙膏式追问。

## BDD 场景契约（自然语言驱动，场景即验收标准）

**场景 1：一稿多平台分发**
```gherkin
Given 一篇已定稿正文（路径 P）
When boss 说「把 P 分发到掘金/知乎/小红书」
Then 识别为同构扇出 → 并行派 3 路 xingtu-distributor（各平台独立适配，禁通稿 PUB-004）
And 产物落 outputs/内容稿件/<slug>/ 下各平台版
And 汇总产物落点清单报 boss，全程只落盘不推送
```

**场景 2：成稿到待发布（全链路自动）**
```gherkin
Given 选题卡或素材卡就绪（路径 A）
When boss 说「这篇走完整条流水线」
Then 按 DAG 自动跑 S1 成稿 → S2 打磨 → S3 独立审查，每站闸门核对后放行
And S3 审查 P0 清零后并行跑 S4a 标题 / S4b 分发 / S4c 核对
And S5 门禁主会话亲跑（privacy_scan --fail-fast + PUB-027 + PUB-003 dry-run）
And 全绿后停在「待发布」状态，报 boss 一句「可发」，等拍板进 S6
```

**场景 3：多路调研**
```gherkin
Given 复合调研需求跨 3+ 素材源
When boss 说「组队调研 X」
Then 并行派 ≤3 路 xingtu-scout 后台执行，各回浓缩简报
And 主会话聚合为一份结论，标注来源与验证程度（BUL-003）
```

**场景 4：失败降级**
```gherkin
Given 某路子代理执行失败
When 带失败原因重派 1 次仍失败
Then 降级为主会话串行执行该站，并报 boss 弃或改
```

**场景 5：写冲突回退**
```gherkin
Given 并行任务共享素材卡/台账且出现写冲突
When 编排者检测到冲突
Then 立即改串行（回 06 号 §〇 决策树），已完成部分不回滚
```

## 何时用

- boss 说触发词（编排跑 / 组队干 / 流水线跑 / 并行编排）**或直接说自然语言目标**（走上方「自然语言目标解析」），或任务天然是复合型（一稿多平台、多篇批量、多路调研、成稿→发布全链路）
- **不用**：单一指向性任务（N=1）走 `workflows/01`，不摆流水线；简单问答不编排

## 铁律（先读，违反即停）

1. **并行 ≤3**：人的 review 带宽（06 号 §〇）。3 个以上逐批推进
2. **共享资产只读**：素材池/知识库/台账只读共享，写冲突任务改串行（06 号 §四）
3. **总控不代写**：主会话只拆解/派发/审核收口，不替子代理写内容
4. **消息只传状态，产物走落盘**：「调研卡 X 已完成，去读路径」——不在会话间搬内容
5. **闸门静态**：路径动态编排 ≠ 免检。每站闸门见下表，编排者负责核对后放行
6. **发布是外发动作**：自动执行到 S5 门禁为止（产物进草稿箱/落盘齐备），S6 点发布按 09-05 看板 D1 条件化授权口径——每日 ≤1、单账号、boss 人工在场指令；D1 未拍板前一律停下等 boss

## 任务性质 → 编排模式映射（核心增量）

| 任务性质 | 模式 | 派发（subagent_type） | 串并行 |
|---|---|---|---|
| 多路调研（跨 3+ 素材源） | 同构扇出 | `xingtu-scout` ×N（Flash）后台 | 并行 ≤3，主会话聚合简报 |
| 单篇成稿→发布全链路 | 流水线 DAG | 见下方 DAG | S1-S3 串行，S4 并行 ≤3 |
| 一稿多平台分发 | 同构扇出 | `xingtu-distributor` ×N 平台（Flash） | 并行 ≤3，禁通稿（PUB-004），只落盘不推送 |
| 多篇批量（2+ 篇） | 批量流水线 | 每篇一条流水线 | 篇间并行 ≤3，篇内串行 |
| 机械核对（发布包齐套） | 单发后台 | `xingtu-pub-check`（Flash） | 单路 |
| 发布数据诊断 | 单发深度 | `xingtu-data-diag`（深度档） | 单路 |
| 发布前对抗审查 | 专家矩阵 | `xingtu-reviewer`（深度档·独立上下文） | 单路串行，结论必须回读 |

**模型分档**（对齐 AGENTS.md）：成稿/审查/诊断 = GLM-5.3 深度档；排版/检索/批量/机械 = Flash 日常档。档位已绑定在各 subagent_type 上，编排时按场景选对 type 即可。

## 单篇内容生产默认 DAG

```
S1 成稿    xingtu-drafter（深度档）        ← 选题卡/素材卡，缺素材写【待补】（B-009）
S2 打磨    xingtu-polisher                 ← 只动表达不动事实，产出 v(n+1) 归档旧版
S3 审查    xingtu-reviewer（独立上下文）    ← P0 未清零不得进 S4
S4a 标题   xingtu-titler    ┐
S4b 分发   xingtu-distributor ├─ 并行 ≤3     ← 均 S3 过后才启动
S4c 核对   xingtu-pub-check  ┘
S5 门禁    主会话亲跑（不委派）：privacy_scan --fail-fast 全绿 + 去AI味量化门禁（PUB-027）+ html_publish_pipeline dry-run（PUB-003 时序）
S6 发布    wechat-mp-publish skill         ← boss 拍板后才动
```

## 派发规范

- 每个 prompt 自含：任务 + 读什么（DIRECTORY.md / RULES 相关分册 / 资产绝对路径）+ 产出到哪 + 过哪个闸门（骨架照 06 号 §六模板替换）
- 子代理默认注入 AGENTS.md，prompt **不重复红线**，但要写明**本站产物落点与验收口径**
- 后台执行（`run_in_background`）：调研 / 核对 / 分发适配；成稿与审查建议前台盯，便于及时纠偏
- 一路失败：带失败原因重派 1 次；再失败 → 降级为主会话串行，或报 boss 选弃
- 中途发现写冲突 → 立即改串行（回到 06 号 §〇 决策树）

## 闸门注入点（编排者核对后放行）

| 站点 | 闸门 | 依据 |
|---|---|---|
| S1→S2 | 素材没有的不编造，【待补】留痕 | B-009 |
| S2→S3 | 事实未被改动（只动表达） | 打磨铁律 |
| S3→S4 | 审查 P0 清零，审查结论回读 | BCI 独立上下文 |
| S4→S5 | 发布包六件套齐套（PUB-031/043） | 台账比对 |
| S5 | 隐私全绿 / 去AI味 / 时序 dry-run | SAF-004 / PUB-027 / PUB-003 |
| S6 | boss 显式拍板 | 外发确认 |

## 收口留痕

编排结束（或中断挂起）必须：①各站产物落点清单报 boss ②统一过 Gate（SAF-004 红线 + BUL-003 依据链）③回写 CHANGELOG（`python3 tools/changelog_append.py ... --tool zcode`）④涉及共享资产变更 → 登记索引。**会话随时可能被切走，落盘即接续**。
