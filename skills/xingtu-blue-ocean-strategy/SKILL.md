# 蓝海市场与受众战略分析（xingtu-blue-ocean-strategy）

> 定位：把一套经过实战验证的「市场 × 受众 × 方向」战略分析方法论，沉淀为可复用的六步引擎。**适用对象**：自己的内容账号、要做的 app/产品、既有创业项目、副业方向的可行性判断。
> 来源：由 `specs/20260903-蓝海市场与受众战略分析/` 完整沉淀（当时用于「AI 编程/vibe coder 工程化」方向，现通用化）。

## 触发条件

- 用户提出：蓝海/市场调研、受众分析、变现人群、人群量化、定位/主方向锁定、赛道分析、战略路线图、内容缺口
- 用户为「内容账号 / app / 产品 / 创业」寻求「市场还有没有机会、该打谁、该往哪走」的判断
- 用户上传了既有调研/数据/竞品分析，要求基于此做战略综合

## 六步核心流程（按序执行，每一步的完整方法见对应 reference）

| 步骤 | 名称 | 核心任务 | 参考 |
|------|------|---------|------|
| **S1** | 明确意图 | 提炼用户的核心问题（通常 3-4 个），写清目标对象与决策诉求 | — |
| **S2** | 市场环境分析 | 市场规模(多口径)/增速/渗透率vs信任度/竞争格局/增量vs存量/蓝海判断 | `references/r1_市场环境分析.md` |
| **S3** | 可变现人群量化 | 8 层漏斗从大池子人口到可触达付费人群，三口径结论，变现节奏 | `references/r2_人群量化漏斗.md` |
| **S4** | 受众分层金字塔 | 5 层人群金字塔，锁定核心目标层，画像 + 付费产品适配 | `references/r3_受众分层金字塔.md` |
| **S5** | 需求缺口与选题 | 竞争扫描 + 「不覆盖」识别 + 痛点排序 + 选题缺口清单 | `references/r4_缺口与选题.md` |
| **S6** | 方向锁定与路线图 | 多方向对比矩阵 + 明确推荐 + 90 天三阶段路线图 + 风险应对 | `references/r5_方向锁定与路线图.md` |

### S1 明确意图（起点，必须先做）
- 提炼用户原始问题的 3-4 个核心问题（例如：市场是不是蓝海？人群有多大？缺口是否真实？该锁定哪个方向？）
- 明确：分析对象（内容账号/app/创业项目）、主阵地/平台、目标人群假设、自身资源与限制
- 把用户的核心观点/假设写进开头——它们是贯穿全篇的分析前提

### S2-S6 执行要求
- **每步都按对应 reference 的「输出模板」产出**，逐条对照「常见坑」自查
- **数据纪律贯穿全程**：每步的数据都要按 `references/r6_数据可信度纪律.md` 分级（🔵硬数据/🟡估算/🔴推测），禁止编造来源
- S4 人群分层、S5 缺口选题的结论必须能回溯到 S2 的市场数据，S6 的方向推荐必须能回溯到 S3/S4/S5 的证据——全链路可追溯

## 产出物要求（每次执行必须交付）

1. **Spec 包**：按顺序编号落盘为独立文件，格式参考 `specs/20260903-蓝海市场与受众战略分析/`：
   - `00_README.md`（总纲：用户意图 + 执行摘要 N 条核心结论 + 文件地图 + 待拍板决策清单）
   - `01_市场环境分析.md` / `02_可变现人群量化.md` / `03_受众分层金字塔.md` / `04_内容缺口与选题.md` / `05_主方向锁定与路线图.md`
   - `06_可视化看板.html`（单文件战略看板）
   - `07_数据来源与可信度.md`
   - 落点：`specs/YYYYMMDD-{项目名}与受众战略分析/`（沿用既有命名）
2. **可视化看板**：单文件 HTML，结构复用 `assets/战略看板_结构模板.html`（含 header/KPI/趋势/漏斗/金字塔/对比矩阵/决策清单/风险），替换为本次项目数据，保持行途蓝风格
3. **待拍板决策清单**：在 README 中给出「# / 决策项 / 推荐选项 / 影响」表，供主理人拍板

## 铁律

1. **数据可信度**：所有数字必须有来源，严格区分已查证/估算/推测（BUL-003），禁止编造链接和数据
2. **脱敏**：涉及当前雇主、薪资、入职年限、隐私数据按用户偏好模糊化；真名及真实联系方式永不上公网，对外统一「行途 XingTu」（SAF-006/SAF-004；**行途 及变体已全面禁用，2026-09-13 裁决**）
3. **方向锚定**：spec 是战略「锚点」，交付后所有执行应回溯到核心结论
4. **落盘登记**：执行完成后按工作区规范回写 `CHANGELOG.md` + 登记 `产出索引.md` + `DIRECTORY.md`
5. **不拍脑袋**：推荐方向必须给「为什么不选其他」的对比证据，不做无依据单选
