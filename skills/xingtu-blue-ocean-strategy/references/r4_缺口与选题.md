# R4 · 需求缺口识别与选题挖掘

> 目标：回答「这个领域的内容/服务是不是真的稀缺？缺口具体在哪？目标人群的真实痛点是什么？」——产出**竞争扫描 + 痛点排序 + 选题缺口清单**。

## 一、竞争格局扫描

对领域内主要赛道打表：

| 赛道 | 拥挤度 | 内容深度 | 代表玩家 | 你的差异化空间 |
|------|--------|----------|---------|--------------|
| {赛道1：操作/教程层} | 🔴极高/🟠高/🟡中/🟢低 | 浅/中/深 | ... | 大/中/小：从「怎么用」到「怎么用好」 |
| {赛道2：专业实战层} | ... | ... | ... | ... |
| {赛道3：教育/入门层} | ... | ... | ... | ... |
| {赛道4：管理/架构层} | ... | ... | ... | ... |
| {赛道5：科普/资讯层} | ... | ... | ... | ... |

**核心发现句式**：「所有赛道都在『前端』（拉新/入门/操作）拥挤，在『后端』（质量/维护/工程化/长期价值）稀缺。机会在后端。」

## 二、「不覆盖」识别法（核心方法）

扫描现有内容后，系统性列出**没人覆盖的维度**。通用模板（以知识/教育类为例）：

1. **不教验收**——所有教程终点是「跑起来了」，不教怎么判断对不对、怎么测试、怎么审查
2. **不教维护**——假设「做完就完了」，不教版本管理、重构、技术债、长期迭代
3. **不教安全**——几乎不面向外行讲安全红线（注入/密钥/权限/备份）
4. **不教部署/上线**——很多人能做 demo，但不会部署上线、配置、监控
5. **不教项目管理**——传统管理讲团队，新范式是「1 人+N 个 Agent」，无人覆盖
6. **不用外行语言讲专业**——专家内容充满术语，目标人群听不懂、不知如何落地

> 套用任何领域时，把这 6 条映射到该领域的「验收/维护/安全/上线/管理/翻译」六件事上，逐条验证是否有内容覆盖。

## 三、痛点排序法（按真实痛感排序）

从社区/评论区/访谈/搜索趋势中收集真实痛点，按「痛感强度」排序（不是按热度排序）。每个痛点给出：

- **表现**：具体场景化描述（用户会做什么、遭遇什么）
- **来源**：原始出处（社区讨论/论文/报告/真实案例），必须可追溯
- **非专业人士的特殊困境**：为什么这个痛点对目标人群更致命
- **量化证据**（如有）：发生率、倍数、比例等硬数据

## 四、需求侧证据（证明缺口是真实需求而非臆想）

| 证据类型 | 指标 | 数据 | 来源 |
|---------|------|------|------|
| 搜索趋势 | 关键词月搜索量变化 | ... | Google Trends/平台指数 |
| 社区规模 | 相关社区成员数/讨论量 | ... | Reddit/论坛/社区 |
| 职场需求 | 相关技能职位增长 | ... | 招聘平台 |
| 内容创作者涌入 | 该领域创作者增速 | ... | 平台报告 |

## 五、选题缺口清单模板

每个选题给出：缺口（为什么没人做）+ 内容方向（具体教什么）+ 目标人群 + 变现潜力。**选题必须来自真实痛点，且市场上无系统性覆盖**：

```markdown
### 选题 N：《{标题}》
- **缺口**：{一句话说清为什么没人做}
- **内容方向**：{教什么/给什么清单}
- **目标人群**：{Lx 为主，Ly 为辅}
- **变现潜力**：{可做成什么产品，价位}
```

## 六、缺口战略总结（四问）

1. **缺口是「没有内容」还是「没有对的内容」？**——通常是后者，90%+ 现有内容在操作层
2. **缺口是单点还是系统性？**——系统性缺口 = 你可以成为这个体系的「定义者」
3. **缺口是否有时效窗口？**——写明窗口期和紧迫原因
4. **缺口是否利他？**——真正解决生存问题而非只为流量 = 高忠诚度 + 口碑传播

## 输出模板

```markdown
## 一、竞争格局扫描（赛道拥挤度表）
## 二、「不覆盖」清单（6 条逐项验证）
## 三、需求侧证据表（搜索/社区/职场/创作者）
## 四、十大真实痛点（按痛感排序，每条含表现/来源/量化证据）
## 五、选题缺口清单（每个选题含缺口/方向/人群/变现）
## 六、战略总结（四问结论）
```

## 常见坑
1. 凭感觉说「稀缺」，没有需求侧证据（必须有搜索/社区/职场数据支撑）
2. 痛点按热度排序而非痛感排序（要做「最痛」的，不是「最多人聊」的）
3. 选题不标注变现潜力（每个选题要能落成产品）
