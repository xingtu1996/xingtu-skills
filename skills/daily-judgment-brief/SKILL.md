# 发布综合判断基线 + 每日对账（daily-judgment-brief）

## 适用前提（范围守卫，必读）

> 读工作区根 `AGENTS.md`，**含「行途」才继续**；否则声明不适用并停止。

## 定位（为什么有这个技能）

boss 的判断力（哪些结论能信、哪类稿能涨粉、什么口径看数据）此前散在 WorkBuddy 记忆文件里——**换会话、换工具就丢**。本技能把判断显性化：

- **土壤** = `reference.md`（判断基线正文，跨工具可见；每次判断**先读它，不凭记忆**）。
- **落点** = `outputs/每日判断对账_YYYY-MM-DD.md`（结论前置、选项制、必挂数据源）。
- 判断基线条目**带来源与日期**；被新数据推翻时**改 reference.md 并注明推翻证据**，不静默漂移。

## 与相邻技能的边界（互补，不重叠）

| 事项 | 归属 |
|---|---|
| 发什么/怎么发/封面底色/晨间决策四块 | `mp-daily-ops-report`（09:30 管线） |
| 发后评估：48h 分诊、7 天终判、假设台账结算、口径守卫 | **本技能** |
| 数据拉取细节（API/白名单/bsk） | `wechat-mp-analytics`（本技能只读现成 `data/stats_*.json`） |
| 素材卡筛选与入库 | L1/L2/L3 管线（`07_AI_使用约定` 第 19 条） |

## 五步流程

### Step 1 读土壤
读本技能 `reference.md` 全文。**禁止跳过凭记忆判断**——记忆会话间不一致，基线文件才是 SSoT。

### Step 2 拉事实（只认凭证）
- `data/stats_YYYY-MM-DD.json`（**一级事实源**；`pulled_at` 必须报告，早于 20:00 的快照标"未结算"）
- `data/publish_board.json`（裂变/contents）
- `outputs/发布排期表_SSoT_*.md`（排期唯一真源）
- **台账/计划行禁当凭证**（历史多次失真）。

### Step 3 对账（按 reference.md §0 口径）
1. **排期倒挂检查**：排期表写的 vs 实际发的（`articles` 最新 publish_time），A级被C级挤掉是常态；
2. **48h 分诊 + 7 天终判**（§2 双峰律），不按时间一刀切；
3. **信号判据**：Δ粉 ≥+3 才是信号；溢出系数必同栏标分享数；
4. 无异常也要写明「无异常信号」，不许硬凑结论。

### Step 4 假设台账结算
`reference.md` §5 的 H-* 假设，到期的逐条 ✅成立 / ❌推翻（附数据）/ ⏸无法结算（写明缺什么、顺延到何时）。结算后**同轮更新 reference.md**。

### Step 5 落点
写 `outputs/每日判断对账_YYYY-MM-DD.md`：
- 结构：**一句话总结 → 三行 recap（事实/对账/结论）→ 判断明细（挂数据源）→ 假设台账变更 → 待拍板（≤2 个选项题，必带专家意见：推荐+理由+风险）**。
- 完成判定查凭证：文件落盘 + `tools/changelog_append.py` 回写 CHANGELOG（`--tool` 标注本工具身份）。

## 红线

1. **全程只读**：不改稿、不发布、不建草稿、不回填台账。
2. **结论必挂数据源**（文件路径+字段），无源结论 = 没说。
3. **判断基线冲突时**：以 reference.md 为准并提示 boss 更新；reference 与新数据冲突时，数据赢，但须结算留痕。
