## 七、v1.3.0 坑位实证（2026-10-13）

| 坑 | 现象 | 解法 |
|---|---|---|
| 插画太小 | 把 scene 图塞进右侧 420px 侧栏 div，人物缩成小图标，boss 说「比例不太好」 | scene 全幅铺满（inset:0），文字压左侧留白区，插画占右半屏 ~50% |
| Chrome headless 超时 | fig_fit.py 跑 `--dump-dom` 60s 超时，因为 Chrome 已在运行 | 直接调 Chrome 加 `--user-data-dir=$(mktemp -d)`，绕过 fig_fit 的 measure 步 |
| 孤字换行 | 标题一行太长最后一个字掉第二行（「偏」单独蹦下去） | 用 `<span class="row">` 强制手动换行，每行 ≤10 字 |
| prompt 布局控制 | 说「右侧放插画」AI 放不准位置 | 说「**左侧留大面积空白**」更可控，AI 自然把主体放右侧 |

## 七·补 v1.3.1 坑位实证（2026-10-14 · THU 封面踩坑全链）

| 环节 | 错误 | 根因 | 防呆（已入 SKILL.md 铁律 0/7/8 + Step 0） |
|---|---|---|---|
| 开工前 | 未 Read 现有 `封面.png` 确认形态 | 凭目录文件名（`封面_文字覆字版_*.html`）默认它是源 | Step 0 闸门：ls + Read 成品图 + 查状态位 |
| 选源 | 选文字版 HTML 重渲，包内已有场景图版正确成品 | 无渲染源优先级规则 | 铁律 7：场景图版源优先；`_旧版_*` 禁作源 |
| 终稿认定 | 10-10 文字版"曾是终稿"的旧印象未刷新 | 上下文陈旧记忆污染 | 铁律 8：终稿认定查 CHANGELOG/打磨日志/状态位 |
| 色值判断 | 一度把 `#F2644F` 当"有问题"，实为三原色标准橙红（`#d71a1b` 已 09-20 弃用） | 视觉 SSoT 读错版本 | 三原色 = 黑 `#1a1a1a` / 白 `#FFF` / 橙红 `#F2644F`，以 DESIGN.md 为准 |

**教训一句话**：封面任务的默认动作是「确认 + 复用」，不是「重渲」；动手前 30 秒的 Read 能省掉一小时的返工。

## 八、boss 偏好记录（封面相关）

- 插画要**够大够醒目**，不要小图标感
- 白底封面加淡网格背景（`bg-grid`）增加质感
- 左下角 tag 用橙红 14px，右下角 footer 用橙红 12px「行途技术」
- 主标橙红强调词 1-2 处即可，不要满屏橙
- 红条分隔线（48×5px）在主标和副标之间
