# 法律合规基线维护 + 出书适配性延伸（legal-compliance-baseline）

> **本 skill 的灵魂**：**误报多的门禁 = 没有门禁**（狼来了效应→僵尸门禁，B-044 同源）。法律合规基线不是"堆规则"，是"精度迭代 + 人工核清单管理"的持续维护工程；同一套基线服务公众号现在、未来出书、个人产品——boss 2026-09-16 凌晨定调「提升影响力的同时要提早打合规基线，从头考虑」。

## 适用范围守卫（首节必读）

读当前工作区根 `AGENTS.md`。**含「行途」二字才继续**；否则本 skill 属行途自媒体项目专属（依赖 `tools/legal_compliance_scan.py`、`tools/content_gate.sh`、`github/xingtu-book/` 等专属资产），在其他仓（如公司项目）零业务文件读取、直接停止并声明不适用。这是无 hook 兜底下的自补洞（同 ZCode 侧 `.zcode/agents/` 守卫规则）。

## 何时用本 skill / 何时不用

**用**：
- 发布前对待发正文跑合规基线（单篇 or 全量发布包）
- 极限词误报太多、精度需要迭代
- content_gate.sh 第⑦门禁要接入/维护/调试
- AI 标识义务、《人工智能生成合成内容标识办法》相关判断
- 🟡 人工核清单要处置、新增、跟踪
- 判断这篇文章"适不适合出书 / 能否作为书稿素材"
- 合规基线要不要加维度（例如新加"数据准确性"扫描）

**不用**（走别处）：
- 建稿前 dry-run / 图文核验 / 草稿箱 API 回查 → `mp-prepublish-draft-verify`
- 文风审查 / 去 AI 味 → `writing-guidelines` / `de-ai-flavor`
- 排期取舍 / 明天发什么 → `mp-daily-ops-report`（原 `xingtu-publish-next-decision` 09-19 并入此）
- 脱敏（真名/手机号/邮箱） → `tools/privacy_scan.py`（铁律 10，独立门禁，不在本 skill 内）
- 群推话术 / 置顶评论 → `mp-group-push-copy`

**边界原则**：本 skill **不出具法律意见**、**不自动改稿**、**不复制扫描规则代码**（SSoT 在 `tools/legal_compliance_scan.py`）。

## 一、法律合规基线扫描（模块 A）

### 1.1 命令

```bash
# 单篇发布前必跑（发布包目录或正文.md 路径均可）
python3 tools/legal_compliance_scan.py <发布包目录 或 正文.md>

# JSON 输出（供脚本消费）
python3 tools/legal_compliance_scan.py <path> --json

# 全量门禁（第⑦道自动调用；有 🔴 阻断发布）
bash tools/content_gate.sh <发布包目录>

# 全库基线（无参数时脚本会拒绝，需显式传发布包父目录）
python3 tools/legal_compliance_scan.py outputs/发布包_2026-09
```

**退出码**：`0`=无 🔴（可发） ｜ `1`=有 🔴（阻断） ｜ `2`=参数/文件错误。

### 1.2 判级语义（🔴🟠🟡✅）

| 级别 | 语义 | 处置 | 举例 |
|:--:|---|---|---|
| 🔴 | **阻断**（硬伤） | 必须改，不改不能发 | 身份证号、银行卡号、手机号、真实邮箱 |
| 🟠 | **需改**（高风险表述） | 强烈建议改，法律风险实锤 | 极限词用于**自家商品**宣传、冒充官方、品牌贬损、证券/医疗/法律结果承诺 |
| 🟡 | **人工核**（不阻断） | 汇总一条，作者逐条判断 | 长引用 >140 字、极限词引用第三方数据、官方 App 图标商用引用、AI 标识义务提示 |
| ✅ | 过 | 无需动作 | — |

**关键区分**：广告法极限词在**自家商品宣传**语境是 🟠（`SELF_GOODS` 命中），在**引用第三方数据**语境是 🟡（`EXTREME_CTX_OK` 命中），在**对第三方最高级正面评价**语境汇总一条不阻断（`PRAISE` 命中，属评论自由）。

### 1.3 精度迭代三条铁律（关键经验，别处没有）

**铁律 1｜广告法只管对自己商品的宣传**
序数词（"第一，"/"第一性原理"/"第一名"）、否定句（"没有绝对的谁好谁坏"）、术语（"第一性原理"）、对第三方产品的最高级正面评价（"最顺手"/"最猛"）**都不该报**——广告法第 9 条规制的是广告中的自我宣传，不是这些正常表达。初版 82🟠 误报几乎杀死门禁。

**铁律 2｜误报多的门禁 = 没有门禁**
狼来了三次，boss 就不看了；这就是僵尸门禁的死法（B-044 同源教训：索引表落后详情小节，因为没人再核）。目标：**🔴🟠 精准、🟡 ≤ 10 条**。当前 AGENT-03 基线 🔴0 🟠0 🟡24，🟡 偏保守但不误阻断——**停止调精度**，惯用语白名单留给门禁用真实跑批数据自迭代。

**铁律 3｜不过度工程**
白名单不是越多越好，每加一条都要问：**这个坑，下一篇还会再踩一次吗？**（基建优先原则的时间盒边界，≤ 半天）会 → 加；不会 → 别加，让它作为 🟡 人工核存在。

**修规则的正确姿势**（避免 bug）：
- 命中词窗口判断用 `text[max(0,m.start()-4): m.start()+len(w)+6]`，别用复杂偏移计算（会算错）
- grep 交替里**严禁空项**：`grep -E "🔴||基线扫描"` 空项匹配所有行，是 bug（09-16 已修一次）
- 序数词白名单要看命中词**前后**字符，不是全句

### 1.4 六维扫描概览

**详细规则清单 + 精度迭代案例见 `reference.md`**（SSoT 在 `tools/legal_compliance_scan.py`，本 SKILL.md 不复制代码）。六维是：

1. **广告法极限词**（《广告法》第 9 条）：`EXTREME` × 语境判断（`SELF_GOODS`/`EXTREME_CTX_OK`/`PRAISE`/`ORDINAL`/`NEG`）
2. **商标冒充与贬损**：`IMPERSONATE`（冒充官方）+ `DEFAME`（贬损词）
3. **著作权长引用**：>140 字引号/引用块，需授权或改写
4. **个人信息扩展**：身份证 / 银行卡 / 手机号 / 邮箱（🔴 阻断）
5. **专业建议**（证券 / 医疗 / 法律）：结果承诺、收益保证、包治根治
6. **AI 标识义务提示**：《人工智能生成合成内容标识办法》2025-09-01 施行

### 1.5 🟡 人工核清单管理

**当前长期挂账三条**（脚本 `pending_human` 输出）：
1. **读《人工智能生成合成内容标识办法》条文原文**，确认「人主导 + AI 辅助」的标识边界（当前验证程度=中，两次 WebFetch 政府/新浪详解超时，基于公开报道解读）
2. **极限词 🟡 项逐条确认**是否为引用第三方数据的事实陈述
3. **官方 App 图标商用引用边界**人工核（评论性引用 vs 商用授权）

**处置流程**：
- 每篇发布前，🟡 汇总一条打印，boss 或作者过一眼 → 若无新风险 → 直接发
- 若发现**新型风险**（例如首次出现证券类表述）→ 加进 `PRO_ADVICE` 或对应维度 → 回写 CHANGELOG
- 长期挂账三条**每季度回看一次**（下次回看：2026-12），条文原文核到就销账

## 二、AI 标识义务待办（模块 B）

### 2.1 当前策略（回应 boss「读者知道 AI 参与会不会反感」）

**读者反感的不是"用了 AI"，是"AI 味"**——套话、无观点、无一手经验。本号护城河恰是 AI 编不出的：本地会话引文、项目真实数字、踩坑记录、敢押注的立场。这些在，文章就是人的。

**两步走**（不逐篇声明，那等于每篇都提醒读者"这不是人写的"）：
1. **让人的痕迹不可伪造地显性化**：会话引文、账本数字、真实截图、立场押注继续保留并加强
2. **一次性透明工作流**：在「关于行途」或某篇方法论文章里讲清——人出观点/素材/判断，AI 做梳理/排版/核验。账号定位本就是"AI 工程化实践者"，用 AI 工程化方法做内容正是实践本身，披露反而把人设坐实

### 2.2 法律层面（验证程度=中，条文原文待人工核）

- 《人工智能生成合成内容标识办法》2025-09-01 施行，AI 生成内容强制"亮明身份"
- **义务主体主要是 AI 服务提供者和传播平台**（加隐式/显式标识、核验标识）
- 「人主导观点/素材/判断、AI 辅助梳理排版」**通常不被认定为强制显式标识对象**
- 用户侧义务：**禁止删除/篡改平台标识**；若内容系**纯 AI 生成**应在发布时声明

### 2.3 触发显式标识的红线

若某段落属**纯 AI 生成**（不是"AI 辅助梳理"），发布时须按办法加显式标识。判断标准（待条文原文核）：
- 观点/立场/结论 = 人给的 → 属"AI 辅助"
- 观点/立场/结论 = AI 生成、人只做删改 → 属"AI 生成"，需标识

## 三、出书适配性延伸检查（模块 C）

> **详细 checklist 见 `book-readiness-checklist.md`**。本节只给触发时机与分级动作。

### 3.1 触发时机

- **每篇成稿发布前**（合规扫描之后追加 5 分钟快检）
- **一稿三形态投影**时（对照 `github/xingtu-book/books/vibe-coder-engineering-guide/` 10 章骨架）
- **季度盘点**（回看本季度所有已发文，挑出书潜力高的补论据/沉淀素材卡）

### 3.2 book-readiness 四问快检

1. **立场押注 / 一手经验含量**：这篇有没有 AI 编不出的东西？（本地会话引文、真实项目数字、踩坑、敢押的立场）
2. **论据可否脱离时效性独立成立**：3 年后读者看这篇还能不能懂？（书有更长货架期，公众号可以蹭热点，书不行）
3. **章节映射**：对应 `vibe-coder-engineering-guide` 哪一章？（Ch01~Ch10，或"不适合任何一章"）
4. **可提取素材**：数据 / 案例 / 踩坑 / 金句，能不能拆成素材卡？

### 3.3 分级与建议动作

| 分级 | 判定 | 建议动作 |
|:--:|---|---|
| **A｜可直接改写** | 四问全过，立场强 + 论据独立 + 章节明确 + 素材丰富 | 落到发布包 `07_作者素材/`，标记"书稿候选"；下次投影时优先纳入 |
| **B｜需补论据** | 立场强但论据依赖时效性热点（例如某产品最新版本） | 发布公众号版；书稿版需补 3-5 个跨时段案例，标"待补论据" |
| **C｜仅时效性** | 蹭热点、立场弱、论据浅 | 只发公众号，不入书；素材卡不必沉淀 |
| **D｜不适合** | 涉个人信息 / 雇主敏感 / 未脱敏 / 立场争议大 | 不发或改到能发；书稿永不考虑 |

### 3.4 合规红线更严（书侧）

**书的法律责任 > 公众号**（更长时效、更强举证、纸媒不可撤稿）。因此：
- 书稿版必须处置**全部 🟡**（不能只"人工核过"，要落到 ✅）
- 长引用 >140 字必须获得**书面授权**或改写至 <50 字
- 官方 App 图标 / 商标使用必须走**授权链**或改用文字描述
- 涉第三方产品的最高级评价（`PRAISE`）书稿版建议加"截至 YYYY-MM 的观察"时间锚

## 四、content_gate 第⑦门禁接入位置

**改脚本时看这段**（`tools/content_gate.sh` 102~125 行）：

- 位置：门禁⑥（规则体系一致性 rule_lint）之后、汇总段之前
- 逻辑：有参数 → 传参调用 `legal_compliance_scan.py`；无参数 → 提示"发布前对待发正文必跑"并跳过（⚪ 占位，不算失败）
- 阻断：`legal_compliance_scan.py` 退出码 1（有 🔴）→ content_gate 计入 FAIL
- 输出：`grep -E "🔴|基线扫描|待人工核"` 摘要前 12 行（**空交替 bug 已修，别再加空项**）

**新增维度时的接入 checklist**：
1. 先在 `legal_compliance_scan.py` 里加规则 → 单跑验证精度
2. 精度达标（🔴🟠 精准、🟡 汇总 ≤ 10 条）→ 才考虑入 content_gate
3. 若维度需**独立门禁**（如脱敏）→ 单开脚本，不塞进本 skill

## 五、常见坑（血泪教训）

| 坑 | 症状 | 教训 |
|---|---|---|
| **僵尸门禁** | 误报太多 boss 不看了 | 铁律 2；宁可漏报不可狼来了 |
| **grep 空交替** | `grep -E "A\|\|B"` 匹配所有行 | 空项等于"匹配任意"，写入前跑一遍验证 |
| **偏移计算错** | 窗口判断绕来绕去还是错 | 简化成 `text[max(0,m.start()-4): m.start()+len(w)+6]` |
| **规则代码复制到 SKILL.md** | SSoT 分裂、脚本改了 skill 没改 | SKILL.md 只写"六维概览"，规则代码永远在 `tools/legal_compliance_scan.py` |
| **法律意见** | 用户问"这样违法吗" | 本 skill **不出具法律意见**；只出"命中 + 上下文 + 判级"，条文原文列入 🟡 人工核 |
| **过度工程** | 白名单加到 200 条还在加 | 铁律 3；每条加前问"下一篇还会踩吗" |
| **书稿版走公众号基线** | 长引用 🟡 直接过 | 书侧红线更严，🟡 必须处置到 ✅ |

## 六、验证（本 skill 自查）

跑完本 skill 后，回答以下问题；任一"否"→ 回炉：

1. 是否对目标正文**现跑**了 `legal_compliance_scan.py`（不是采信 CHANGELOG 里的"门禁全绿"文字记录）？
2. 🔴 是否为 0？（否则阻断发布）
3. 🟠 是否已改或已给出"不改的理由"？
4. 🟡 是否汇总一条打印，boss/作者过一眼？
5. 若涉及书稿版：🟡 是否全部处置到 ✅？
6. 长期挂账三条 🟡（条文原文 / 极限词第三方数据 / 官方图标商用）是否**至少每季度回看一次**？
7. 出书适配四问是否给出 A/B/C/D 分级 + 建议动作？
