# book-readiness-checklist.md — 每篇文章的出书适配性延伸检查

> 本文件是 `SKILL.md` 模块 C 的详细 checklist。**轻量、人工判断、5 分钟级**——不落脚本，避免过度工程（boss 09-16 拍板）。

## 为什么要做这个检查

**boss 09-16 凌晨定调原话**：
> "公众号是发给公众的，大家都能看得到的，可能未来就是我做个人产品啊，什么之类的，也写书啊，这些都是需要从头来进行考虑的。"

**含义**：每篇公众号文章不只是"发出去就完"，还要**为未来出书/个人产品沉淀资产**。同一套基线（合规 + 出书适配）服务三个场景：公众号现在、未来出书、个人产品。

**已有书稿骨架**：`github/xingtu-book/books/vibe-coder-engineering-guide/`（10 章，Ch01~Ch10）。09-15 CHANGELOG 有「一稿三形态投影」先例——把小册既有 10 章骨架映射到已发 8 篇/待发成稿/12 张素材卡，标可改写 vs 需新写与分钟级成本。

## 触发时机

1. **每篇成稿发布前**（合规扫描之后追加 5 分钟快检）
2. **一稿三形态投影**时（对照 10 章骨架做批量映射）
3. **季度盘点**（回看本季度所有已发文，挑出书潜力高的补论据/沉淀素材卡）

## 四问快检

### 问题 1｜立场押注 / 一手经验含量

**问**：这篇有没有 AI 编不出的东西？

**判定标志**（有 = 高分）：
- 本地会话引文（真实工作流的对话截图/文本引用）
- 项目真实数字（token 消耗/耗时/成本/转化率）
- 踩坑记录（"我试了 X，结果 Y，改成 Z 才对"）
- 敢押注的立场（"我押 X 会赢，因为 Y"，非骑墙）
- 一手访谈/交流观察（"我跟做 X 的朋友聊，他说……"）

**判定标志**（无 = 低分）：
- 全是公开报道二次转述
- 观点骑墙（"仁者见仁智者见智"）
- 无具体数字/时间/人名/项目名
- 结论套话（"未来已来""拥抱变化"）

**评分**：0~5 分（5 = 一手经验密集，0 = 全是套话）

### 问题 2｜论据可否脱离时效性独立成立

**问**：3 年后读者看这篇还能不能懂？

**判定标志**（可独立 = 高分）：
- 论据是**方法论 / 原则 / 底层机制**（不依赖特定产品版本）
- 案例可**泛化**（"某办公 Agent 产品"而非"XX 产品 v2.3.1"）
- 数据有**时间锚**（"截至 2026-09 的观察"）
- 结论是**判断**（"我认为 X 会赢"）而非**预测**（"X 会在 Q4 发布 Y"）

**判定标志**（依赖时效 = 低分）:
- 蹭热点（"最近某公司发布了 XX"）
- 强依赖特定产品版本（"XX v2.3.1 的新功能"）
- 数据无时间锚（"目前市占率第一"—— 什么时候的第一？）
- 结论是短期预测（"下季度会……"）

**评分细则**（🆕 09-16 首跑 AGENT-03 补，解决 4/5 vs 3/5 边界模糊）：
- **5 分**：框架 + 论据 + 结论全部可脱离时效泛化（几乎无产品名 / 具体版本依赖）
- **4 分**：**核心框架 / 方法论可泛化 + 数据 / 产品名可加时间锚或泛化**（AGENT-03 属此类：两层框架独立，但三家产品名 + 榜单需"截至 2026-09 观察"锚）
- **3 分及以下**：**框架本身依赖时效**——脱离当前产品格局 / 时间窗口，论点即不成立
- 判据口诀：**"把产品名 / 日期全抹掉，论点还站得住吗？"** 站得住且只需加时间锚 → 4；站不住 → ≤3

**评分**：0~5 分（5 = 3 年后仍可读懂，0 = 3 个月后过时）

### 问题 3｜章节映射（三形态分别判）

**问**：对「书 / 小册 / 课」三形态分别给出映射结果（🆕 09-16 首跑 AGENT-03 改，旧版只判小册会误判强投书的篇目）。

**背景**：09-15 投影文档 §一确立三形态（一稿三形态），单篇常"小册弱映射但书强映射"，不能只对一个骨架判。

**三形态骨架来源**：
- **书** `ai-engineering-handbook`（六层架构 / v0.4 序 + 12 章，野心层：系统怎么设计）→ 读 `github/xingtu-book/books/ai-engineering-handbook/` 若存在
- **小册** `vibe-coder-engineering-guide`（10 章，¥39 避坑：我该怎么干）→ 读 `github/xingtu-book/books/vibe-coder-engineering-guide/`
- **课** 样模块（挂 L4/L5，不新建产品线）→ 读投影文档 §三，或记"暂不映射"

**操作**（对每一形态分别问一次）：
1. 这篇的核心论点最贴近该骨架的哪一章 / 哪个模块？
2. 强 / 弱 / 无映射？（视角与读者是否错位）
3. 若弱或无，说明错位原因（避免硬套，见"常见坑"）

**输出格式**：
```
书：   Ch0X: <章名>（强/弱/无）— 一句话理由
小册： Ch0X: <章名>（强/弱/无）— 一句话理由
课：   样模块 <名称>（强/弱/无）— 或"暂不映射"
```

**判读原则**：**别把三形态都往一篇上套**。投影文档 §零 原话"别让一本 ¥39 的避坑小册去做 ¥199 的书该做的事"——同一篇常只在一两个形态强映射。

**参考**（09-15 Harness 线投影结论 + 09-16 AGENT-03 首跑，会随书稿演进）：
- 小册 Ch03/04/06/07 强供（工作台方法论）；Ch05 可补；Ch08/09 必须换线别硬套
- 书侧：工作台/Harness 本身的野心留给书，"入口/选型"类行业切片是书的**立论背景章**候选（AGENT-03 即此类）

### 问题 4｜可提取素材

**问**：数据 / 案例 / 踩坑 / 金句，能不能拆成素材卡？

**判定标志**（可提取 = 高分）：
- **数据**：具体数字（token/耗时/成本/转化率/榜单排名）
- **案例**：真实项目/产品/事件的完整故事线
- **踩坑**：错误做法 + 正确做法 + 原因分析
- **金句**：可独立引用的观点句（20~50 字，立场鲜明）

**落点**：
- 素材卡落到发布包 `07_作者素材/` 目录
- 或落到 `素材库/` 主库（走 `xingtu-ingest` skill 的价值分级流程）
- 命名：`素材卡_<主题>_<YYYY-MM-DD>.md`

**评分**：0~5 分（5 = 可拆 3+ 张素材卡，0 = 无可提取素材）

## 分级与建议动作

**总分 = Q1 + Q2 + Q4**（Q3 只做映射不计分），满分 15。

| 分级 | 总分 | 判定 | 建议动作 |
|:--:|:--:|---|---|
| **A｜可直接改写** | 12~15 | 立场强 + 论据独立 + 素材丰富 + 章节明确 | 落到发布包 `07_作者素材/`，标记"书稿候选"；下次一稿三形态投影时优先纳入 |
| **B｜需补论据** | 8~11 | 立场强但论据依赖时效性 | 发布公众号版；书稿版需补 3-5 个跨时段案例，标"待补论据"入 `07_作者素材/待补清单.md` |
| **C｜仅时效性** | 4~7 | 蹭热点、立场弱、论据浅 | 只发公众号，不入书；素材卡不必沉淀 |
| **D｜不适合** | 0~3 | 涉个人信息 / 雇主敏感 / 未脱敏 / 立场争议大 | 不发或改到能发；书稿永不考虑 |

**特殊判定**（不看总分直接归 D）：
- 有 🔴 合规硬伤未处置
- 涉真名 / 手机号 / 雇主邮箱（`privacy_scan.py` 未过）
- 立场争议大到可能引发法律纠纷（例如指名道姓批评某产品是"骗局"）

## 合规红线更严（书侧）

**书的法律责任 > 公众号**（更长时效、更强举证、纸媒不可撤稿）。因此书稿版必须：

| 项 | 公众号基线 | 书稿基线 |
|---|:--:|:--:|
| 🟡 人工核 | 汇总一条过一眼即可 | **必须处置到 ✅**（不能挂账） |
| 长引用 >140 字 | 注明出处 + 引号（合理引用） | **书面授权** 或 改写至 <50 字 |
| 官方 App 图标 | 评论性引用边缘可发 | **授权链** 或 改用文字描述 |
| 第三方最高级评价（`PRAISE`） | 汇总一条不阻断 | 加**时间锚**（"截至 YYYY-MM 的观察"） |
| 个人信息扩展（🔴） | 阻断 | 阻断 + **书稿全稿复核**（不能只扫单章） |
| 立场押注 | 敢押即可 | 押注 + **论据可复核**（读者能验证） |

## 素材沉淀落点

### 发布包内沉淀（`07_作者素材/`）

每篇 A/B 级文章发布时，在发布包 `07_作者素材/` 下建：

```
07_作者素材/
├── 素材_<主题>_<YYYY-MM-DD>.md          # 从这篇提取的素材卡（数据/案例/踩坑/金句）
├── book-readiness_<YYYY-MM-DD>.md        # 本 checklist 的填写结果（Q1~Q4 + 分级 + 建议动作）
└── 待补论据_<主题>.md                    # 若分级 = B，列出需补的跨时段案例
```

### 主库沉淀（`素材库/`）

若素材价值高（跨篇复用），走 `xingtu-ingest` skill 的价值分级流程，落到 `素材库/`：
- **黄金级**：跨篇复用的核心方法论 / 一手数据
- **关键级**：单篇强论据 / 独家案例
- **重点级**：可作辅证的数据点
- **高知级**：知识背景 / 术语定义

### 书稿侧沉淀（`github/xingtu-book/`）

若已确定章节映射（Q3 有结果），把 `07_作者素材/` 的素材卡**指针**登记到对应章节的素材索引：
```
github/xingtu-book/books/vibe-coder-engineering-guide/
└── Ch0X_<章名>/
    └── 素材索引.md   # 追加一行：<来源发布包路径> · <素材主题> · <YYYY-MM-DD>
```

**注意**：素材本体**不复制**到书稿目录（避免 SSoT 分裂），只登记**指针**——需要时从发布包 `07_作者素材/` 取。

## 常见坑

| 坑 | 症状 | 教训 |
|---|---|---|
| **总分机械算** | Q1 高分 + Q2 低分 = B 级，但内容其实是蹭热点 | Q2 低分**优先降级**（时效性依赖是硬伤），不看总分 |
| **素材卡复制本体** | 把发布包正文全篇复制到 `07_作者素材/` | 素材卡是**提取**（数据/案例/金句），不是复制 |
| **章节映射硬套** | 强行把跑题文章塞进某一章 | Q3 = "无映射"是合法结果，别硬套（09-15 投影已判 Ch08/09 必须换线） |
| **书稿版走公众号基线** | 长引用 🟡 直接过 | 书侧红线更严（见「合规红线更严」节） |
| **A 级文章不沉淀** | 分级 = A 但没落素材卡到 `07_作者素材/` | A 级**必须**沉淀，否则等于"知道有价值但没资产化" |
| **D 级还发公众号** | 分级 = D 但公众号照发 | D 级意味着合规或立场有硬伤，公众号也不能发 |

## 验证（本 checklist 自查）

跑完本 checklist 后，回答以下问题；任一"否"→ 回炉：

1. 四问是否都给出评分或映射结果？
2. 是否给出 A/B/C/D 分级 + 建议动作？
3. A/B 级是否已落素材卡到发布包 `07_作者素材/`？
4. B 级是否已落"待补论据"清单？
5. Q3 有映射时，是否已登记指针到书稿章节 `素材索引.md`？
6. 书稿版是否处置了**全部 🟡**（不能只"人工核过"）？
7. 分级 = D 时，是否明确"不发或改到能发"？
