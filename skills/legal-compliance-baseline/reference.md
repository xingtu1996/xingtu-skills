# reference.md — 六维扫描规则详解 + 精度迭代经验

> 本文件是 `SKILL.md` 的深度参考层。**SSoT 在 `tools/legal_compliance_scan.py`**，本文件只做规则语义解释、迭代案例复盘、常见坑清单——不复制代码。

## 一、六维扫描详解

### 维度 1｜广告法极限词（《广告法》第 9 条）

**规制对象**：广告中的**自我宣传/商品推广**，不是文章里所有含"最""第一""绝对"的表达。

**扫描词表 `EXTREME`**（16 词）：
```
最、第一、顶级、国家级、独家、首选、万能、绝对、永久、
100%、全网最、史上、空前、绝无仅有、销量冠军、领导品牌
```

**语境判断五层过滤**（按优先级从上到下）：

| 过滤器 | 命中语境 | 判级 | 举例 |
|---|---|:--:|---|
| `ORDINAL` | 序数词 / 术语 | ✅ 不报 | "第一，"、"第一件事"、"第一层"、"第一步"、"第一问"、"第一性原理"、"第一名"、"前三"、"第二"、"第三"、"第十"、"一轮"、"一次"、"一家" |
| `NEG` | 否定句 | ✅ 不报 | "没有绝对"、"不是最"、"不等于最"、"别比"、"未必最"、"不再最"、"没有最" |
| `EXTREME_CTX_OK` | 引用第三方数据 | 🟡 人工核 | "总榜第一"、"增速榜第一"、"排名第一"、"居第一"、"第 1 期"、"第一名" |
| `SELF_GOODS` | 用于**自家商品**宣传 | 🟠 需改 | "自查卡"、"小册"、"课程"、"咨询"、"本书"、"小报童"、"星球"、"付费版" |
| `PRAISE` | 对**第三方**最高级正面评价 | 🟡 汇总一条 | "最猛"、"最好"、"最顺手"、"最强"、"最快"、"最方便"、"最火"、"最普世"、"最深"、"最形象"、"最真切"、"最优"、"最佳" |
| 兜底 | 数据性/中性最高级 | 🟡 人工核 | "最大"、"最多"、"最低"、"最差" 等 |

**窗口判断实现**（关键，避免偏移 bug）：
```python
win = text[max(0, m.start()-4): m.start()+len(w)+6]  # 命中词前 4 字 + 词 + 后 6 字
if any(k in win for k in ORDINAL): continue
```
不要用复杂的句子级偏移计算——09-16 首版就写错过一次，简化成"命中词前后窗口"最稳。

### 维度 2｜商标冒充与贬损

**`IMPERSONATE`**（🟠 需改）：冒充官方表述
```
官方认证、官方授权、官方合作、我们是官方、代表官方
```

**`DEFAME`**（🟠 需改）：品牌贬损词
```
垃圾、骗局、割韭菜、诈骗、智商税、骗子、黑心、倒闭预定
```

**边界说明**：
- 客观评测（"某产品在 X 场景表现不佳"）不属贬损，是评论自由
- 贬损的核心是**主观否定 + 情绪化标签**，不是负面评价本身
- 对比评测文里的"最顺手/最猛"属正面评价第三方，**归 `PRAISE` 汇总**，不逐条报

### 维度 3｜著作权长引用

**规则**：连续 >140 字引号/引用块 → 🟡 人工核
```python
re.finditer(r"[「"]([^」"]{140,})[」"]", text)
```

**处置**：
- 公众号：注明出处 + 引号（属合理引用范畴，但边界模糊）
- **书稿版**：必须获得**书面授权**或改写至 <50 字（书侧红线更严）

### 维度 4｜个人信息扩展（🔴 阻断）

**`PII` 模式**（4 类）：
```python
(r"\b\d{17}[\dXx]\b", "身份证号"),
(r"\b\d{16,19}\b", "银行卡号"),
(r"1[3-9]\d{9}", "手机号"),
(r"[\w.-]+@[\w-]+\.(com|cn|net|org)", "邮箱"),
```

**注意**：本维度**与铁律 10 的 `privacy_scan.py` 有重叠但不重复**：
- `privacy_scan.py` 扫真名/中文姓名/雇主/入职年限/薪资（脱敏红线 SAF-004/SAF-010）
- `legal_compliance_scan.py` 扫身份证/银行卡/手机号/邮箱（个人信息硬伤）
- 发布前**两个都要跑**：`privacy_scan.py --fail-fast` + `legal_compliance_scan.py`

**输出脱敏**：命中后只显示前 6 位 + `****`，避免扫描日志本身泄敏。

### 维度 5｜专业建议（证券/医疗/法律）

**`PRO_ADVICE`**（🟠 需改）：
```python
(r"(建议|推荐)(买入|加仓|全仓|抄底|清仓)", "证券投资建议"),
(r"(保证|承诺)(收益|回报|稳赚|不亏)", "收益承诺"),
(r"(包治|根治|治愈|药效)", "医疗宣称"),
(r"(一定|必然)(胜诉|赢官司)", "法律结果承诺"),
```

**边界说明**：
- 本号内容是**AI 工程化实践**，一般不触证券/医疗/法律
- 但若写"AI 在投资决策中的应用"等交叉话题，容易命中——需人工核是否属"结果承诺"
- 引用他人观点（"某某说会涨"）不属本号建议，但需注明出处避免被视为传播

### 维度 6｜AI 标识义务提示（🟡 长期挂账）

**规则文本 `AI_NOTE`**（脚本尾部固定输出）：
```
义务主体主要为 AI 服务提供者与传播平台；人主导观点/素材/判断、AI 辅助
梳理排版通常不属强制显式标识对象（解读验证程度=中，条文原文待人工核）。

```

**待办 `pending_human`**（脚本尾部固定输出三条）：
1. 读《人工智能生成合成内容标识办法》条文原文，确认人主导+AI辅助的标识边界
2. 极限词 🟡 项逐条确认是否为引用第三方数据的事实陈述
3. 官方 App 图标商用引用边界人工核

**验证程度标注**（BUL-003 数字/事实来源标注纪律）：
- **验证程度=中**：基于公开报道（澎湃/新浪/浙江网信），两次 WebFetch 政府条文详解超时未成功

## 二、精度迭代案例（82 → 24 全过程）

### 首轮：82🟠 误报几乎杀死门禁

**问题现象**（对 AGENT-03 首扫）：
```
🟠 极限词「第一」｜…"第一，生态绑定…"…
🟠 极限词「第一」｜…"第一性原理"…
🟠 极限词「绝对」｜…"没有绝对的谁好谁坏"…
🟠 极限词「最」｜…"最顺手的还是…"…
（共 82 条）
```

**根因诊断**：初版规则只做**词表匹配**，不做**语境判断**——把所有含极限词的表达都当"广告法违规"。但广告法第 9条规制的是**广告中的自我宣传**，不是文章里的：
- 序数词（"第一，"表列举）
- 术语（"第一性原理"是哲学/工程术语）
- 否定句（"没有绝对"恰好是**反极限词**表达）
- 对第三方的正面评价（"最顺手"是评测文的正常表述）

**教训**：**误报多的门禁 = 没有门禁**。狼来了三次，boss 就不看了；这就是僵尸门禁的死法（B-044 同源教训：`.harness/memory/bad-case-index.md` 索引表落后详情小节，因为没人再核）。

### 二轮：加语境白名单，🟠 清零

**修法**：加 `ORDINAL` / `NEG` / `EXTREME_CTX_OK` / `SELF_GOODS` 四层过滤。

**结果**：🔴0 🟠0 🟡59——🟠 清零是对的（本文不卖货，无自家商品宣传极限词）。但 59 个 🟡 仍然偏多，全是"最猛/最好/最顺手/最强"这类**对第三方的最高级正面评价**。

### 三轮：正面评价汇总一条，🟡 降到 24

**再诊断**：59 个 🟡 逐条报仍是狼来了。这些属**评论自由范畴**（正面评价第三方不贬损），贬损风险由 `DEFAME` 单独扫。

**修法**：加 `PRAISE` 白名单——命中就 `praise[0] += 1`，不逐条报，最后汇总一条：
```
🟡 对第三方产品的最高级正面评价 N 处（评论自由范畴；贬损风险由贬损词扫描单独覆盖，此处仅提示知悉）
```

**结果**：🔴0 🟠0 🟡24，精度可用。

### 停止调精度的判断

24 条 🟡 里仍有重复（同一句在 MD 目录和正文出现两次）和低风险项（"最大的支持""第一时间"是惯用语）。可再加惯用语白名单降到 ~10，但**边际收益递减**（09-16 01:3x 深夜，时间盒 ≤ 半天纪律）。

**判断**：当前精度已可用（🔴🟠 精准，🟡 作为人工核清单偏保守但不误阻断）。**停止调精度**，把"惯用语白名单迭代"列为门禁自身的待办——**用真实跑批数据自迭代**，不再过度工程。

**这是铁律 3「不过度工程」的活案例**：加白名单前必问"这个坑，下一篇还会再踩一次吗？"—— 会 → 加；不会 → 让它作为 🟡 存在。

## 三、content_gate 第⑦门禁接入详解

### 接入位置（`tools/content_gate.sh` 102~125 行）

```bash
# ⑦ 法律合规基线（🆕 2026-09-16：著作权/商标/广告法极限词/专业建议/个人信息/AI标识义务）
#    🔴 阻断（个人信息等硬伤）；🟠🟡 仅提示不阻断（需作者人工核，见脚本 pending_human）
TOTAL=$((TOTAL+1))
echo "▶ [$TOTAL] 法律合规基线（legal_compliance_scan）"
LEGAL="$TOOLS/legal_compliance_scan.py"
if [ ! -f "$LEGAL" ]; then
  echo "   ⚠️  脚本缺失: legal_compliance_scan.py"
  FAIL=$((FAIL+1))
elif [ $# -gt 0 ]; then
  if python3 "$LEGAL" "$@" > /tmp/gate_legal_$$ 2>&1; then
    echo "   ✅ 通过（无 🔴 阻断项）"
    PASS=$((PASS+1))
  else
    echo "   ❌ 失败 — 存在 🔴 阻断项，发布前必须清零"
    FAIL=$((FAIL+1))
  fi
  grep -E "🔴|基线扫描|待人工核" /tmp/gate_legal_$$ 2>/dev/null | sed 's/^/      /' | head -12
  rm -f /tmp/gate_legal_$$
else
  echo "   ⚪ 未传目标路径 — 全量基线请跑: python3 tools/legal_compliance_scan.py outputs/发布包_2026-09"
  echo "      （发布前对待发正文必跑：python3 tools/legal_compliance_scan.py <发布包或正文.md>）"
fi
```

### 关键设计

- **有参数才扫**：`content_gate.sh` 无参数时对⑦**跳过**（⚪ 占位），不算 FAIL——因为其他门禁（①虚构口径等）有默认目标，但法律合规扫全库太慢且噪声大
- **阻断条件**：仅 🔴 阻断（脚本退出码 1）；🟠🟡 打印摘要但不计入 FAIL
- **摘要过滤**：`grep -E "🔴|基线扫描|待人工核"`，前 12 行——避免打印几十条 🟡 淹没汇总

### grep 空交替 bug（09-16 已修一次）

**症状**：初版写成 `grep -E "🔴||基线扫描|待人工核"`（🔴 后多了个 `|`），交替项变成 `[🔴, 空, 基线扫描, 待人工核]`——**空项匹配所有行**，导致打印前 12 行（head 限制）而非过滤后的关键行。

**修法**：`sed -i '' 's/grep -E "🔴||基线扫描|待人工核"/grep -E "🔴|基线扫描|待人工核"/'`

**教训**：写 grep 交替前**必须肉眼数一遍 `|` 数量**——空交替是静默 bug，不报错、结果全错。

## 四、发布包目录识别逻辑

`legal_compliance_scan.py` 对目录参数的处理（`main()` 106~120 行）：

```python
if os.path.isdir(a.path):
    pk = os.path.join(a.path, "01_正文")
    if os.path.isdir(pk):
        # 传入的是单个发布包 → 扫 01_正文/*.md 全部
        files = sorted(glob.glob(os.path.join(pk, "*.md")))
    else:
        # 传入的是发布包父目录（如 outputs/发布包_2026-09）
        # → 每包只取 mtime 最新的一个正文 md（避免 v1..vN 全扫噪声）
        files = []
        for d in sorted(glob.glob(os.path.join(a.path, "*"))):
            if os.path.isdir(d):
                c = sorted(glob.glob(os.path.join(d, "01_正文", "*.md")), key=os.path.getmtime)
                if c: files.append(c[-1])
        if not files:
            files = sorted(glob.glob(os.path.join(a.path, "*.md")))
```

**关键设计**：发布包父目录扫描时**每包只取最新正文**（v5 而非 v1~v5 全扫），避免历史版本噪声。

**踩坑**：初版写成"先扫 `01_正文/`，若空则扫根目录 `*.md`"——但发布包父目录（如 `outputs/发布包_2026-09/`）根下没有 md 文件，会误判为"未找到可扫文件"退出。修成上面的两级识别才对。

## 五、官方 App 图标商用引用边界（长期挂账 🟡）

**扫描逻辑**（`main()` 133~136 行）：
```python
assets = glob.glob(os.path.join(a.path, "04_配图", "_assets", "*.png")) if os.path.isdir(a.path) else []
if assets:
    img_notes.append(("🟡", f"官方 App 图标 {len(assets)} 枚（评论性引用边缘，商用号建议人工核授权边界）",
                      ", ".join(os.path.basename(x) for x in assets)))
```

**边界判断**（验证程度=中）：
- **评论性引用**（合理）：文章评测某产品，配一张官方 App 图标做视觉识别——类似新闻报道配图
- **商用引用**（需授权）：把图标用于自家商品宣传（例如"本课程联合 XX 官方出品"）
- **本号现状**：所有第三方图标都用于评测/对比场景，属评论性引用边缘，风险低但**非零**

**处置**：
- 公众号版：🟡 提示，boss 过一眼即可发（当前策略）
- **书稿版**：必须走授权链或改用文字描述（"某办公 Agent 产品"），书侧红线更严

**长期挂账**：待条文原文核 + 商用号规模化后，可能需要联系法务或走 CC/Fair Use 类授权模板。

## 六、常见坑清单（血泪教训）

| 坑 | 症状 | 教训 |
|---|---|---|
| **僵尸门禁** | 误报太多 boss 不看了 | 铁律 2；宁可漏报不可狼来了 |
| **grep 空交替** | `grep -E "A\|\|B"` 匹配所有行 | 空项等于"匹配任意"，写入前跑一遍验证 |
| **偏移计算错** | 窗口判断绕来绕去还是错 | 简化成 `text[max(0,m.start()-4): m.start()+len(w)+6]` |
| **规则代码复制到 SKILL.md** | SSoT 分裂、脚本改了 skill 没改 | SKILL.md 只写"六维概览"，规则代码永远在 `tools/legal_compliance_scan.py` |
| **法律意见** | 用户问"这样违法吗" | 本 skill **不出具法律意见**；只出"命中 + 上下文 + 判级"，条文原文列入 🟡 人工核 |
| **过度工程** | 白名单加到 200 条还在加 | 铁律 3；每条加前问"下一篇还会踩吗" |
| **发布包父目录扫不到** | 初版目录识别只看 `01_正文/`，父目录扫出 0 文件 | 两级识别：单包看 `01_正文/`，父目录 glob 每包取 mtime 最新 |
| **书稿版走公众号基线** | 长引用 🟡 直接过 | 书侧红线更严，🟡 必须处置到 ✅ |
| **规则代码硬编码到 skill** | 脚本改了 skill 没同步 | SSoT 在 tools/，skill 只写语义 + 命令 |
| **采信 CHANGELOG "门禁全绿"** | 历史文字记录当凭证 | 完成判定查凭证不问模型（B-009/B-046），必须**现跑**脚本 |

## 七、扩展维度的接入 checklist

未来若要加新维度（例如"数据准确性扫描""竞品对比公平性"），走这个流程：

1. **判定是否属法律合规范畴**
   - 是 → 加进 `legal_compliance_scan.py`
   - 否 → 单开脚本（例如 `data_accuracy_scan.py`），不塞进本 skill

2. **精度达标才接入**
   - 单跑 3~5 篇历史发布包 → 统计误报率
   - 🔴🟠 精准、🟡 ≤ 10 条 → 达标
   - 未达标 → 迭代白名单，别急着入 content_gate

3. **content_gate 接入**
   - 参照⑦段模板：脚本存在检查 → 有参数才扫 → 阻断条件明确 → 摘要 grep 过滤（**数 `|` 数量**）
   - 加完跑一次 content_gate 全量，看是否影响其他门禁

4. **回写四处**（铁律：不回写 = 变更未发生）
   - `CHANGELOG.md`（`python3 tools/changelog_append.py --type "🔧" --tool qwenwork`）
   - `SKILL.md` 变更历史节
   - `reference.md` 本文件对应维度详解
   - `.agents/skills/LEDGER.md`（`python3 tools/skill_ledger.py` 自动重生）

5. **验证**：跑本 skill 六节自查清单（`SKILL.md` §六）
