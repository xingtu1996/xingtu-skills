# 听友好版改编（Audio-Friendly Adapt）— xingtu 版

> 定位：图文成稿 → 听友好版的标准化派生流程，确保同一篇内容覆盖"看"和"听"两种场景。
> 规则锚点：PUB-024（六条铁律）+ PUB-025（多形态产线）+ PUB-026（完结检查）。
> 原则：**只改表达层，不改核心观点**；**纯文本无噪音**；**编号可听辨**。

## 触发条件

以下任一触发：
- 用户说：听友好 / 音频版 / 播客版 / 朗读版 / 语音版 / 听书版 / 改成能听的 / 多形态派生
- 图文版定稿后，按 PUB-025 多形态产线自动派生
- 内容创作完结检查（PUB-026）发现听友好版缺失

## 改编检查清单（PUB-024 六条铁律，逐条过）

### ① 必砍：朗读噪音元信息
以下内容**全部删除**，不出现在听友好版中：
- frontmatter（`---` 包裹的 title/seo_core/desensitize 等）
- mermaid 代码块（` ```mermaid ` 整块）
- 其他代码块（` ``` ` 包裹的配置/命令/代码）
- "配图建议"、"配图建议（复利曲线）"等发布元信息
- "平台微调（PUB-004 禁通稿）"整块
- "脱敏确认"整块
- "文末尾舱"整块（关于行途/延伸阅读/关注/名片位）
- "改编说明"整块（非朗读内容）
- 表格（用口语描述替代，见下方④）

### ② 编号口语化
- 大标题编号："一、二、三、四、五" → "第一部分、第二部分、第三部分..."
- 小标题编号："1. 2. 3." → "第一点、第二点、第三点..."
- 无序列表（`- ` 开头）→ "第一点... 第二点... 第三点..."（按出现顺序编号）
- 嵌套列表：外层"第一点"，内层"其中第一小点"
- 保留标题文字本身，只改编号前缀

### ③ 数字口语化
- 精确数字 → 口语化约数："1161 张" → "一千一百多张"；"70%" → "七成"；"3.2万" → "三万二"
- 年份保留："2026 年"直接读"二零二六年"或"今年"（根据上下文）
- 百分比："2-4%" → "百分之二到四"或"两到四个百分点"
- 比例："3:4" → "三比四"
- 金额："¥699" → "六百九十九元"
- 原则：**听的时候不需要精确值，需要的是量级感**；精确数字只在金句/关键数据处保留

### ④ 图表用嘴描述
- mermaid 流程图：用"我给你描述一个循环：第一步... 第二步... 第三步... 最后回到第一步"替代
- 架构图："从下往上看，最底层是... 中间层是... 最上层是..."
- 对比表格："左边是 A，特点是...；右边是 B，特点是...；两者的区别在于..."
- 数据图表："横轴是时间，纵轴是能力，曲线初期平缓，到某个拐点后陡峭上扬"
- 原则：**让没看到图的人也能在脑子里画出图**

### ⑤ 加开头问候 + 结尾道别
- 开头模板（三选一，根据内容调性）：
  - 通用型："大家好，欢迎来到行途。今天这期，我想聊..."
  - 故事型："大家好，我是行途。前几天发生了一件事，让我意识到..."
  - 观点型："大家好，欢迎收听。今天分享一个我越来越笃信的认知..."
- 结尾模板（三选一）：
  - 通用型："感谢收听，我是行途，我们下期见。"
  - 互动型："如果你也有类似的经历，欢迎在评论区告诉我。我是行途，下期见。"
  - 金句型："最后送你一句话：[金句]。感谢收听，我是行途。"
- 开头必须包含"问候 + 本期主题预告"，结尾必须包含"道别 + 署名"

### ⑥ 文件命名与落盘
- 命名规范：`原编号_标题_听友好版.md`
  - 例：`B11-技术人的复利_听友好版.md`
  - 例：`C03_AI项目的70%墙_听友好版.md`
- 落盘位置：与图文版同目录（`素材库/成稿/` 或 `02_草稿箱/`）
- 与图文版并存，不覆盖原文
- 文件头部加一行标记：`> 适用：播客 / 视频号语音 / 音频朗读。纯文本，无代码无图表，编号口语化。`

## 改编流程（Step by Step）

### Step 0: 前置侦察
- 读取图文版原文，确认结构（几个大部分、几个列表、有无代码/图表/表格）
- 确认原文 frontmatter 中的 desensitize 标记（听友好版同样需要脱敏，对齐 SAF 族）
- 确认是否已有听友好版（避免重复派生）

### Step 1: 执行六条铁律
按 ①→②→③→④→⑤→⑥ 顺序逐条执行，每执行一条在心里打勾

### Step 2: 朗读自检（关键）
改编完成后，**默读一遍**，检查：
- [ ] 有没有残留的 Markdown 标记（`**`、`>`、`- `、`#`）
- [ ] 有没有残留的元信息（配图建议/平台微调/脱敏确认）
- [ ] 编号是不是都口语化了（还有没有"一、"或"1."）
- [ ] 数字是不是都口语化了（还有没有"1161"或"70%"）
- [ ] 图表是不是都用嘴描述了（还有没有 mermaid 或表格）
- [ ] 开头有没有问候+主题预告
- [ ] 结尾有没有道别+署名
- [ ] 整体读起来顺不顺，有没有"看的语言"（如"如下图所示"、"见上表"）

### Step 3: 完结检查（PUB-026）
听友好版派生完成后，触发内容创作完结检查：
- [ ] 图文版已定稿
- [ ] 听友好版已派生（本 skill 产出）
- [ ] 短视频脚本版已派生（如排期需要）
- [ ] 平台差异化适配完成
- [ ] 隐私扫描全绿
- [ ] session 沉淀已执行
- [ ] CHANGELOG 已回写

## 常见反模式（禁止）

1. **只删 frontmatter，不编号口语化**：听的时候"一、二、三"和"1. 2. 3."容易混淆
2. **保留代码块**：语音朗读代码块是灾难，必须删除或用口语描述
3. **保留"如下图所示"**：听的人看不到图，必须改成"我给你描述一下"
4. **开头直接进正文**：没有问候和主题预告，听众不知道在听什么
5. **结尾直接结束**：没有道别和署名，听众不知道是谁在讲
6. **覆盖原文**：听友好版必须与图文版并存，不能覆盖原文
7. **精确数字不口语化**："1161 张"听的时候需要反应一下，"一千一百多张"更自然
