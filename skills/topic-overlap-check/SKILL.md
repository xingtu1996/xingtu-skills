# 主题撞库核查（topic-overlap-check）

> **适用范围守卫**：专为「行途 XingTu」内容仓库设计。当前工作区不含 `github/xingtu-vault/02_内容仓库 (Content Hub)/` 时，声明不适用并停止。
> 本 skill 管**主题撞库**（写过没），不管**标题撞题**（搜一搜被淹没）：

| 要做的事 | 走哪 |
|---|---|
| 标题撞题（同标题/同框架词被大媒体写过） | `mp-title-collision-rename`（WebSearch 双查） |
| 主题撞库（这个角度/这个读者群以前写过没） | **本 skill**（本地已发文章聚簇） |
| 选题入池时的初筛 | 本 skill + `xingtu-ingest` |

## 一、为什么要有这个 skill

10-22 冷启动复盘 40 篇全靠人肉盘点撞库（CHANGELOG 19:14）——把 40 篇标题/开头翻一遍，判断"这个主题是不是写重复了"。痛点：
- **人肉盘点不可复现**：下次换个 agent 又得从头翻。
- **标题撞题 ≠ 主题撞库**：标题不一样但讲的是同一件事（如 RTK 两篇讲同一家公司不同切面），标题撞题 skill 查不出来。
- **读者群覆盖盲区**：写给"AI 工程团队负责人"的稿子已经写了 3 篇，再写第 4 篇同读者群 = 边际递减，但不显式盘点就发现不了。

本 skill 把撞库检查**前置**到动笔前/入池时，不靠人肉记忆。

## 二、触发时机（三个时点）

| 时点 | 谁触发 | 查什么 |
|---|---|---|
| **动笔前**（写新稿前） | boss 说"开始写 XX" | 主题级：这个角度写过没？ |
| **选题池入池时** | `xingtu-ingest` 收素材 | 入库前先查：这个素材是否已被覆盖？ |
| **标题撞题核查前** | `mp-title-collision-rename` Step 1 前 | 主题聚簇先跑一遍，避免改完标题才发现主题本身重复 |

**不触发的场景**：日常改稿、封面重渲、发布流程——这些跟主题撞库无关。

## 三、查库路径（三个真源）

按顺序扫：

1. **已发文章正文**：`github/xingtu-vault/02_内容仓库 (Content Hub)/`（按月份目录）
2. **生产态稿件**：`outputs/内容稿件/`（含未发草稿）
3. **发布归档区**：`github/xingtu-vault/02_内容仓库 (Content Hub)/07_发布与归档/`（已发成品）

**聚簇方法**（不靠全文对比，靠标签/角度词）：
- 提取候选稿的 **3 个核心主题词**（如"RTK"、"Agent 编排"、"FDE"）+ **1 个读者群标签**（如"技术负责人/独立开发者/职场转型"）。
- 在三个路径里 `grep` 这 3+1 个词，按命中篇数排序。
- 人工读 Top 5 命中篇的**开头 3 段 + 一句话摘要**（不读全文），判断"角度是否真的重复"。

## 四、输出格式（三行结论，不多写）

```
此角度写过 N 次：<列篇名，逗号分隔>
此读者群已覆盖：<覆盖 N 次 / 未覆盖>
建议差异点：<一句话——要么"换读者群"，要么"换切面"，要么"停写">
```

**示例**（虚构）：
```
此角度写过 2 次：《RTK vs MCP 选型》、《FDE 工具链实测》
此读者群已覆盖：技术负责人已写 5 次，边际递减
建议差异点：本篇切"独立开发者/小团队"读者群，不切"企业选型"
```

**判定阈值**：
- 同角度同读者群 ≥2 篇 = 🔴 回炉（必须换切面或换读者群）
- 同角度不同读者群 = 🟡 可发但需在开头明示"这篇写给谁，跟 XX 篇有何不同"
- 不同角度 = 🟢 直接过

## 五、与 mp-title-collision-rename 的分工

| 维度 | mp-title-collision-rename | topic-overlap-check（本 skill） |
|---|---|---|
| 查什么 | 标题撞题（搜一搜同标题大媒体 ≥3 篇） | 主题撞库（本地已发文章同角度聚簇） |
| 数据源 | WebSearch 公网 | 本地 vault + outputs |
| 时机 | 标题已写定之后 | 动笔之前 / 入池时 |
| 输出 | 三候选新标题 | 三行撞库结论 |
| 先后 | 本 skill 先跑 → 过了再写标题 → 标题 skill 跑 | — |

## 六、首案参考（10-22 冷启动复盘 40 篇）

10-22 复盘时人肉盘点 40 篇的痛点：
- HARN-05 / 16GB 等撞库案例是**事后**才发现（发完才知道写重复了）。
- 人肉盘点不可复现，下次新 agent 接手得重新翻 40 篇。
- 结论只留在对话里，没沉淀成"主题→篇名"的索引表。

**本 skill 的沉淀义务**：每次跑完，把命中的主题聚簇追加到 `github/xingtu-vault/02_内容仓库 (Content Hub)/00_主题索引.md`（若无此文件则新建）——下次直接查索引，不用重新 grep。

## Pitfalls（实测坑）

- **只查标题不查正文**：标题不一样但正文讲同一件事，会漏。必须读命中篇的开头 3 段。
- **把"同读者群"当"同角度"**：写给技术负责人的稿子可以写第 6 篇（只要切面不同），不是读者群重复就回炉。
- **grep 太宽**：如查"Agent"会命中 30 篇没用。主题词必须 3 个具体词（产品名/方法名/场景名），不要泛词。
- **不沉淀索引**：跑完只回结论不写索引 = 下次还得重跑。
- **跟标题撞题混淆**：本 skill 不查公网、不出新标题——那是 mp-title-collision-rename 的活。

## Verification（成功凭证）

- 输出严格三行结论，含具体篇名（不空泛）；
- 命中的主题聚簇已追加到 `00_主题索引.md`；
- 🔴 回炉时给了具体差异建议（换读者群/换切面），不是空说"写重复了"；
- 已向 boss 明示：**本 skill 过了 ≠ 标题能发**，标题撞题还得走 `mp-title-collision-rename`。
