# 平台能力 → 行途 IP 变现参考价值审计

## 适用与不适用

**适用**：boss 甩来一个链接（平台 / 仓库 / 工具），想知道「这玩意对行途 IP 的变现和运营有没有用、能不能操作」。

**不适用**：纯技术教程调研（那是 research 范畴）；已有明确执行指令的任务（直接干）。

## 核心立场

**不要罗列能力，要回答「对行途战略的增量是什么」。** 一份只列出「这个平台能发帖、能评论、能付费」的报告没有价值——价值在于指出**哪些能力是我们上一轮评估漏掉的、哪些能补上战略短板、哪些能动但什么时候动**。

行途战略锚点（每次都要对齐）：
- 第一性原理：内容利他、对准目标用户，每篇原创积累信任成本
- 定位：既带团队又写代码的人，讲 AI 工程化怎么落地
- 变现终局：利他 → 信任 → 星球（知识星球，年费 199–599）
- 内容形式：文章 / 图文 / 视频（**视频是当前产能短板**）
- 主阵地公众号，其余平台分发占位

## 工作流（7 步）

### ① 一手实查（禁二手转述）
并行执行，不串行：
```bash
# GitHub 仓库 → gh 实拉（不用 WebFetch 猜）
/opt/homebrew/bin/gh repo view <owner>/<repo> --json name,description,stargazerCount,forkCount,updatedAt,pushedAt,licenseInfo
/opt/homebrew/bin/gh api repos/<owner>/<repo>/contents/            # 目录结构
/opt/homebrew/bin/gh api repos/<owner>/<repo>/readme --jq '.content' | base64 -d
/opt/homebrew/bin/gh api repos/<owner>/<repo>/contents/<path> --jq '.content' | base64 -d

# 本地状态实查
which <cli> && <cli> --version && <cli> auth status
ls -d ~/.claude/skills/*<kw>* ~/.workbuddy/skills/*<kw>* 2>/dev/null   # 是否已有同类 skill
```
**数字必须实拉**（star / 版本 / 日期），不写「约」「大概」。

### ② 与我们现状对比（这步最容易被跳过，但最出结论）
必查三件事：
- **我们已有的同类资产是什么版本？** 例：WorkBuddy 平台内置 connector 常是**旧版简化封装**，GitHub 上的官方版才是完整形态——版本号一比，增量立刻显形。
- **本地环境缺什么？** 例：`~/.claude/skills/` 没有 → 装它有明确增量。
- **认证通道有几条？** 这类平台常有**多条并行通道**（平台 connector / CLI OAuth Keychain / MCP Key），要数清楚并写进结论，否则日后会混用。

### ③ 能力全景（分类，不流水账）
按「内容生产 / 运营自动化 / 多模态出图出片 / 变现支付」四类归拢。
**重点标记上一轮评估漏掉的能力**——这些才是本次的价值所在。

### ④ 对照战略找增量（灵魂步骤）
逐条回答：
- 能不能**补全变现闭环**？（从「知道规则」升级到「可自动化编排」？）
- 能不能**补内容矩阵短板**？（尤其视频——一篇内容能否裂变为 长文 + 海报 + 竖版视频？）
- 能不能**反过来成为内容素材**？（用过一轮后写成《我是怎么用 AI 运营 X 的》，形成 用→写→引→卖 正循环）
- 是否对齐**多 harness 协作**战略？（Claude Code / Codex / Cursor / OpenClaw）

### ⑤ 安全审计（P0/P1/P2 分级）
逐项审并给处置：
| 审计项 | 典型判断 |
|---|---|
| 来源可信度 | 官方 org / 知名作者 / 协议 / star / **最近更新时间**（>3 个月未更新要警惕） |
| 代码形态 | 纯文档（documentation-only）风险低；有可执行脚本须细看 |
| 凭据处理 | 是否存系统 Keychain？是否明文落盘？ |
| 写操作护栏 | 是否有确认门？不确定 ID 是否先查询？ |
| **涉资金** | 有支付 / 下单 / 转账能力 → **一律 P1**：非 boss 逐次明确指令不触碰、不预授权 |
| **隐私可见性** | 公开可见内容（如 zsxq 的 Note 任何持链者可访问）→ 禁写隐私 / 真名 / 雇主（对齐 SAF-004） |

### ⑥ 分层操作清单（三档，不是一锅粥）
- ✅ **现在就做**：零业务风险的能力预埋（存档快照、登记台账、装纯文档型 skill）
- ⏳ **触发才做**：写清触发条件（如「公众号破千粉 / 稳定回流」）
- 🚫 **现在禁做**：空转动作（粉丝不足就建付费社群）、踩红线动作（把平台内容当公众号原创首发 → BCI-001）

### ⑦ 交付 + 登记（空间铁律，漏了等于没做）
1. **HTML 单文件零依赖看板**（boss 硬偏好，MD 只做机器中间层），配色：行途蓝 `#056DE8` + 亮蓝 `#4A9EFF` + 青 `#00D4FF` + 对比橙 `#FF6B35`，light theme 用浅底深字
2. 看板结构：一句话结论 → 实查事实表 → 版本差异对比 → 能力全景 → 战略增量 → 安全审计 → 分层清单 → 待拍板
3. **登记三索引**：
   ```bash
   # 产出索引.md 加一行（日期 | 标题 | 详细概要）
   # CHANGELOG.md 用官方工具（勿手写）
   python3 tools/changelog_append.py --type "🔍" --path "<路径>" --desc "<为何改了什么>" --date YYYY-MM-DD --time HH:MM
   # 直接 Edit 产出索引.md；DIRECTORY.md 视资产性质决定
   ```
4. **写工作日志** `.workbuddy/memory/YYYY-MM-DD.md`（append-only）
5. **长期事实沉淀**：若是认知修正 / 通道数量 / 红线这类跨会话有用的事实，同步更新 `.workbuddy/memory/MEMORY.md`

## 交付前自检

- [ ] 所有数字都是实拉的，没有「约 / 大概 / 应该是」
- [ ] 明确写出了「上一轮评估漏掉了什么」——没写出来说明这轮白做了
- [ ] 安全审计给了 P0/P1/P2 分级，涉资金项列了 P1 并写明需逐次授权
- [ ] 有三档分层清单，不是一堆并列待办
- [ ] 未核实项**明确标注待验证**，没有拿猜测当结论（BUL-003）
- [ ] 三索引 + 日志已写（不回写 = 变更未发生）

## 已知坑

- **`/tmp` 快照会失效**：跨轮次时 `/tmp/xxx.md` 可能已不存在，重新拉取并**直接落盘到工作区**，不要寄存在 /tmp
- **`timeout` 命令在 macOS 不存在**：用 `gtimeout` 或去掉
- **`grep` 中文路径可能搜不到**：用 `cd` 到目标目录再 grep，或直接用 Grep 工具
- **CHANGELOG 工具会提示「旧章节编号需手动顺延」**：该工具每天插入新章节时编号都写 `## 1.`，历史遗留多个 `## 1.` 并存，属已知问题，不必强行重编号（会牵连 `## 2/3/4` 章节）
