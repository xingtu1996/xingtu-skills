# 四路抽取提示词（可替换项目名复用）

## 〇、怎么用

1. 把本文件的**共同前导**（§一）复制到每路 Agent 的提示词开头
2. 按路数挑对应章节（§A / §B / §C / §D），替换 `{占位符}`
3. **四路同时发出**（一条消息里并行发起）——数据源无交集，只读操作，互不依赖
4. 四路回来后，主线程按 SKILL.md「阶段 2 合成」收敛

**替换表**（发之前逐项填实）：

| 占位符 | 填什么 | 示例（泛化） |
|--------|--------|-------------|
| `{项目}` | 项目代号 | 示例项目 |
| `{文档仓}` | 已发布文档所在目录 | `{文档仓}/` |
| `{本地工作区}` | 未发布的草案/方案/资料目录 | `{工作区}/` |
| `{规格目录}` | 需求/设计/Spec/原系统材料 | `{规格目录}/` |
| `{会话目录}` | 逐字稿、纪要、聊天归档 | `{会话目录}/` |
| `{域}` | 本次要抽的业务域 | 某业务域 |

> ⚠️ **不得**在提示词里硬编码客户名/仓名/人名——一律走占位符。抽取 Agent 的输出里出现的项目专有名词是**数据**，不是模板内容。

## 一、共同前导（四路都要带）

```text
你是「{项目}」统一语言抽取 Agent 的其中一路。你的任务是从你负责的数据源里，
抽出【术语】和【业务本体要素】，按下面的输出契约返回。

## 你是哪一路
{本路名称}——只扫：{本路目录/范围}。**不要越界扫别的目录**（其他三路有人在扫）。

## 抽取目标
1. 业务术语（业务概念词）
2. 技术术语（分开记：As-Is 现状 / To-Be 目标 / 环境工具链）
3. 业务本体要素：对象 / 关系 / 动作 / 规则
4. **禁止别名**：同一概念在材料里出现过的错误写法、旧写法、转写错字
5. 易混淆词：两个词常被混用、且混用会出事

## 铁律
- **出处必填**：每条必须写 `{文件相对路径}:{行号}` 或 `{文件} §{节}`。写不出来源的条目——不要写。
- **置信度必填**，三级：
  🟢 已实测 / 客户原话（有可指认的一手来源：逐字稿行、原系统页面、命令输出）
  🟡 文档佐证（Spec / 纪要 / 设计文档有明确记载，但未实证）
  🔴 仅推断（从命名或上下文推测，无直接来源）
  **宁低勿高**——拿不准就降一级。
- **定义要能独立读懂**：禁写「见 XX 文档」「同上」「详见 §X」。
- **不许编**：查不到就留空或标 `[待确认]`，**一个字都不要猜**。
- **冲突单列**：同一概念在不同文件里说法不一致时，**不要静默择一**——
  两条都写进「冲突与存疑」表，说明各自出处与差异。
- **原文引用优先**：业务文案、错误码、字段名、界面文案**照抄原文**，不改写、不意译、不美化。

## 输出契约（**格式不要改**，主线程靠它机械合并）

> **表头名是硬约定**——合并脚本按表头名找列，不按列序。**列序随意，表头名不能变。**
> 没有内容的表也要留表头，写「无」——整张删掉会被当成"这路没跑"。
```

## A 路：文档仓全仓（已发布文档）

**用途**：抓**已经发出去的**口径——面向全员、写给团队看的文档。这里的说法一旦错，传播面最大。

```text
【A 路 · 文档仓全仓】
范围：`{文档仓}/` 全仓 Markdown（排除 .git、node_modules、archive/ 归档目录）。

重点：
- 已有的术语表 / 词表 / 索引 / 上手文档——**先找存量词表**，它们是并表的基础
- 各文档的**文件头元信息**（生成时间、真相源声明、置信度声明）
- 文档间**互相引用**的术语（引用处数 = 改名成本，单独列出来）

额外产出（在契约之外加一节）：
## 存量术语载体清单
| 载体文件 | 词条规模 | 定位 | 被谁引用 |
```
> ⚠️ 找到多份存量词表时，**不要合并到一起去重**——只报告"哪几份、各自管什么、重叠在哪"，主线程来做分层归位。

---

## B 路：本地工作区（未发布草案）

**用途**：抓**还在草稿态**的口径——方案、评估、汇报、临时笔记。这里最容易出现"同一个词三种叫法"。

```text
【B 路 · 本地工作区】
范围：`{本地工作区}/` 下的 Markdown / 表格 / 文本（排除依赖目录、构建产物）。

重点：
- 同一概念在不同草案里的**不同叫法**（这正是"禁止别名"的原料）
- **口径演进痕迹**：被推翻的旧口径（如"A 方案" → 后来改"B 方案"）——
  旧口径也要收，标「已作废」，注明作废依据与时间
- 与已发布文档**不一致**的地方 → 一律进「冲突与存疑」表

额外产出（在契约之外加一节）：
## 口径演进
| 旧口径 | 新口径 | 变更依据（谁·何时·哪句话） | 是否已同步到发布文档 |
```
> ⚠️ 「已作废」不等于「删掉」——**要留痕**，否则下次有人在旧草案里翻到旧口径，又会当新口径用。

## C 路：业务规格 / 需求 / 设计（业务本体主产地）

**用途**：**本体四张表（对象/关系/动作/规则）的主力**。这路产出的对象与规则数量应占全文大头。

```text
【C 路 · 业务规格】
范围：`{规格目录}/`（需求、设计、Spec、原系统材料、demo 演练稿、接口清单）。

重点：
- **对象**：出现在业务流程里的实体——每个都问三句：它是什么？它由什么构成？它存在哪？
- **关系**：对象之间连什么线——关系名用**动词短语**，必须带基数
- **动作**：谁能对什么做什么——主体（角色）必填，前置条件与后置效果必填
- **规则**：什么不能做 / 必须满足什么——**优先照抄系统既有错误码**，不另造编号
- **状态机**：有状态的对象，把流转图画出来（用代码块，别用图片）

额外要求：
- 对象**没有独立数据表、只是文本字段**这类事实，必须写明（这是最容易踩的坑）
- 同一对象在需求与设计里字段不一致 → 进「冲突与存疑」
- 版本号、协议名、许可这类**易变事实**，照抄材料原文，不自己"更新"
```
> ⚠️ 源码未到位时，本路全部产出**不得超过 🟡**——一切以文档描述为限，从命名反推的一律降 🔴。

---

## D 路：会话与会议记录（真相源最高，噪音最大）

**用途**：抓**客户/干系人原话**——这是把条目从 🟡 升到 🟢 的唯一途径；同时抓语音转写错词。

```text
【D 路 · 会话与会议记录】
范围：`{会话目录}/`（逐字稿、纪要、聊天归档、录音转写）。

重点：
- **客户原话**：原样摘录 + 定位（`{文件}:{行号}`）。这条决定了别的路能升到 🟢 的资格。
- **语音转写错词**：逐字稿里像术语、但拼写/用字可疑的词——
  重点抓「同一概念多种转写写法」「明显同音异形」两类。**别自己纠正**，把原样和疑似正解都列出来。
- **决策与口径变更**：谁在什么时候说了什么，改变了哪个口径。
- **与他人材料冲突**：转写稿说的与文档写的不一致 → 进「冲突与存疑」，注明**以逐字稿为准**。

额外产出（在契约之外加一节）：
## 原话摘录（对外可用的一手来源）
| 原话（照抄） | 说话人 | 时间 | 文件:行号 | 能支撑哪条术语/规则升 🟢 |

## 转写可疑写法
| 疑似错写 | 出现的上下文 | 疑似正解 | 依据 | 建议处置 |
```
> ⚠️ **不改原文**。逐字稿一个字都不动——错词的处理方式是**记进别名表**，不是去改转写稿。

## 二、四路的关系（为什么可以并行）

| 路 | 数据源 | 与他人是否有交集 | 读/写 |
|:--:|--------|:--:|:--:|
| A | 已发布文档仓 | 无 | 只读 |
| B | 本地工作区（草案） | 无 | 只读 |
| C | 规格 / 需求 / 设计 | 无 | 只读 |
| D | 会话与会议记录 | 无 | 只读 |

**判据**：**数据源无交集 + 全部只读** → 可完全并行。
一旦出现「A 路要读 B 路产出的文件」这类依赖，就**不能并行**，必须改成串行。

**并行的代价**：四路输出风格必然有差异 → 靠上面的**输出契约**把格式钉死，合成时才能机械并表、不靠人读。
