# 项目级统一语言——建册 · 增量 · 追踪 · 对账

## 你要解决的事

用户说：

> "建个术语表" / "统一一下叫法" / "这个词到底叫什么" / "抽一下业务本体" / "两份文档口径不一致" / "改了术语要同步哪些地方"

**你要把他从「术语散落在十几份文档里，谁写谁的，改了 A 忘了 B」带到「有一份文档，写材料前查一遍、改术语前看一眼影响面」。**

产物有四种，按他要什么给什么：

| 他要什么 | 你的产物 |
|---------|---------|
| 建册 | 项目文档仓里的**统一语言文档**（本体 + 术语 + 别名禁令 + 维护指南） |
| 增量 | 该文档的**新增/修订段落** + 版本历史新行 |
| 追踪 | 改术语前的**影响清单**（文件:行号 + 要改成什么 + 验证命令） |
| 对账 | 两份材料口径不一致的**冲突清单**（各自出处 + 建议处置） |

---

## 这个技能为什么存在

- **解决什么问题**：**三个真实痛点，缺一个都不需要这个技能。**

  | # | 痛点 | 表现 | 后果 |
  |:--:|------|------|------|
  | 1 | **术语散落无主从** | 同一概念在 5-7 处各有定义，部分重叠，没声明谁优先 | 双维护 → 漂移 → 读者查到旧口径 |
  | 2 | **口径漂移改一处忘 N 处** | 改一个词要同步十几个引用点，全靠人肉 grep | 一天犯 5 次"改了 A 忘了 B" |
  | 3 | **词表纯手工必腐烂** | 新增术语靠人记得去加，没人记得 | 文档写完即过期，回到原点 |

  **手工维护的术语表一定腐烂——这是这个技能存在的唯一理由。** 技能的价值不在"写出一份词表"，在**下次还有人跑它**。

- **不解决什么（边界）**：
  - ❌ **不管人名**——人名转写校正走 `stakeholder-register` 技能，同构但不同域（一个是概念名，一个是人名），读者和场景都不同，**不合并**
  - ❌ **不裁定角色职责**——以项目周报/项目全景为准
  - ❌ **不做翻译**——中英互译走 `doc-translate`
  - ❌ **不猜**——没有来源的条目标 `[待确认]`，**一个字都不要编**

- **决策依据**：
  - **文档落项目仓，不落本技能** —— 本技能包**公网可达**，真实业务口径、客户名、人名进包 = 把项目内情挂公网。技能只提供**方法、提示词、骨架**，数据留在项目里。
  - **文件名能不改就不改** —— 主文档常被十几处引用。改名收益 < 断链成本。原地升级内容，**保持文件名不变**。
  - **单文件优先** —— 单文件才有人读。深水区内容下放分册，不在主文档里堆。
  - **一个概念一处定义** —— 分册不重复主文档词条；镜像从主文档单向同步，不独立维护。

## 四种用法（按用户要什么给什么）

| 用法 | 他说什么 | 你跑哪几步 | 产物 |
|------|---------|-----------|------|
| **建册** | "建个术语表""抽一下统一语言" | 阶段 0 → 1 → 2 → 3 **全跑** | 完整文档（八分区） |
| **增量** | "加个术语""这个说法更新一下" | 阶段 0（查重）→ 局部抽取 → 合成（单条）→ 落地 | 文档新增/修订段 + 版本历史行 |
| **追踪** | "改这个词要同步哪些地方""旧叫法还有没有残留" | 阶段 0（引用面）→ 输出影响清单 | 文件:行号 + 改成什么 + 验证命令 |
| **对账** | "这两份口径怎么不一样""以哪个为准" | 抽取两处 → diff → 冲突清单 | 冲突清单（不静默择一） |

> **用法 2/3/4 都不跑四路并行** —— 四路是给"从零建册 / 大版本刷新"用的重武器。单条增量直接局部扫描，别为了一个词起四个 Agent。

## 核心流程

### 阶段 0：盘点（**串行起点，不能跳过**）

**任何抽取动作之前，先做两件事。**

```bash
# ① 找存量词表——已有的比新建的重要
ls *glossary*.md *术语*.md *统一语言*.md 词表*.md 2>/dev/null
grep -rl "术语表\|统一语言\|glossary" --include="*.md" . 2>/dev/null | head -20

# ② 测引用面——改名的成本在这里量出来
bash scripts/scan-refs.sh <术语文档> <仓库根>
```

`scan-refs.sh` 返回 `文件:行号 | 引用形式 | 命中行原文`，退出码 `0 = 无命中 / 1 = 有命中`。
**先跑一次拿清单，再决定动哪些**——术语改名的代价不在术语表本身，在**引用它的那些文件**。

**输出一张影响清单**：

| 目标文件 | 引用方 | 处数 | 处置 |
|---------|--------|:--:|------|
| {主文档} | {文件1(3) / 文件2(2) …} | {N} | 文件名不变，原地升级 → 零断链 |

**判据**：

- 找到**一份**含术语定义的 Markdown → 原地升级它，**不要建第二份**
- 找到**多份** → 报告"哪几份、各自管什么、重叠在哪"，做**分层归位**（主文档管全局，分册管某个只有它能管的深水区），不做合并
- 一份都没有 → 走建册

> ⚠️ **并列 vs 分层**：三份平级词表 = 必漂移；`主文档 + 分册 + 镜像` = 可维护。
> **两份清单并存 = 下次校验以谁为准的争论。**

### 阶段 1：四路并行抽取

**数据源切分为四路，各自独立抽，互不读对方的产出。**

| 路 | 数据源 | 抽什么 | 为什么单列这路 |
|:--:|--------|--------|--------------|
| **A** | 已发布文档仓全仓 | 存量词表、文件头真相源声明、文档间引用 | 已经发出去的口径错，传播面最大 |
| **B** | 本地工作区（未发布草案） | 同一概念的不同叫法、口径演进痕迹 | "禁止别名"的原料在这；旧口径容易翻出来当新口径用 |
| **C** | 业务规格 / 需求 / 设计 | **本体四张表的主力**（对象/关系/动作/规则/状态机） | 本体的主产地 |
| **D** | 会话与会议记录（逐字稿/纪要） | 一手原话、语音转写错词、决策变更 | **把条目从 🟡 升到 🟢 的唯一途径** |

**为什么这四路可以并行**：**数据源无交集 + 全部只读** → 无依赖。
只要出现"A 路要读 B 路的产出"这类依赖，就**不能并行**，改串行。

**并行的代价**：四路输出风格必然有差异 → 靠下节**输出契约**把格式钉死，合成时才能机械并表。

**提示词模板**：`templates/四路抽取提示词.md`——共同前导 + 四路各自的范围与额外产出，替换占位符即可复用。

> 💡 **四路同时发起**（一条消息里并行），不要排队。四路都回来后进阶段 2。

---

### 阶段 2：合成（**串行收敛**）

四路输出并过来之后，**先跑一次机械合并**，再做人工收敛：

```bash
# 并表 + 冲突检测（退出码 1 = 检出冲突，必须人来裁决；2 = 契约格式不对）
bash scripts/merge-terms.sh <A路结果> <B路结果> <C路结果> <D路结果> --out <合并结果文件>

# 画图（.mmd → .svg；找不到渲染器就报错退出，不静默跳过）
bash scripts/render-diagrams.sh <图源码目录>
```

`merge-terms.sh` 按**表头名**找列（不按列序），所以四路结果列序可以不同，**但表头名必须一致**。

然后**按顺序**做五件事：

| # | 动作 | 判据 |
|:--:|------|------|
| 1 | **去重** | 同一概念多条 → 留**置信度最高、出处最硬**的那条，其余出处并入同一条（多出处 = 更可信，不是冗余） |
| 2 | **冲突显性化** | 两份材料说法不一 → **两条都留**，进「冲突与存疑」表，标 `[待确认]` + 待谁核。**不静默择一** |
| 3 | **分层归位** | 项目级的进主文档；只有某一域才管得着的进分册；离线环境需要的做成镜像。**一个概念一处定义** |
| 4 | **标置信度** | 每条按 🟢/🟡/🔴 标；**宁低勿高**；一行可拆两标（如「🟢（关系）／🔴（存储形态）」） |
| 5 | **画图** | 对象关系画 Mermaid ER；状态机画流转图。**渲染成 SVG 放正文，源码留 `<details>` 折叠块**——改图靠源码，图与表必须能互相对上 |

**合成时的三条硬纪律**：

- **定义要能独立读懂**——禁写「见 XX 文档」「同上」
- **出处必填**——写不出 `文件:行` / `文件 §节` 的条目，退回 🔴 或直接删
- **表头写死口径**——置信度含义写在表头附近，读者不用翻到最后一节才知道 🟢 是什么

---

### 阶段 3：落地（**串行**）

| # | 动作 | 做法 |
|:--:|------|------|
| 1 | **写入主文档** | 原地升级，**文件名不变**（引用面已在阶段 0 量过） |
| 2 | **分册改造** | 分册顶部声明「项目级词条以主文档为准」；分册内容与主文档**不重叠** |
| 3 | **同步镜像** | 镜像从主文档**单向同步**，不手工维护 |
| 4 | **复扫影响面** | 新增了禁止别名 → `bash scripts/scan-refs.sh <术语文档> <仓库根> "<旧写法>"` → **退出码 0（零命中）才算完成** |
| 5 | **更新变更记录** | 项目文档仓的 CHANGELOG / 版本历史表追加一行（写清**改了什么 + WHY**） |

**收尾判据（铁律）**：

> 不是「我觉得改完了」，是「**我 grep 过，确认零残留**」。

## 本体的四张表

> **完整字段定义 + 填写示例 + 写法纪律**：`templates/本体数据模型.md`。下面是速查。

| 表 | 回答的问题 | 关键字段 | 最容易被写废的地方 |
|----|-----------|---------|------------------|
| **对象类型** | 世界里有什么 | 对象 / 中文 / 定义 / 关键属性 / 数据载体 / 置信度 / 出处 | 收了全量字段而不是**关键属性**；没写出"它其实不是实体表，只是某字段" |
| **关系** | 它们怎么连 | 源 / 关系（**动词短语**）/ 目标 / **基数** / 说明 / 置信度 / 出处 | 关系名写成「关联」这类空词；没标注**快照 / 覆盖写入**这类反常语义 |
| **动作** | 谁能对它做什么 | 动作 / **主体（角色）** / 作用对象 / 前置 → 后置 / 置信度 / 出处 | 主体不写（不知道谁有权限）；后置效果写「操作成功」而不是系统变成什么样 |
| **业务规则** | 什么不能做 | 编号（**优先复用既有错误码**）/ 规则 / 触发场景 / **违反后果** / 置信度 / 出处 | 自造编号体系；没写违反后果 |

**加两张附加图**：

- **状态机**（有状态的对象才写）——状态名 + 流转条件 + 每个状态下的可写范围；枚举是否穷尽要**显式表态**
- **对象关系图**（Mermaid ER）——图与表必须能互相对上，对不上就是有一处错了

> **四张表缺任何一张，都会退回成词表。** 关系表和动作表是本体与词表最大的差别——它们回答「谁连着谁」「谁能对它做什么」。

## 置信度分级

| 标记 | 含义 | 判据 | 能对外说吗 |
|:--:|------|------|:--:|
| 🟢 | 已实测 / 客户原话 | 有可指认的一手来源（逐字稿行、原系统页面、命令输出） | ✅ 可以 |
| 🟡 | 文档佐证 | Spec / 纪要 / 设计文档有明确记载，但未实证 | ⚠️ 需复核 |
| 🔴 | 仅推断 | 从命名或上下文推测，无直接来源 | ❌ 不可 |

**执行规则**：

1. **宁低勿高**——拿不准就降一级。**"都标 🟢"是这类文档最常见的死法**——降级是诚实，不是示弱。
2. **一行可拆两标**——「🟢（关系存在）／🔴（存储形态）」比硬凑一个级别有用得多。
3. **可升级**——实证后改级别，并在版本历史留痕（写明升级依据）。
4. **🔴 隔离**——对外版本生成时自动剥离；文档里凡 🔴 条目，写材料前先扫一遍。

**配套产出：存疑清单**（放文档末尾）——把「不知道」变成「待办」：

| 存疑点 | 为什么存疑 | 怎么核实 | 待谁 |
|--------|-----------|---------|------|

## 写作标准（与技能输出直接相关的 7 条）

| # | 标准 | 落地写法 |
|:--:|------|---------|
| 1 | **首屏给行动，不给介绍** | 标题后第一节 = **「怎么用」**（查词 / 写材料 / 改术语三个动作 + 按角色最少读法表），不是「这是什么」 |
| 2 | **先盘现状再给方案** | 用「有什么 / 缺什么」两列对照，让读者自己能核对；缺口是推出来的，不是断言出来的 |
| 3 | **1 就是 1，不用模糊措辞** | 写清**条件** + 写清**事实**。禁「较新版本需注意」式含糊；未实测就标"未实测"（标了边界仍是精确） |
| 4 | **给能用的，别堆论证** | 表格优先；定义一句话能独立读懂；不写「见 XX 文档」 |
| 5 | **可解释：每个判断能追溯来源** | 每条带出处（`文件:行` / `§节`）；没有出处的标 🔴 |
| 6 | **可读：结构自解释** | 表头写死口径（如「🟢=客户原话或实测」），读者看表头就知道这是什么，不用读正文猜 |
| 7 | **内外分层** | 内部理解 ≠ 对客内容；🔴 条目对外版本自动剥离；**许可类词条写具体协议名**（`Apache 2.0` / `GPLv2+CE` / `专有订阅`），**不写「免费」**——「免费」会被读成「有门槛的免费版」 |

> **自检一句**：**另一个 AI 读完这份文档，能照着往下做吗？** 能 → 合格。

## 输出契约（抽取 Agent 必须遵守）

**每路 Agent 按下面的格式返回，四路格式一致，主线程才能机械并表。**

```markdown
## {分区名}
| 术语 | 英文/别名 | 定义 | 出处 | 置信度 |

## 冲突与存疑
| 项 | 冲突内容（含各方出处） | 建议处置 |
```

> **表头名是硬约定**——`merge-terms.sh` 按表头名找列（`术语` / `定义` 必填，`英文/别名` / `出处` / `置信度` 选填）。
> 表头名换了，那一列会被静默忽略。**列序随意，表头名不能变。**

**硬要求**：

| # | 要求 | 为什么 |
|:--:|------|--------|
| 1 | **出处必填**（`文件:行` 或 `文件 §节`） | 没有出处的条目无法验证，等同于编 |
| 2 | **置信度必填** | 合成时要按级别排序、按级别剥离 |
| 3 | **冲突项单独列，不静默合并** | 静默择一 = 把冲突藏起来，下次还会踩 |
| 4 | **定义能独立读懂**（禁「见 XX 文档」） | 否则并表后指向失效 |
| 5 | **表头不改** | 主线程按表头并表；表名变了就静默丢数据 |
| 6 | **没有内容的表也要留表头** | 写「无」，不要整个删掉 |

---

## 四条红线

1. **动手前先 grep 存量** —— 已有词表就先收敛（原地升级 or 分层归位），**不造第二份**。
   多份并存 = 下次校验以谁为准的争论。**判据：我在查还是在猜？猜的一律标待核实。**
2. **冲突不静默择一** —— 两份材料口径不一，**显式标出待确认**（两条都留 + 各自出处 + 待谁核）。
   只有在能指认「以某份为准」的依据时才可以定，且必须写明依据。
3. **置信度宁低勿高** —— 拿不准就降级。**把推断当事实用，是对外出错的第一来源。**
4. **改完必须复扫** —— 不是「我觉得改完了」，是「**我 grep 过，确认零残留**」。
   新增了禁止别名 → 全仓 grep 旧写法 → 输出为空才算完成。

**另加两条**：

- ❌ **真实项目数据不进技能包** —— 本技能包公网可达；客户名、业务口径、人名一律留在项目仓
- ❌ **不猜** —— 没有来源的条目标 `[待确认]`，一个字都不编

## 交付前自检清单

| # | 检查项 | 怎么验 |
|:--:|--------|--------|
| 1 | 动手前 grep 过存量词表吗？ | 阶段 0 的输出里有「存量载体清单」 |
| 2 | 引用面量过吗？ | `bash scripts/scan-refs.sh <术语文档> <仓库根>` 有输出清单 |
| 3 | 文件名改了吗？ | 引用面大时**没改**；改了则所有引用点已同步 |
| 4 | 每条都有出处吗？ | 抽 10 条，逐条能指认到 `文件:行` 或 `§节` |
| 5 | 每条都有置信度吗？ | 没有空值；🔴 条目没有被写成 🟢 |
| 6 | 冲突单列了吗？ | 有「冲突与存疑」表；没有静默择一的痕迹 |
| 7 | 一个概念一处定义吗？ | 主文档与分册 grep 交叉比对，无重复词条 |
| 8 | 首屏是「怎么用」吗？ | 标题后第一节 = 三个动作 + 按角色读法表 |
| 9 | 图与表对得上吗？ | 图里的关系表里都有；表里的关系图里画得下 |
| 10 | 复扫零残留吗？ | `bash scripts/scan-refs.sh <术语文档> <仓库根> "<旧写法>"` → 退出码 0 |
| 11 | 变更留痕了吗？ | 版本历史/CHANGELOG 有新行，写清**改了什么 + WHY** |
| 12 | 对外版本剥离 🔴 了吗？ | 对外材料生成时单独过一遍 🔴 清单 |

## 排错

| 现象 | 真原因 | 怎么办 |
|------|--------|--------|
| 四路结果并不到一起 | 某路没按输出契约返回（改了表头 / 漏了置信度） | 退回该路重跑，附上契约格式；**不要手工适配**——手工适配一次，下次还会错 |
| 文档越写越长没人读 | 单文件超载，深水区内容堆进主文档 | 下放分册；主文档只留项目级 + 索引 |
| 同一概念还是两处有定义 | 分层时没做交叉 grep | grep 词条名，主文档与分册各留一处，另一处改指针 |
| 置信度全是 🟢 | 没有分级判据写在文档内 | 把判据表写进文档；合成时按"宁低勿高"重标一遍 |
| 改完还是有人看到旧叫法 | 只改了"产出类"文件，或镜像没同步 | 同步镜像 + 别名表补进旧写法 + 全仓复扫 |
| 用户说"这两份不一样，用哪个" | 两份都还没闭环 | **不要替他选**——出冲突清单（各自出处 + 影响面），让他定 |
| 增量加了个词，发现全仓十几处旧写法 | 之前没建禁止别名表 | 这次一并把旧写法补进 §六，再跑一次复扫（这正是追踪用法的价值） |
