# talkinghead-trim · 实拍口播精剪

实拍口播（talking head）的 A-Roll 精剪流程，四个环节写死、不许跳步。
源自一次真实实例：DJI 原片 6 分 45 秒 → 2 分 40 秒（全流程见 `references/试跑记录_6分45秒实例.md`）。

## 何时用

- 用户给一段实拍口播原片，说「剪一下」「精剪」「删口误」
- 用户说「A-Roll 先出」
- 复盘某次剪辑：当时为什么删这一刀

## 不适用

- AI 生成视频（走 AI 生成线，不管这个 skill）
- A-Roll 之后的包装（字幕 / 特效 / 转场）——那是人工确认门之后的事

## 四个环节（顺序写死）

### 环节一 · 转写

| | |
|---|---|
| 输入 | 原片视频（或其音频轨） |
| 输出 | 带时间轴的转写文本：每句带起止时间，静音段单独标出 |
| 工具建议 | faster-whisper（small 或以上）；云端 whisper+ffmpeg 链路已验证可用 |

判定规则：

1. 时间轴精度到 0.5 秒以内；
2. 转写完成前，不做任何"删 / 留"判断；
3. 口误、重复、卡壳在转写里原样保留，不提前清洗。

### 环节二 · 剪辑决策表

| | |
|---|---|
| 输入 | 环节一的转写文本 |
| 输出 | 剪辑决策表（模板见 `references/剪辑决策表模板.md`）：一行一条，含起止时间 / 原文本摘要 / 类型 / 处置 / 理由 |

判定规则：

1. 可删的只有四类：口误重录、重复起句、卡壳、长停顿；
2. 信息句、重点句、转折句一律保留——拿不准就标"待定"，不擅自删；
3. 处置只有三态：删 / 留 / 待定；"待定"必须进人工确认门；
4. 时长目标：成片压到原片的 35%–45%（实例为 39.5%）；超了就回头找重复信息句，不要动刀砍观点。

### 环节三 · 无损剪

| | |
|---|---|
| 输入 | 决策表 + 原片 |
| 输出 | A-Roll 初版 + 切点清单（EDL：每刀的起止时间与处置依据） |

判定规则：

1. 不动原片：用 EDL + ffmpeg 无损切，原片只读；
2. 全局 1.1 倍速；
3. 重点句 5% punch-in（画面轻微推近，强调但不断节奏）；
4. 每个切点做音频交叉淡化，杜绝爆音和断句；
5. 这一环节只出 A-Roll：不加字幕、不调色、不做转场——包装是确认门之后的事。

### 环节四 · 人工确认门

| | |
|---|---|
| 输入 | A-Roll 初版 + 决策表 |
| 输出 | 确认通过 / 打回清单（哪几刀有问题、怎么改） |

判定规则：

1. 强制暂停：A-Roll 完成后必须停下来等人看，不自动进入包装、不自动导出；
2. 任何不可逆删减（删整段观点、删唯一信源句）必须人点头；
3. 打回项回填决策表，重跑环节三；
4. 通过后才允许包装（字幕 / 转场 / 特效）；
5. 完成后通知用户（实例中走飞书通知）。

## 边界（红线）

1. **云端只复刻决策逻辑，不操作 ChatCut 插件**——ChatCut 是 Mac 端 Codex App 的插件（应用内完整 NLE，与 AI 助手对话协作剪辑），云端没有 Codex App，打不开它。实拍精剪在 Mac 端做。
2. **不可逆删减必须过人工确认门**——没有"看着像废话就删"的自由裁量。
3. **不自动导出、不自动发布**——终点是"待确认的 A-Roll"，导出和发布由人按键。
4. **纯文本 skill**——视频二进制不上仓库，只进资源库。
5. 分工：Mac 端 ChatCut 负责实拍精剪；云端负责 AI 生成线。两边同一标准：先 A-Roll、强制暂停待审。
