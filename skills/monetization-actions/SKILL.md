# 变现推进动作（monetization-actions）

> **适用范围守卫**：专为「行途技术」知识付费产品（面包多预售 / 小册 / 自查卡）设计。当前工作区不含 `outputs/运营台账/` 与面包多相关凭证时，声明不适用并停止。
> 本 skill 管**怎么收钱**，不管**发什么**：

| 要做的事 | 走哪 |
|---|---|
| 今天/明天发什么稿、封面什么底色 | `mp-daily-ops-report`（晨间决策） |
| 本周变现推进哪一步具体动作 | **本 skill**（每周一晨间决策时被路由调用） |
| 变现周提醒（盘点类） | 已有 cron 任务，本 skill 不重复 |

## 一、为什么要有这个 skill

**40 天空转实证**（10-25 CHANGELOG 02:08）：知识付费周提醒 cron 挂了 40 天，每周一跳"该推进变现了"的提醒，但**从来没有具体动作清单**——boss 看到提醒想"这周忙完再说"，下一周又看到同样提醒。40 天下来：
- 面包多预售页没改一次；
- 转化表没实填一次；
- 定价没 A/B 过一次。

**病根**：提醒 ≠ 行动。周提醒是"盘点"，本 skill 是"推动一件 5 分钟能完成的具体动作"。

## 二、核心定位

> **不是盘点（周提醒已做），是每周推动一件 boss 5 分钟能完成的具体动作。**

每周一晨间决策时，`mp-daily-ops-report` 路由到本 skill，从动作池里**挑 1 个**（不多挑），生成一条动作指令推给 boss：

```
本周变现动作（5 分钟可完成）：
动作：<从动作池选 1 个>
具体步骤：<3 步以内>
完成凭证：<截图/填表链接/CHANGELOG 行>
```

## 三、动作池（5 类，按周轮换）

| 动作 | 5 分钟步骤 | 完成凭证 |
|---|---|---|
| **A. 面包多预售页状态检查** | ①登录面包多后台 ②截图预售页当前转化率 ③对照上周 Δ | 截图 + CHANGELOG 一行 |
| **B. 关键词配置对齐** | ①查面包多后台 SEO 关键词 ②对比正文最近 3 篇长尾词 ③改 1~2 个错位词 | 后台截图 |
| **C. 转化表实填或冻结** | ①打开 `outputs/运营台账/转化表.xlsx` ②把本周真实数据填上（哪怕 0）③若连续 2 周 0 → 冻结该动作并记录原因 | 表格 mtime 更新 |
| **D. 读者付费意愿私信回访** | ①翻最近 7 天评论区高赞提问 ②挑 2~3 个最认真提问的读者私信"要不要看下预售" ③记录回复率 | 私信截图（脱敏） |
| **E. 定价 A/B 微调** | ①若预售页浏览 >50 但转化率 <2% ②把价格下调一档（如 99→79）观察 1 周 ③下周复盘 | 后台价格截图 |

**轮换规则**：按 A→B→C→D→E→A 循环，每周一推下一个。**不重复推同一个动作**直到 5 轮走完。

## 四、节奏

```
每周一 09:30
  ↓
mp-daily-ops-report 晨间决策
  ↓
四块简报里 ④待拍板区块追加一条："本周变现动作 = <X>"
  ↓
boss 5 分钟做完 → 截图回填
  ↓
下周一自动轮到下一个动作
```

**若 boss 本周没空做**：
- 记录"本周跳过"，下周一**不换动作**（继续推同一个，直到做完或冻结）。
- 连续 3 周跳过 → 触发 🟡 人工核：这个动作是不是物理不可行？要不要从动作池里删掉？

## 五、与 mp-daily-ops-report 的分工

| 维度 | mp-daily-ops-report | monetization-actions（本 skill） |
|---|---|---|
| 管什么 | 发什么稿、封面底色、群推动作 | 怎么收钱、本周变现推一步 |
| 频率 | 每天 09:30 | 每周一（被晨间决策路由） |
| 输出 | 四块简报（含 ①~④） | 一条 5 分钟动作指令 |
| 数据 | 阅读/分享/粉丝 | 预售页转化率/付费读者数 |

**边界**：本 skill **不做盘点**（"本周卖了多少"是周提醒 cron 的活），**只推动作**。

## 六、反面教材（40 天空转）

10-25 02:08 CHANGELOG 记录的空转根因：
- 周提醒文案只有"该推进变现了"一句话，**没有具体动作**；
- boss 看到提醒想"等这周忙完"，下周又看到同样提醒；
- 40 天下来面包多后台**没登录过一次**。

**本 skill 的反空转设计**：
1. 每周动作**具体到 3 步以内**（不说"优化预售页"，说"改 1~2 个错位关键词"）；
2. 每个动作**5 分钟可完成**（超过 10 分钟的动作不进池）；
3. 完成凭证**机械可查**（截图/表格 mtime），不靠 boss 自述"做了"；
4. 连续 3 周跳过 → 触发人工核（动作池本身要修）。

## Pitfalls（实测坑）

- **把盘点当动作**："拉一下本周数据"是周提醒的活，不是本 skill 的活。本 skill 只推"改一下"的动作。
- **一次推多个动作**：boss 注意力稀缺，一次 5 分钟只能做一件事。多推 = 全不做。
- **动作太宏大**："重新设计预售页"=2 小时活，进不了池。必须 5 分钟。
- **不轮换**：连续推同一个动作 = 空转重启。按 A→E 轮换。
- **跳过不记录**：boss 说"这周没空"但不留痕 → 下周不知道是该换还是该继续。
- **碰定价太激进**：A/B 微调一次只动一档（99→79），不要从 199 直接砍到 49。

## Verification（成功凭证）

- 每周一晨间决策里 ④区块含 1 条具体变现动作（不是空说"该推进了"）；
- 动作 ≤5 分钟可完成、≤3 步；
- 完成凭证机械可查（截图/mtime/CHANGELOG 行）；
- 动作按 A→E 轮换，无连续 3 周重复；
- 已向 boss 明示：**本 skill 不替 boss 登录面包多后台**（无凭证），只生成指令；boss 操作完截图回填才算闭环。
