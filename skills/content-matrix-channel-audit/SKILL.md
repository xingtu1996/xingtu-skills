# 全渠道内容矩阵环境审计（content-matrix-channel-audit）

> 沉淀自 2026-09-16「全矩阵调度与变现闭环」会话的实战分析轮：boss 反复纠正「不要只看公众号、要多渠道、用资深内容运营视角把超杂环境理清」。该轮跑出的六段框架与固定数据源判据已验证有效，本技能将其变为可 verbatim 复跑的管线。首案实录见 `reference.md` §六。

## 适用前提（范围守卫，必读）

> **守卫规则**：本技能承载「行途」工作区专属数据源与运营口径。开工前先读工作区根 `AGENTS.md`，**含「行途」才继续**；否则声明不适用并停止——不把他项目的库存/渠道套用本框架，也避免行途个人 IP 口径渗入非本空间会话。

- **全程只读**：不改稿、不发布、不建草稿、不回填台账、不改配置。报告里的"建议动作"仅供 boss 拍板，战略级事项（IP 切割、变现开卖时点）绝不擅动。
- 角色预设照 `RULER.md`：资深全平台内容运营操盘手，有专业判断、有辨别力，结论敢下但每条带证据。
- 必备工具：`python3`（内联统计，snippet 在 `reference.md` §二）、`tools/changelog_append.py`（留痕）。
- 核心纪律一：**决策不脚本化**——脚本只聚合事实，六段判断由 agent 综合给出（不过度工程）。
- 核心纪律二：**完成判定查凭证**——渠道"在发"的硬证据 = 分发凭证文件计数，台账/日报里"已发"文字不作数。

## 六段工作流

### Step 1 素材时效现状（判据：腐坏在停滞不在到期）

统计 `cards[]` 各分布 + days_left<30/<7 计数。判据：**时效压力 = 快到期卡数 / 总卡数**，占比低则"腐坏焦虑"多为假信号；真瓶颈查三重停滞——① `platforms` 字段渠道覆盖缺口（对照 Step 2 渠道全集）② 囤稿包数 vs 日吞吐上限的比值 ③ ready 高分但 blocker=无配图的卡死数。详见 `reference.md` §三判据表。

### Step 2 全渠道矩阵盘点（本技能核心，禁只看公众号）

对 公众号/视频号/掘金/CSDN/知乎/小红书/抖音/X/GitHub（全集以数据源实测为准，不硬编码数量）逐渠道填三列：**受众-时效适配度**（该渠道吃不吃技术长文/时效敏感与否）、**真闭环凭证**（=分发凭证计数，0 即"躺着"，不认文字自述）、**归类**（主阵地 / 半闭环 / 躺着 / 该战略切割）。必查坑：**"多渠道"可能是伪命题——同一个人皮下藏着休眠的另一条 IP**（受众割裂、停更久），那是注意力分配问题不是渠道运营问题。

### Step 3 变现承接链路断点

读数据源 2 monetization + 4。断点归因二选一：**流量不足**（有商品没读者）vs **建品产能**（有读者没商品/正文），拿凭证区分（粉丝数、销售数、商品状态）。附风控撞标签史检查（日报 risk_flags / CHANGELOG），急推售卖有限流风险则明说。

### Step 4 结构性瓶颈 top3

从 Step 1-3 事实里挑至多 3 个**结构性**（重复出现、非单篇）瓶颈，每条一句话 + 证据数字，禁列 10 条凑数。

### Step 5 口径漂移检测（多 agent 后遗症，必做）

跨数据源找互相打架的口径：同名数字多源不一致（如粉丝数）、同一主题 spec 多份无 SSoT、渠道主次/变现载体新旧冲突。输出漂移清单并**只建议立 SSoT 指针，不擅自合并/删 spec**（删改归 boss 拍板 + 基建修复轮）。

### Step 6 操盘手主杠杆结论 + 落盘

① 一句话主杠杆：找出能同时撬动多段的单一杠杆（首案=分发凭证 0→1）。② 战略级问题以 **A/B 选择题**呈 boss（≤2 个，禁开放式），未拍板前按"更稳"侧假设写报告并标注。③ 可逆的标记建议（如"某渠道标计划中"）可写入报告建议区，但本技能不执行。④ 落盘三连：报告 → `CHANGELOG`（`--tool qwenwork` 或实际工具身份）→ `产出索引.md`。

## 交付格式

- 报告：`outputs/全渠道矩阵环境审计_YYYY-MM-DD.md`，六段结构 + 每段带证据数字与来源路径；篇幅 ≤1200 字正文，细节放附录。
- **完成判定凭证**：报告文件存在且 mtime=当天 + CHANGELOG 有本轮行 + 六段标题 grep 可数——三者齐才算完成，模型自述不作数。

## Pitfalls

- 只看公众号就下结论——本技能存在的首要理由就是防这条（boss 原话纠正过）。
- 把"快到期占比低"直接报成"无时效压力"而不查三重停滞——到期≠时效问题的全部。
- 拿台账/日报里"已发 XX"文字当闭环证据——只认分发凭证文件计数，且排除 `凭证_*` 脏前缀。
- 把休眠的另一条 IP 当"没运营好的渠道"——先判受众是否割裂，再谈运营。
- 发现口径漂移就动手改 spec/数字——本技能只读，立 SSoT 是指南不是动作。
- 统计脚本把判断也写了——脚本只聚合，六段结论必须 agent 综合给出。
- 复跑时抄上一轮报告——历史结论不作豁免，每轮重新核凭证（B-009/B-046 同源）。

## Verification

1. `ls` 报告文件存在、mtime=当天；`grep -c "^## "` ≥6 段标题齐全。
2. 每段至少 1 个带路径的证据引用（数据源编号或文件路径）。
3. `CHANGELOG.md` 顶部有本轮条目（`--tool` 正确）。
4. 抽查一个"躺着"渠道判定：对应分发凭证 glob 实跑计数确为 0。
