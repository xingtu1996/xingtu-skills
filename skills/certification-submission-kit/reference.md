# certification-submission-kit · 参考资料

本文件是 `SKILL.md` 的按需展开层。SKILL.md 保留流程骨架，本文件放**全量模板 / 禁词表 / 平台对照表**，避免 SKILL.md 超 300 行影响加载。

## 一、认证描述三段式模板

**结构**：`职业身份字段同词` + `主体泛化 + 头衔字面` + `职责范围 + 领域关键词`

```
<职业身份同词>，现任<行业类目泛化><头衔字面>，负责<职责大类>，工作覆盖<领域关键词 1>、<领域关键词 2>与<领域关键词 3>。
```

### 模板实例

**V0 保守极简**（不声明头衔 → 佐证负担最小，只需在职证明；放弃了头衔路径的材料匹配）
```
软件工程师，从事企业软件研发与 AI 工程化落地，负责大模型接入、Agent 编排与研发流程自动化相关工作。
```

**V2 推荐** ⭐（头衔可佐证 + 企业泛化不定位 + 领域关键词利于站内搜索与 AI 抓取）
```
软件工程师，现任某软件与信息技术服务企业技术主管，负责 AI 应用工程化与研发交付，工作覆盖大模型接入、Agent 编排与研发流程自动化。
```

**V1 含公司全称**（过审力度最高，代价见 SKILL.md Step 7 分支 B；仅在驳回理由为「无法核实主体」时启用）
```
软件工程师，现任〈公司全称〉技术主管，负责 AI 应用工程化与研发交付，工作覆盖大模型接入、Agent 编排与研发流程自动化建设。
```

**V3 定位加强**（加了内容承诺，风险：审核可能判「描述偏向自媒体创作、与软件工程师身份不匹配」→ 与所选职业身份打架）
```
V2 全文 + ；长期记录 AI 落地的可复现步骤与踩坑。
```

### 写法纪律（为什么这么写）

- **开头即职业身份同词**：与表单「职业身份」字段一致，满足「描述应匹配认证身份」🟩。
- **全程客观陈述**：无程度副词、无修饰词、无效果承诺。
- **行业类目泛化**：「某软件与信息技术服务企业」= 读者知道是企业技术管理者，反查不到具体主体。
- **领域关键词承担 GEO**：微信内搜索与 AI 问答可抠出这些实体词，与账号主线内容同频。
- **不写「分享/干货/博主/自媒体」**：那是兴趣认证口径，与职业认证身份冲突，且属主观修饰。
- **不写代表作名称**：一旦提及代表作即触发佐证要求 🟩，徒增审核面。

### 判定规则

1. **找不到材料字面对应的 claim → 直接删**（B-009 不编造同源）。
2. **材料字面与 claim 用词不一致 → 改 claim 跟材料**，不改材料跟 claim（材料是客观凭证）。
3. **claim 触发额外佐证要求的**（例如提及代表作、具体项目名、精确年限）→ 评估是否值得增加审核面，多数情况删掉更稳。
4. **可选加分材料**（加盖公章的在职证明）提前准备，驳回分支 A 直接可用，不临时找。

## 四、驳回两分支预案模板

### 分支 A：驳回理由含「职位/身份证明材料不足」

**触发**：审核认为头衔字面与材料不匹配，或材料不足以佐证具体职位。

**处置**：
1. 补一份**加盖公章、写明头衔字面**的在职证明（例如「兹证明 XXX 同志现任我司技术主管职务」）。
2. 描述保持 V2 不改，材料追加在职证明重提。
3. 仍不通 → 退到 V0 保守版（不声明头衔，只靠在职证明与个税记录佐证职业身份）。
4. 额度消耗 2 次仍可接受（年度 3 次 🟨）。

### 分支 B：驳回理由含「描述信息不完整、无法核实主体」

**触发**：审核认为「某软件与信息技术服务企业」过于泛化，无法核实主体真实性。

**处置**：
1. 启用 V1（把「某软件与信息技术服务企业」替换为公司全称）。
2. 材料不变（身份证 + 名片 + 企业详情页 + 个税记录）。
3. 此时已拿到明确驳回理由，不算盲赌——V1 过审力度最高。
4. 额度消耗 2 次，仍可接受。

### 不盲重试原则

- 被驳回后**必须先看理由原文**，按分支走。
- 同一版描述连续提交 ≥ 2 次 → 停下找原因，不烧额度。
- 驳回理由不在两分支覆盖范围 → 回 Step 2 重新核实平台规则，可能踩了未预料的红线。

### 关键真相

1. **公众号 ≠ 视频号 ≠ 名人认证**：三套独立体系，不互认 🟨。视频号将来单独申请，材料可复用。
2. **职业认证 vs 兴趣认证**：职业认证不看粉丝数，兴趣/自媒体类认证普遍要 ≥500 粉 🟨。阶段 0-1（粉丝 < 500）唯一做得动的是职业认证。
3. **CSDN 公司名真相**：认证标不含公司名；但公司全名可能在**主页「工作信息」栏**（自填字段，独立于认证）。撤销不用动认证，进个人中心编辑资料清空即可。
4. **大 V 前台实名展示**：2023-10 平台公告 🟨，粉丝超 50 万的自媒体账号分批次引导前台展示真实姓名。**长期红线观察项**，与 SAF-010 正面冲突，号到 50 万粉那天单独决策，与现在提交无关。
5. **审核联系渠道**：个人认证是材料审核制，全程唯一主动联系渠道是申请人自留的联系电话/邮箱（= boss 本人）；平台流程里没有回访雇主、致电公司的环节 🟨（文档未见该机制；给不出「绝对不 call」的保证，残余风险仅限「打给你本人」）。
6. **认证行为本身不新增「做自媒体」的暴露面**：描述纯职务、材料只证明任职关系与企业存在——雇主侧拿不到这次提交的任何信息。真实暴露面是公开内容本身（按号名可搜到），独立于认不认证而存在，归 SAF 脱敏体系管。

## 七、素材标注用语库

写方案/填写表时用统一术语，避免歧义：

| 用语 | 含义 |
|---|---|
| **公开面** | 认证标、公众称谓、职业身份、认证描述等审核通过后展示在主页/关于页的字段 |
| **举证面** | 上传给平台审核的身份证、名片、企业页、纳税记录等材料，审核私有 |
| **头衔字面** | 钉钉名片/在职证明上印的职位原文（例如「技术主管」），描述必须逐字跟 |
| **可反推三元组** | 行业类目 + 精确注册资本 + 管理职位，三项同时命中可定位到自然人 |
| **公众称谓** | 平台表单字段名，与「主体姓名（= 真名）」对立，必须选此项 |
| **唯一文本位** | 描述全文只出现在填写表 §二，方案引用不复制，防双副本腐烂 |
| **额度** | 一个自然年内可修改认证身份/名称的次数（公众号 3 次 🟨） |
| **分支 A / 分支 B** | 驳回两分支预案，见 §四 |
