# 平台认证提交包生成流水线（certification-submission-kit）

## 适用前提（范围守卫，必读）

> **守卫规则**：本技能专为「行途」工作区的脱敏红线（SAF-004/005/010/013）、变现策略与多平台分发台账设计。开工前先读工作区根 `AGENTS.md`，**含「行途」才继续**；否则声明不适用并停止——不套用本流程操作其他项目的认证提交，避免个人雇主信息、真名红线口径渗入非本空间会话。

- 必备工具（相对工作区根路径）：`tools/privacy_scan.py`、`tools/changelog_append.py`、`tools/skill_ledger.py`。
- 必备本技能脚本：`.agents/skills/certification-submission-kit/tools/cert_desc_scan.py`（字数 + 禁词 + 硬命中扫描）。
- 必备规则底座：`SAF-004`（脱敏三查）、`SAF-005`（雇主信息模糊化）、`SAF-010`（真名红线 🔴 致命）、`SAF-013`（可反推三元组）、`BUL-001`（关键决策留痕）、`BUL-003`（数字标注来源+验证程度）、`PUB-004`（差异化分发/平台独立体系）、`STR-010`（基建修复回写 CHANGELOG）。
- 必备既有资产：`outputs/发布包_*/多平台分发/认证盘点与推荐_*.md`（历史盘点）、`outputs/发布包_*/多平台分发/变现策略_个人IP_*.md`（IP 定位口径）、`outputs/发布包_*/多平台分发/00_账号就位确认清单.md`（各平台账号状态）。
- 核心原则：**完成判定查凭证，不问模型自述**（B-009 / B-046 同源）——每一步以「命令输出 / 落盘文件 / 材料字面比对」收口。

## 与其他技能的边界（互补，不重叠）

| 阶段 | 归属技能 |
|---|---|
| 认证提交包生成、认证描述纪律、材料映射、驳回预案 | **本技能** |
| 各平台账号品牌化（昵称/简介/头像统一） | 直接走多平台分发 SOP，不属本技能 |
| 多平台内容差异化分发（PUB-004） | `xingtu-multiplatform-distribution` |
| 公众号发文前核验、嵌图 N/N、建稿回查 | `mp-prepublish-draft-verify` |
| 全工作区脱敏红线扫描（提交前跑） | `tools/privacy_scan.py`（本技能引用，不重写） |

**交接点**：本技能 Step 8 结束时，认证提交包两层文档已落盘、台账三处已回写；提交动作由 boss 手机端执行，回执截图落到 `凭证_<平台>认证_YYYY-MM-DD/`，本技能不代跑提交。

## 触发场景

- boss 说「帮我做公众号/知乎/掘金/百家号/CSDN/视频号/小红书认证」「认证描述怎么写」「认证材料要哪些」「认证被驳回了怎么办」「认证额度还剩几次」「主体姓名 vs 公众称谓怎么选」「认证会不会暴露公司/真名」。
- 主动巡检：多平台分发流水线铺到新平台时，检查该平台是否有未做的个人/职业认证。

## 认证描述四条铁律（客观纪律，红线级）

1. **公开面泛化、举证面精确**：认证描述、公众称谓、职业身份是**公开展示位**（平台明文：审核通过后展示在主页/关于页，被站内搜索与 AI 抓取收录）；公司全称、注册资本、真名、城市/园区、精确职务年限**只出现在上传材料里**（审核私有面）。混淆 = SAF-010 🔴 致命红线。
2. **无修饰词、无效果承诺**：禁「资深/知名/一线/顶级/权威/领先/专家/优质/顶尖/最/第一/国家级/保证」等（广告法禁词 + 平台禁修饰词，全表见 `reference.md`）。全程客观陈述句，不带程度副词。
3. **头衔与佐证材料逐字一致**：钉钉名片/在职证明/个税任职受雇页字面写「技术主管」，描述就写「技术主管」，不擅自升格为「技术负责人」；平台明文要求「涉及具体职位须上传材料佐证」，字面不一致是最高频驳回原因。
4. **认证描述 ≠ 账号简介**：简介承担营销口径（价值主张、可带钩子），描述承担**可核实的身份事实**。把简介搬进描述，最可能按「描述与身份不匹配」驳回。

## 8 步工作流

### Step 1：既有盘点回读（不裸开新单）

先查这三份历史资产，避免从零猜口径：
- `outputs/发布包_*/多平台分发/认证盘点与推荐_*.md` — 各平台认证路径、材料清单、名称卡点的既有盘点。
- `outputs/发布包_*/多平台分发/变现策略_个人IP_*.md` — IP 定位与变现阶梯，判断「公司名上号」的绑定代价。
- `outputs/发布包_*/多平台分发/00_账号就位确认清单.md` — 各平台账号昵称/简介/认证状态，确认全平台昵称一致性（= 公众称谓的佐证）。

同时 `memory_search` 查 boss 历史拍板（例如 CSDN 工作信息是否保留、公众号名是「行途」还是「行途 AI」等）。

**输出**：本次要做的平台 + 认证类型（职业/兴趣/企业）+ 已备材料清单 + 历史口径要点。

### Step 2：平台规则核实并分级标源

**不猜规则**，逐条核实。规则来源分级标注（BUL-003）：
- 🟩 **第一方**：官方帮助文档、认证表单页截图原文、平台公告。
- 🟨 **第三方实测**：知乎/经验帖/自媒体攻略，标发帖时间，注明「政策可能已更新，未官方复核」。
- ⚪ **待核**：本次未取到原文，明确写「待官方复核」，不作为决策唯一依据。

必查项：
- 认证类型与展示位（哪些字段公开、哪些审核私有）
- 认证描述字数上限（公众号 240 字，其他平台按各自规则）
- 材料清单与门槛（如「注册资本 500 万以上的技术负责人」这类硬门槛）
- 年度额度（公众号 3 次/年 🟨）与提交门槛（如 30 天内需有群发 🟨）
- 与其他认证体系是否互认（公众号 ≠ 视频号 ≠ 名人认证，独立体系 🟨）
- 常见驳回原因清单

**输出**：规则要点表，每条带来源分级标签。

### Step 3：公开面 vs 举证面切分

明确本次认证的**两类字段**：

| 类别 | 字段举例 | 处置 |
|---|---|---|
| **公开展示位** | 公众称谓、职业身份、认证描述、认证标 | 走脱敏三查（Step 6），泛化处理 |
| **审核私有材料** | 身份证、名片、企业详情页、纳税记录、在职证明 | 精确匹配平台要求，可含公司全称/注册资本 |
| **联系方式** | 手机号、邮箱 | 提交给平台不公开展示；邮箱**不用雇主邮箱** |

**关键提醒**：截图字段名可能是「个人称呼」但含义是「主体姓名（= 真名）」——**必须选「公众称谓」**，否则真名上主页 = SAF-010 🔴。

### Step 4：认证描述候选生成 + 脚本实测

写 3~4 版候选（V0 保守 / V1 含公司名 / V2 推荐 / V3 定位加强），模板见 `reference.md`「认证描述三段式模板」。

每版必须过 `cert_desc_scan.py` 实测：
```bash
python3 .agents/skills/certification-submission-kit/tools/cert_desc_scan.py "<描述文本>"
# 或从文件读：
python3 .agents/skills/certification-submission-kit/tools/cert_desc_scan.py --file /tmp/desc.txt
```

脚本检查（退出码非 0 阻断提交）：
- 字数是否超上限（默认 240，可 `--limit` 覆盖）
- 禁词命中（广告法禁词 + 平台禁修饰词全表）
- 硬命中报警：中文真名（（主理人）等）、英文名（行途 等）、公司全称标记（有限公司/股份/科技/集团）、注册资本数字、城市/园区名
- 头衔字面是否与 `--badge "技术主管"` 参数一致（名片头衔逐字校验）

**输出**：候选对照表（版本 / 文本 / 字数 / 禁词命中 / 适用判断），每版都跑过脚本。

### Step 5：claim → 材料映射表

描述里**每一句 claim** 必须找到对应佐证材料字面。模板见 `reference.md`。

| 描述中的 claim | 佐证材料 | 材料字面 | 状态 |
|---|---|---|---|
| 软件工程师（职业身份） | 个税「任职受雇信息」页 | 显示受雇于该企业 | ✅ 已备 |
| 现任…技术主管（具体职位） | 钉钉职业名片 | 名片原文 =「技术主管」 | ✅ 已核（字面一致） |
| 某软件与信息技术服务企业（主体性质） | BOSS 直聘企业详情页 | 注册资本 4000 万 + 高新资质 | ✅ 已备 |

**判定规则**：找不到材料字面对应的 claim 直接删；材料字面与 claim 用词不一致的（例如名片「技术主管」但 claim 写「技术负责人」）→ 改 claim 跟材料，**不改材料跟 claim**（材料是客观凭证）。

### Step 6：公开面脱敏三查（SAF-004/010）

跑工作区 `tools/privacy_scan.py --fail-fast`（全绿才允许提交）：
```bash
python3 tools/privacy_scan.py --fail-fast <(echo "<描述文本>")
```

三查清单（人工复核一遍，脚本兜底）：
1. **真名**：中文真名、英文名及全部变体、拼音全名 — 一律禁
2. **雇主公司全称**：有限公司/股份/科技/集团等后缀 — 禁上公开面
3. **可反推三元组**：行业类目 + 精确注册资本 + 管理职位 = 可定位到自然人 — 三元中**至少模糊一项**（推荐模糊注册资本，用「某软件与信息技术服务企业」代替公司名 + 不写注册资本数字）
4. **手机号邮箱**：手机号可用真实号（提交给平台，非公网展示）；邮箱**不用雇主邮箱**，用个人邮箱或选填留空

### Step 7：额度管理 + 驳回两分支预案

**额度提醒**：
- 一个自然年只有 N 次改认证机会（公众号 3 次/年 🟨，其他平台按 Step 2 查到的口径）。
- **公众称谓一次只试一个**：首选（例如「行途」，全平台昵称一致即佐证）→ 备选（例如「行途的工程笔记」）；不同时提交，被驳回再退。

**驳回两分支预案**（写进方案 §五，提交前就定好）：
- **分支 A：驳回理由含「职位/身份证明材料不足」** → 补一份加盖公章、写明头衔字面的在职证明重提；仍不通则退到「不声明头衔」的 V0 保守版，额度消耗 2 次仍可接受。
- **分支 B：驳回理由含「描述信息不完整、无法核实主体」** → 才启用 V1（含公司全称版），此时已拿到明确驳回理由，不算盲赌。

**不盲重试**：被驳回后必须先看理由原文，按分支走，不重复提交同一版。

### Step 8：两层文档落盘 + 台账三处回写

**两层文档**（防双副本腐烂，boss 09-16 明确要求）：

| 文档 | 内容 | 命名 |
|---|---|---|
| **方案** | 判断/取舍/风险/预案/规则来源分级/IP 与变现层面判断 | `<平台><认证类型>_提交方案_YYYY-MM-DD.md` |
| **填写表** | 表单逐项填法、描述唯一文本位、材料清单、提交前 30 秒自查、提交后回填 | `<平台>认证_填写表_YYYY-MM-DD.md` |

落盘位置：`outputs/发布包_YYYY-MM/多平台分发/`。

**关键约束**：方案与填写表**不互抄正文**——描述文本只出现在填写表 §二「唯一文本位」，方案里引用「见填写表 §二」；判断理由只出现在方案，填写表不解释为什么。

**台账三处回写**（缺一 = 变更未发生）：
1. `CHANGELOG.md` — `python3 tools/changelog_append.py --type "🆕" --path "outputs/发布包_YYYY-MM/多平台分发/<文件>.md" --desc "因为什么改了什么" --tool qwenwork`
2. `产出索引.md` — 新批次登记（多平台分发节）
3. `specs/*/…/台账.md` — 状态位更新，清过期项（例如「描述 A/B 待拍板」在拍板后立即改为「已定案：V2」）

**提交后**：审核结果截图 → `outputs/发布包_YYYY-MM/多平台分发/凭证_<平台>认证_YYYY-MM-DD/`，回填方案 §七 结果表（提交时间 / 描述版本 / 审核结果 / 驳回理由）。

## 常见坑（BCI 同源教训）

- **认账号坑**：认证详情页显示的账号名与台账口径不一致时（例如显示「行途 AI」但台账全用「行途」），**先核实不阻塞提交**（认证绑定账号主体而非名称），但要在填写表头部标「⚠️ 待核实」项，boss 后台核实后再统一修台账。**核实前不改名**——改名与认证审核并行 = 变量纠缠。
- **头衔升格坑**：名片写「技术主管」，描述擅自升级为「技术负责人」以匹配材料路径门槛 → 字面不一致必被驳回。**跟材料，不跟门槛**。
- **简介抄进描述坑**：把「一线 AI 工程化实践者 · FDE 方向 / 分享可抄作业的 AI 落地实战」这类营销口径搬进认证描述 → 「描述与身份不匹配」驳回。简介归简介，描述归描述。
- **一次多试名称坑**：公众称谓同时提交首选 + 备选 → 烧两次额度。**一次只试一个**。
- **公司名上号坑**：为「过审最稳」把公司全称写进描述 → 把「行途 = 某公司技术主管」交给平台背书，将来变现阶梯卖独立实践者判断力时最难解绑。**默认不上**，被驳回再按分支 B 补。
- **代跑提交坑**：模型自述「已提交」但实际没跑 — 提交动作归 boss 手机端，本技能只出提交包，**不代跑**（B-009 / B-046 同源）。
