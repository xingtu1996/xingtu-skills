# reference.md · Spec 驱动 × 对抗式审查工作流

> 按需直读：写红队任务书看 §1，建目录看 §2，留痕看 §3+附录A，拿不准红队力度看 §4，定稿放行后写执行委派简报/做磁盘验收看 §5。

## 1. 红队任务书模板（派发独立上下文子代理）

```
你是红队审查员，独立上下文，只攻击不处置。目标：证伪下面这份 spec 的设计。
待审文件：<specs/…/00_README.md、01_*.md、02_*.md 绝对路径>
工作区事实源：你必须有 Read/Grep/Glob/Bash(只读)，逐条实地核对，禁止凭 spec 自述采信。

按五类靶输出，每条给【结论：成立/不成立/存疑】+【证据：文件:行号 或 实测数字】+【影响】：
T1 引用证伪——spec 引用的每个 JSON 字段名、文件路径、行号，打开源文件核对是否真实存在、
   层级是否正确（如 distribution.external_ok_from vs distribution.packages[].external_ok_from）、
   数据覆盖度是否与"全体"假设相符（如仅 3 个对象有值却被当作全量可用）。
T2 单一信号绑架——打分/排序公式里某信号是否被双重放大，导致设计目标（如"去腐/长尾激活"）
   数学性沉底永远选不出？用真实数据代入举一个反例。
T3 平行系统——新提议的工具/引擎是否与既有脚本或模块职责重复？特别核对是否违背既有
   SKILL/README 写明的铁界（如"决策由 agent 产出、不追求脚本化"）。
T4 口径污染——同一事实是否存在多套统计口径（glob 前缀误计、CHANGELOG 文本 vs 文件存在性、
   新旧索引并存）？此前已推送给决策人的结论有没有基于脏口径？逐条点名纠正。
T5 副本腐烂——权重数值/流程判据/触发路由/定时任务 payload 是否散落在 ≥2 处且无主从声明？

要求：证伪不到就明说"该项核过成立"，不许为凑数编造问题；不许改任何文件。
输出 ≤600 字简报回主会话。
```

处置侧（Step 3）：红队"不成立"项也要写进 03（成立/不成立+理由），防选择性沉默。

## 2. Spec 四件套骨架

有 scaffold 引擎先跑引擎再裁剪填充（行途引擎见附录A）；无引擎手搓：

```
specs/YYYYMMDD-名称/
├── 00_README.md            总纲：一句话｜真问题(侦察后修正，覆盖口头假设)｜复用地图(表：关注点→既有资产路径)
│                           ｜缺口 N 条编号｜红线与坑(🔴硬约束/⚠️雷/✅边界)｜待拍板表(# | 决策 | 默认值)
├── 01_任务分解与依赖DAG.md  G0 地基(字段勘正/数据日刷) → G1 核心(可并行≤3) → G3 收敛(挂接+回收旧雷)
│                           每任务：编号｜内容｜依赖｜可独立验收判据（写"怎么算完"，不写"做了啥"）
└── 02_决策模型.md          字段级/公式级细节；引用 00 的复用地图不复制正文
（Step 3 追加）03_对抗式审查与修订.md  A 地基勘误表｜B/C/D… 必改①②③(证据+改法)｜F 单一SSoT表
```

00 顶部指针写法（红队修订后）：

```
> ⚠️ **以 `03_对抗式审查与修订.md` 为准**（冲突处推翻本文件）。红队已证伪：<一句列举>；修订见 03。
```

## 3. 收口留痕通用原则

- 探测本区时间轴/登记机制并用之；**完成判定 = 落盘凭证**（spec 文件存在 + 时间轴新行 + mtime=今天），模型自述"已完成"不作数。
- 汇报口径：三五行 recap（真问题修正 / 红队推翻清单 / 挂着哪几个待拍板默认值）。
- 行途空间的具体命令见附录A；其他空间无附录则写 `决议记录.md` 于 spec 目录内。

## 4. 首案实录（2026-09-16 · 行途空间，校准红队力度用）

任务：日报升级为"全矩阵调度+变现闭环"（`specs/20260916-运营日报升级_全矩阵调度与变现闭环/`）。

侦察修正：口头"要建综合研判引擎" → 实测素材库 1484 卡已有 `publish_priority/urgency/tier/platforms` 打分、既有简报脚本已产热点匹配与时序窗 → 真问题改判为"缺编排 + 分发凭证闭环=0 + 变现轨脱节"三个缺口。

红队战果（五类靶命中实例）：
- T1：字段引用层级写错且仅 3 对象有值被当全量 → 改引用路径并如实标注覆盖面。
- T2：新打分在已含时效信号的既有分上再叠同一信号 → 双重放大，长尾满分卡永输时效卡，"去腐"目标被公式锁死 → 拆单列榜、时效降级为提醒。
- T3：拟新建每日调度决策脚本，与既有两支脚本重复且违背上游技能"决策不脚本化"铁界 → 降级为"只喂数不决策"的 feed 脚本。
- T4：「分发凭证=0」结论被无关前缀的 `凭证_*` 目录污染误计，且脏结论已推送 → 唯一命名+显式排除 glob+单一判据（文件存在性），废止文本口径。
- T5：权重/判据/路由/payload 散在 3 处 → 03 末尾产出单一 SSoT 表 + 验收加一致性校验步。

教训固化：把"字段存在"写进 spec 前必须打开源文件核到行号；已推送的数值结论若被证伪基于脏口径，须在 03 点名纠正并同步决策人，不许悄悄改口。

## 5. 执行委派简报骨架与磁盘核对清单（Step 5 用）

**委派简报骨架**（发给后台执行子代理，四要件按序填充）：

```
你在 <工作目录绝对路径> 执行已定稿 spec 的 Phase <N>（Phase <1..N-1> 已完成并独立复核通过）。
先读该工作区根规则文件遵守其红线（下面也复述），再读 spec 目录，按其推进。

## 唯一真相源
<specs/…/ 目录路径>（00-05 + execution-log）。开工前先读 execution-log 尾部
（上一 Phase 实际做到哪、留了什么给本 Phase）与任务清单本 Phase 段，别重做已完成工作。

## 本 Phase 目标
<逐项列任务与验收判据，引用 spec 条目编号，不复制正文>

## 红线（复述，不依赖注入）
<改前备份 / 禁硬删 / 只读不发布 / 显式列文件禁 git add -A / 留痕走并发安全追加 / 每步写 execution-log>

## 辖区与排他
只可改动：<目录/文件清单>。另有并行任务在跑，勿碰：<对方辖区文件>。
<共享文件（如时间轴）> 只经 <带并发保护的追加脚本/命令> 写入。

## 完成定义（DoD，须自证不许虚报）
逐项 ls/grep/实跑 自证并把输出贴进 execution-log；没做完或需人审的列「尾巴项」上报，
不擅自扩大动作（越界只上报不动手）。完成判定以磁盘产物为准，自述不作数。
```

**主代理磁盘核对清单**（收到完成通知后，按此序，不读全量大日志）：

| 查什么 | 怎么查 | 防什么 |
|---|---|---|
| 产物真生成 | **实跑**交付的工具/脚本一次，核对输出与关键产物 mtime=当天 | 虚报"已实现" |
| 关键字段/勾选 | grep 任务清单 `[x]` 与产物 JSON/配置关键字段；勾选须与磁盘事实一致 | "做了没勾"/"勾了没做" |
| 镜像同源 | 多池/多副本 `diff -q` 验字节一致 | 双副本腐烂 |
| 行为门禁 | hook/validator 正反面例各实测一次（该拦的拦、该放的放），含大小写/变形绕过 | 守卫形同虚设 |
| 红线越界 | grep/ls 核查辖区外文件 mtime 未动、无未授权提交/发布 | 执行代理越界 |
| 诚实尾巴 | execution-log 尾部遗留项清单与分期计划一致 | 把"没做"混进"做完了" |

**校准次案（2026-09-16 · 三例同构管线）**：
- 日报升级 Phase1：主代理实跑喂数脚本产当日快照（json+md，mtime 当天）、grep 排除清单与榜首构成验去腐数学修复、核备份 tar 存在、确认脚本内零发布动作——全绿后才向决策人验收汇报。
- 日报升级 Phase2：brief 首段即要求"先读 execution-log 尾部，别重做 Phase1"，并复述红线与辖区。
- ctf 蒸馏：与 Phase1 并行，brief 显式划定"勿碰其正在改的 <config/规则文件>"、留痕走并发保护脚本；验收用 `diff -q` 验双池字节同源、grep 目标技能确认增强关键词、实测 hook 大小写绕过拦截。
- **键名坑**：验收探针猜键 `track_c` 落空，打印产物真实顶层键才知是 `track_c_decay`——核验落空先疑探针口径再下结论，别误判执行方没做。
- **自染产物**：验收动作本身会生成副作用文件（如 hook 测试日志），收口前清出交付目录，别算进执行方遗留。
