# 已发布文章入库闭环（published-article-archive）

> 定位：公众号发完之后的**闭环动作**。不回填 = 盲发（个人订阅号拿不到统计接口，唯一能指导下一次的就是人工回填的链接与数据）。
> 与 `xingtu-ingest`（素材入库，收外部内容进素材库）**不同**：本 skill 处理的是「自家已发布文章 → 回填台账 + 镜像开源仓」。
> 与 `publish-package-review`（发布前审校）**互补**：那个在发布前，这个在发布后。

## 触发条件

- boss 发来公众号后台「发表记录」截图 + 链接，说「入库 / 回填 / 归档」
- boss 只给标题，说「这篇发了，记一下」
- 定期盘点：对照后台发表记录补录漏记文章

---

## 核心流程（六步）

### Step 1 · 识别目标文章

从截图/链接确认：**标题 / 实际发布日期时间 / 阅读·分享·评论·收藏数据**。

⚠️ 截图上的标题可能是 OCR 或换行截断（如「没让我一行配置」实为「没让我**改**一行配置」）——**以本地发布包为准，不以截图为准**。

### Step 2 · 定位本地发布包（**不要靠 WebFetch 抓正文**）

🔴 **头号坑**：`WebFetch` 抓 `mp.weixin.qq.com/s/<短id>` **会抓错文章**（实测抓成了另一天发的另一篇）。公众号短链不可用于内容确认。

正确做法 —— 回本地找发布包：

```bash
# 1) 按标题关键词找发布包
ls ~/xingtu/outputs/发布包_2026-09/ | grep -iE "关键词|内部编号"
# 2) 按封面/配图文件名里的数字锚点找（最快）
find ~/xingtu/outputs -name "*306*" -o -name "*86.7*"
# 3) 读包内 00_标题摘要 / 01_正文 / 06_发布参考/发布操作单.md 核对
```

发布包标准结构（缺一不可）：

```
发布包_YYYY-MM/<内部编号>_<主题>/               ← 在制
发布包_YYYY-MM/_archive/已发布/<MMDD>_<主题>/    ← 发布后被归档任务移入并加日期前缀
  00_标题摘要/    ← 主选标题 + 摘要 + 合集 + 数字锚点
  01_正文/        ← 正文终版 md
  02_排版HTML/    ← md2wechat 渲染产物（实际粘贴版，镜像以此为准）
  03_封面/        ← 1800×766
  04_配图/
  05_合集/合集归属.md   ← 合集真名（PUB-044：必须比对台账）
  06_发布参考/发布操作单.md  ← 发布时间/合集/数据一致性锚点
  _archive/       ← 历史版本
```

🔴 **路径会失效**：发布包发布后会被归档任务移入 `_archive/已发布/` 并加 `MMDD_` 前缀。回填台账前先 `ls` 确认包还在不在原位，**不在就先 `find` 再用**（B16 入库时就是写完路径后 2 分钟被移走，导致台账里写了个失效路径）。
```

### Step 2.5 · 🔴 核对「发布微调」（本地终稿 ≠ 线上版本）

> boss 2026-09-14 明确：**发布到公众号时会做微调**，典型是**范围保守化**（精确数字改「约」、绝对断言加限定词、弱化免责口径）。本地终稿不是线上版。

**B16 实证（必看）**：

| 版本 | 数字表述 |
|---|---|
| 发布前精确备份（09-11） | `445 → 139 行` / `745 → 295` / `166 → 123 KB` |
| **排版 HTML（实际粘贴版，17:43）** | `445 → 139 行`（精确） |
| **本地 01_正文 md（次日 02:08 改）** | **`约 450 → 约 140 行` / `约 750 → 约 300` / `约 160 → 约 120 KB`** |

病根：**改了 md 没重渲染 HTML**，两者漂移，实际发出去的是旧的精确版。

**处理规范**：

1. **镜像取哪个版本** → 以 `02_排版HTML/`（实际粘贴版）为准，**不是** `01_正文/` 的 md
2. **差异必须标注** → 若 md 与 HTML 数字/口径不一致，镜像时按 HTML 走，并在台账「复盘」栏记一行漂移说明
3. **反查线上真值** → 需要确认线上实际措辞时，用 bsk 接管已登录浏览器读已发布文章；**WebFetch 抓短链会抓错文章，禁用**
4. **军规候选（建议在发布前审校环节拦截）**：**改正文 md 后必须重跑 md2wechat 重渲染 HTML**，发布前比对 md 与 HTML 的关键数字锚点是否一致

**发布微调的典型类型**（遇到新的就补进来）：

| 类型 | 表现 | 例 |
|---|---|---|
| 范围保守化 | 精确 → 模糊 | `445 行` → `约 450 行` |
| 断言弱化 | 绝对 → 限定 | `一定` → `通常` / `所有` → `多数` |
| 口径补注 | 补免责 | 加「第三方口径，非官方对比，数据截至发稿」 |
| 脱敏 | 去内部指向 | 「平台通知」→「API 平台升级公告」 |

### Step 3 · 回填三处台账

🔴 **路径坑**：台账真实路径是 `xingtu/**github/**xingtu-vault/...`，**不是** `xingtu/xingtu-vault/...`（主根下多一层 `github/`）。`00_入口.md` 里的相对链接缺这层，照抄会 File not found。

| # | 文件 | 改什么 |
|:--:|---|---|
| 1 | `github/xingtu-vault/03_运营工具箱 (Operations Toolkit)/00_全局发布日历_2026-09.md` | 对应日期行：状态改 `✅已发布` + 补链接/时间/合集/数据 |
| 2 | `github/xingtu-vault/09_个人台账/03_已发布文章档案/发布日志_2026-09.md` | 表格行补「链接」+「数据」+「复盘」 |
| 3 | `github/xingtu-vault/09_个人台账/03_已发布文章档案/已发布文章档案.md` | 顶部（倒序）新增 `### [N] 标题` 条目 |

**排期被替换时的处理原则**：若该日原排期是「顺延待定」的别篇，实际发了这篇 —— **新增一行（如 `#12b`）而非覆盖原行**，保留「原篇仍顺延」这条待办线索。覆盖 = 线索丢失。

**合集名铁律（PUB-044）**：引用前比对台账真名。已知错名映射：「技术人的复利」→「AI时代知识复利」；「国产大模型速评」→「技术闪记」。全空间有 100+ 文件在用后台不存在的名字。

### Step 4 · 镜像到开源仓 xingtu-articles

```
~/xingtu/github/xingtu-articles/
  articles/YYYY-MM-DD-<slug>.md   ← 命名格式，md 与配图平铺同目录
  README.md                        ← 按分类列表，articles 徽章计数 +1
```

镜像 md 结构（照抄最近一篇的格式）：

```yaml
---
title: <发布时的真实标题>
date: YYYY-MM-DD
tags: [关键词...]
original: https://mp.weixin.qq.com/s/<短id>
views: <阅读数，无则 ->
category: <AI工程化实战 / AI大模型观察 / 知识复利 / 省token实战 / 看懂AI Agent>
author: 行途
---
```

正文要求：配图占位 `【配图：xx.png】` → 改为 `![](配图N_描述.png)`；末尾加**引流页脚三件套**（公众号卡片占位 / 延伸阅读 / 「行途·排版引擎·©2026 行途·禁止未授权用于AI训练」）+ 搜一搜关键词行 + 数据来源与核验时间。

配图拷贝命名：`配图N_<内部编号>_<语义>.png`（与既有 `配图1_价格对比图解.png` 同风格）。

### Step 5 · 安全扫描（**公开仓必做**）

```bash
按脱敏词表跑隐私扫描（真名/拼音/英文名/雇主代号/客户名/wxid 等类别，工具：tools/privacy_scan.py）<待提交文件>
```

0 命中才能提交。xingtu-articles 是**公开仓**，SAF-010 红线：中文真名 / 英文名及变体 / 拼音全名 / 雇主信息 / 内部项目代号一律禁上公网。

同时自查「指纹组合」：跨度极大的连续职业履历细节自述、「在职身份未公开」类自述、内部成本数字——均按类别核查，不列举具体字样。

### Step 6 · 备份 → CHANGELOG → git 提交

1. **备份**：`bash ~/xingtu/tools/safety/backup-before-op.sh "<描述>" <路径...>`
2. **回写 CHANGELOG**（不回写 = 变更未发生）：
   ```bash
   cd ~/xingtu && python3 tools/changelog_append.py \
     --type "✏️" --path "<相对路径>" --desc "改了什么 + 为什么" --tool workbuddy
   ```
3. **git 提交**：
   - 🔴 **只 `git add` 本次改动的文件**，禁止 `git add -A`（仓内常有其他并行任务未完改动）
   - 身份：xingtu 品牌空间自动为 `行途 XingTu <274853659+xingtu1996@...>`（local 已钉死，勿动）
   - 镜像仓 commit 格式：`docs: 归档已发布《标题》(MM-DD HH:MM 原创首发，<分类>，配图N张入库，链接<短id前7位>)`
   - 🔴 **默认不 push**，提交后向 boss 报告 commit hash 并问是否推送

## 入库完成后的附加动作

- **顺带查相邻条目缺口**：回填时扫一眼发布日志前后 2-3 行，常能发现「已发但链接待回填」的漏记（如某篇截图可见已发但台账仍空）
- **数据归因写进复盘**：与同题材历史文章对比（如「同 DeepSeek 题材，9/9 速评 62 vs 本篇 2」），给出可证伪的归因假设 + 观察窗口（7d 看搜一搜补量）
- **72h / 7d 二次回填**：同一条目追加，不新开条目（BUL-003：拿不到就写「待回填」，绝不估读）
