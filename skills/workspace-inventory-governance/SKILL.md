# 工作空间盘点与治理（workspace-inventory-governance）

## 解决什么

一个开发者 / 内容团队的本地工作区里，git 仓库与非 git 资产分散在多处，平时靠记忆掌握：本地领先未推送、本地与远端分叉、未提交改动积压、无远程本地仓等漂移容易长期无人发现。

本技能把「**家底盘点 + 同步健康巡检 + 跨期对比 + 治理待办清单**」封装成可重复执行的只读管线：手动跑一次出一份盘点报告；也可挂每日 / 每周定时任务自动巡检，异常项进晨间决策简报。

**只读盘点层**：本技能只采集、只出报告与建议清单，**不执行**迁移、删除、推送、建草稿、发布等写动作；所有处置动作列清单交人工拍板。

|---|---|---|
| 仓库清单、提交数、最近提交、ahead / behind、未提交、无远程 | ✅ 本技能 | — |
| 非 git 资产目录规模台账 | ✅ 本技能 | — |

| 真名 / 身份泄漏、git 历史清洗、对外发布安全扫描 | ❌ | 转隐私 / 开源守卫类专用技能 |
| 单个交付包（发布包 / 制品包）组件齐全性体检 | ❌ | 转交付包健康检查技能 |
| 线上内容渠道矩阵、平台账号分发节奏 | ❌ | 转渠道矩阵审计技能 |
| 跨外部 AI 工具的技能安装量与版本漂移 | ❌ | 转工具带扫描技能 |
| 常驻配置层体量减法执行 | ❌ | 转配置治理技能 |

## 触发场景

- 用户说「盘点一下工作空间 / 仓库现状 / 家底 / 资产台账」
- 例行巡检：看哪些仓积压未推、有没有新分叉、未提交改动是否堆积
- 定时任务每日 / 每周自动跑（挂载方式见文末「定时任务衔接」）
- 新仓归类确认、归档遗留克隆排查、跨期资产规模趋势回看

## 执行流程

### Step 1 根路径确认

- 默认从脚本位置向上自动探测同时含 `github` 与 `rules` 的目录作为工作区根；布局不同时用 `--root <路径>` 显式指定。
- 确认仓库扫描根存在；不存在则如实报告「未发现 git 仓库目录」，不编造数据。

### Step 2 运行采集脚本

```bash
# 全量：JSON 台账 + Markdown 报告
python3 scripts/workspace_inventory.py

# 定时任务 / 机器消费：只写 JSON
python3 scripts/workspace_inventory.py --json-only

# 人读：只写 Markdown 报告
python3 scripts/workspace_inventory.py --md-only

# 指定工作区根 / 仓库扫描根
python3 scripts/workspace_inventory.py --root <工作区根> --repo-root <仓库目录>
```

采集口径（全部本机实测，零估算）：

- **仓库矩阵**：仓库扫描根下一级含 `.git` 的仓库，逐项采集远程地址、当前分支、提交总数、最近提交日期、ahead、behind、未提交改动数、是否无 origin。
- **非 git 资产**：默认统计 rules / workflows / tools / data / outputs / skills 等目录文件数；可在脚本 `DEFAULT_NON_GIT_DIRS` 按自身布局替换。
- **遗留克隆**：归档区根与内嵌第三方子克隆单列一节，不计入现役矩阵。
- **非 git 旁路目录**：仓库扫描根下一级存在但不含 `.git` 的目录（散落文档、空元数据目录等），如实列出名称与文件数，不纳入仓库矩阵。
- **健康分级**：
  - 🔴 分叉：ahead > 0 且 behind > 0
  - 🟠 本地领先未推送：ahead > 0
  - 🟡 有未提交改动
  - 🟡 无远程本地仓
  - 🟢 正常

> 主标签按优先级互斥；`dirty>0` 不被 ahead 标签吞掉，待办清单在 🟠 / 🔴 条目后另附未提交改动提示。

### Step 3 核对采集结果

- 报告仓数、提交总量与脚本 JSON 台账一致。
- 未命中业务分组的新仓自动归「未分组」，在报告中标注，交人工拍板后再固化分组。
- 数字异常（提交数骤降、日期倒挂）先复核 git 实测，不直接写进结论。

### Step 4 生成盘点报告

| 产物 | 默认路径 | 用途 |
|---|---|---|
| JSON 台账 | `data/workspace_inventory_YYYY-MM-DD.json` | 机器消费、跨期对比基线 |
| Markdown 报告 | `outputs/workspace_inventory_report_YYYY-MM-DD.md` | 人读：概览 / 跨期对比 / 仓库明细 / 资产规模 / 遗留克隆 / 旁路目录 / 治理待办 |

报告结构：盘点概览（仓数、提交总量、健康分布、旁路目录数）→ 跨期对比 → 仓库矩阵明细 → 非 git 资产规模 → 归档遗留克隆 → 非 git 旁路目录 → 治理待办清单。

### Step 5 跨期对比解读

- 脚本自动读取 `data/workspace_inventory_*.json` 最近一期做 diff：仓数变化、提交总量变化、新进入 ahead 清单、已推送清掉领先清单。
- 首期无历史基线时如实标注「首跑，无跨期对比」，不编造趋势。
- 异常漂移（单仓 ahead 突增、新出现分叉、未提交改动堆积）在报告「治理待办」区块置顶标注。

### Step 6 治理待办清单（只读建议，不代执行）

按健康等级输出建议：

- 🔴 分叉：先 `git fetch` 评估合并或变基，人工拍板后再操作。
- 🟠 本地领先未推送：核对内容后择机 `git push`。
- 🟡 未提交改动：确认进行中工作还是残留，择机提交或丢弃。
- 🟡 无远程本地仓：确认有意本地仓还是漏挂远程。

**红线**：脚本与技能均不执行 `git push`、目录迁移、文件删除；涉及删除走工作区安全删除流程，批量结构改动先备份。

### Step 7 留痕

- 手动全量盘点完成后，按工作区惯例在变更日志追加一条记录。
- 周度 / 月度例行盘点按需同步资产索引与目录文档。

## 定时任务衔接（未来演进，默认不接线）

技能本体交付、手动跑通后，是否挂每日 / 每周定时任务属调度动作，需负责人拍板后再落地。建议节奏：

| 节奏 | 时机 | 用途 | 产物 |
|---|---|---|---|
| 每日轻量 | 晨间决策前 | 看昨日是否有仓积压未推、新出现分叉、未提交改动堆积 | JSON 台账 + 终端摘要，异常进晨间简报 |
| 每周全量 | 周日晚 / 周一晨 | 全量盘点 + 跨期趋势 + 治理待办归档 | Markdown 报告 + JSON 台账 + 周报附录 |

定时运行红线：

1. **只读盘点**：不执行 `git push`、不迁移目录、不删除文件、不碰草稿箱与发布接口。
2. **处置待拍板**：报告建议只列清单；实际合并 / 变基 / 清理由负责人确认后执行。
3. **数字认磁盘凭证**：仓数、提交数、ahead / behind、未提交数全部来自本机 git 与文件系统实测，模型自述「已盘点」不作数。
4. **私有路径不外发**：台账与报告含本机绝对路径，只落本地 `data/` 与 `outputs/`；进入公开仓前先跑隐私扫描。
5. **跨期基线**：脚本自动读最近一期 JSON 做 diff；首期如实标注无对比基线，不编造趋势。

## 红线与坑位

1. **只读不动手**：不改仓库内容、不推送、不迁移、不删除、不碰草稿箱与发布接口；处置动作一律列清单交人工拍板。
2. **数字认磁盘凭证**：仓数、提交数、ahead / behind、未提交数全部来自本机 git 与文件系统实测，禁止估算编造。
3. **不越界**：隐私泄漏 / 历史清洗转专用守卫技能；交付包组件体检转专用检查技能；线上渠道审计转渠道审计技能；外部工具漂移转工具带扫描技能。
4. **新仓归类**：未命中业务分组归「未分组」，不擅自分组；拍板后再固化分组映射。
5. **跨期基线**：自动读最近一期 JSON 做 diff；首期如实标注无对比基线。
