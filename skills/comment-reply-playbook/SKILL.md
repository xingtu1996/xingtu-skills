# 评论区长期维护 SOP（comment-reply-playbook）

> **适用范围守卫**：专为「行途技术」公众号工作区设计。当前工作区不含 `outputs/发布包_*/` 与 `github/xingtu-vault/02_内容仓库 (Content Hub)/` 时（如公司侧仓），声明不适用并停止。
> 本 skill 只负责**发布后**评论区运营。三方分工不越界：

| 要做的事 | 走哪 |
|---|---|
| 发布那一刻生成群推话术 + 置顶评论三层文案 | `mp-group-push-copy`（产出物是本 skill 的起点） |
| 发布后 24h 内补勘误、7 天内回读者追问、抬杠应对 | **本 skill** |
| 发前事实回源、嵌图核验、建稿 | `mp-prepublish-draft-verify` |
| 发后铺多平台、图卡变体 | `xingtu-multiplatform-distribution` |

## 一、为什么要有这个 skill

10-23 RTK 稿评论区更正单独立文件（CHANGELOG 12:24）暴露出一个空档：**`mp-group-push-copy` 只管发布那一刻**（出话术+置顶文案），但发布后读者提问、数据勘误、抬杠、高频问题沉淀，从来没有 SOP。结果是：错数据挂在正文里没人改、读者追问石沉大海、好问题白白流失选题池。

本 skill 把这件事工程化：**发完不是终点，评论区才是第二轮内容生产现场**。

## 二、三层置顶评论维护（时间轴）

承接 `mp-group-push-copy` Step 5 的三层置顶结构（第 1 层反差钩 / 第 2 层 @AI 总结 / 第 3 层作者追评）。本 skill 管**之后**的演化：

| 时间窗 | 动作 | 落盘凭证 |
|---|---|---|
| 发前（mp-group-push-copy 已做） | 预设 1 主 2~3 备选置顶 | `06_发布参考/群推话术与置顶评论_<日期>.md` |
| 发后 0~24h | 观察回复流；若发现数据/事实错 → **24h 内置顶更正**（见第三节） | CHANGELOG 留痕 |
| 发后 24h~7d | 把第 1 层反差钩换成**长评论收口**（作者补一段正文没展开的判断 / 回应最高赞追问） | `06_发布参考/评论区维护_<日期>.md` |
| 发后 7d+ | 数据复盘后再补一条**衍生判断**（"一周回看：这个判断被打脸了吗？"），为下一篇攒素材 | 同上文件追加节 |

**铁律**：作者连占置顶位**不超过 2 条**。第 3 层之后不再自我置顶，让位给读者高赞留言。

## 三、数据口径勘误 SOP（24h 黄金窗）

发现正文/置顶里有数据错、产品名错、引用错时，按此流程：

1. **24h 内**：在评论区置顶一条更正（不修改已群发的正文——公众号群发后不可改，只能补勘误）。话术骨架：
   > "勘误：第 X 节里写的 <原错句> 应为 <正确句>。来源 <链接/数据出处>。感谢 <读者昵称> 指出。"
2. **正文补「勘误」段**：下一篇成稿或下次重渲时，在文末加一段「上篇勘误」。**已群发稿不回改**。
3. **CHANGELOG 留痕**：
   ```bash
   python3 tools/changelog_append.py --type "✏️" \
     --path "outputs/发布包_YYYY-MM/<包名>/" \
     --desc "评论区置顶勘误：<原错>→<正确>（读者 <昵称> 指出）" --tool doubao
   ```
4. **回写排期台账**：若该错误影响排期判断（如榜单名次错导致推荐结论错），同步回 `daily-judgment-brief` 的假设台账。

**不做的事**：不在评论区跟读者长篇辩论；不删读者批评（除非人身攻击/广告）；不把勘误藏进折叠区。

## 四、抬杠应对模板（三类）

boss 实测用词里"抬杠"只出现 3 次，但评论区三类对手是稳定的：

### 4.1 事实错误型（读者说错了数据）
**话术骨架**：
> "你这条数据对不上，我查了下 <来源>，应该是 <正确值>。可能咱俩看的是不同版本/时间点，欢迎把你的出处贴上来对一下。"

要点：不居高临下、给来源、邀请对质。**不要说"你错了"**——说"对不上"。

### 4.2 立场对立型（读者价值观跟你相反）
**话术骨架**：
> "这个判断确实有争议，我这篇是 <场景/前提> 下的一家之言。换个前提（<反例>）结论会不一样，欢迎展开聊。"

要点：不辩护、不说服、承认前提。**立场问题不争输赢**，公开辩经只会吸黑不吸粉。

### 4.3 无厘头型（灌水/广告/人身攻击）
**话术骨架**：不回复。**必要时点举报**，不在公开区跟人对骂。

**通用红线**：作者公开回复**单条 ≤ 3 行**；超过 3 行的争论转私信；不在评论区承诺效果（"用了保证涨粉"）。

## 五、读者问题沉淀成素材的回路

评论区是**免费的选题调研位**。每天（或每周晨间决策时）扫一遍最近 7 天高赞/高频问题：

1. 把同一类问题的回复数 ≥3 的留言，**摘抄到素材库**：
   ```
   素材库/选题卡/读者高频问_<主题>_<YYYY-MM-DD>.md
   ```
2. 卡片字段：原问题（摘录读者原话）/ 回复次数 / 我的初答 / **是否值得扩成一篇新稿**。
3. 一周汇总：进 `outputs/运营台账/选题池.md`，标注「来源=评论区」。
4. 闭环：下一篇成稿若命中此类问题，在正文/置顶评论里 @该读者（"上周有读者问 X，这篇展开了"）——**让读者感到被听见**，这是留存杠杆。

## 六、与 mp-group-push-copy 的分工（防重叠）

| 维度 | mp-group-push-copy | comment-reply-playbook（本 skill） |
|---|---|---|
| 时间点 | 发布**前**（草稿阶段） | 发布**后**（24h~7d+） |
| 产物 | 话术四版 + 置顶三层文案 | 勘误置顶 / 长评论收口 / 抬杠回复 / 选题卡 |
| 落点 | `06_发布参考/群推话术与置顶评论_<日期>.md` | `06_发布参考/评论区维护_<日期>.md`（新建） |
| 触发词 | 群推/怎么转发/往哪个群发 | 评论怎么回/勘误/有人抬杠/读者追问 |

## Pitfalls（实测坑）

- **改已群发正文**：公众号群发后正文不可改，只能补勘误段。不要试图"回去改稿子"。
- **作者连占 3 条以上置顶**：自嗨感重，让位给读者高赞。
- **跟立场型读者公开辩经**：吸黑不吸粉，转私信。
- **评论区问题不沉淀**：每天扫一眼但不入库 = 白扫。必须落 `素材库/选题卡/` 才算闭环。
- **勘误只在评论区改不改 CHANGELOG**：下次复盘时忘了这个坑，会再踩。
- **回复过长**：单条 >3 行 = 把评论区当博客，读者不看。

## Verification（成功凭证）

- 发布包 `06_发布参考/` 下存在 `评论区维护_<发布日期>.md`；
- 若有勘误：CHANGELOG 有 ✏️ 条目 + 置顶评论截图留痕；
- 每周至少 1 张「读者高频问」素材卡落 `素材库/选题卡/`；
- 抬杠回复单条 ≤3 行、无"你错了"等居高临下措辞；
- 已向 boss 明示：**评论区维护 ≠ 回复每条留言**，本 skill 管三层置顶 + 勘误 + 选题沉淀，不做客服式全回。
