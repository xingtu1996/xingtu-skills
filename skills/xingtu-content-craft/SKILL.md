# 行途成稿总装（xingtu-content-craft）

> **定位**：内容生产主线的总装层。把「选题卡/素材卡/闪记」变成「一篇过门禁、可交 mp-publish-sop 排版的 `01_正文/正文_vN.md`」。
> **边界**：本技能**不**管规划（交 `publish-pack-planning` Step 0 论证溯源）、**不**管排版渲染（交 `mp-publish-sop` Step 6 render_wechat.py）、**不**管封面配图（交 `wechat-cover-gen` / `pub-infographic-supplement`）、**不**管建稿（交 `mp-publish-sop` Step 9）。本技能只管「正文 MD 本身」。

## 适用范围守卫（首节，不可移）

读当前工作区根 `AGENTS.md`，正文含「行途」才继续；否则输出「xingtu-content-craft 仅适用于行途工作区」并停止，不读任何业务文件。

## 触发时机

- boss 说「写这篇 / 起草正文 / 开始成稿 / v1 / 把素材写成文章」
- 闪记/素材卡已沉淀、需要扩成可发正文
- 标题已拍板、要往正文里填内容

## 成稿七步（按序，每步有闸门）

### Step 0 规划前置（不重跑，只查凭证）

成稿前必须已完成 `publish-pack-planning`：
- `_规划参考/论证溯源.md` 存在（论点×论证×论据三级表 + 素材出处 + 反证与边界）——缺则停下，回去补论证溯源，**不带着模糊论点硬写**（BUL-006 No Spec No Code）
- 标题已拍板（`00_标题摘要/标题摘要.md` 有「摘要1推荐」或 boss 拍板行）——标题未定不动笔，避免写完再改六载体同步

**闸门**：上述两凭证缺失 = 不进入 Step 1。

### Step 1 正文 v1 起草（素材没有的写【待补】，不编造）

**骨架基准**（对齐已发正例 FDE-04 / ADV-02）：
1. **开头不堆「我是谁」**（坑位 69）：身份由名片 API 承载，正文开头直接进论点。首屏公式在排版层处理（名片→引子图→行途导读→结论→目录），MD 源不需要手写这四块。
2. **先说结论**：首段压成 2 行内核心判断，细节正文展开（坑位：首屏公式 v2）。
3. **实质章节带 h2 + 序号**：`## 1. xxx`、`## 2. xxx` ……，收尾「核心结论」也进目录（坑位 38）。
4. **7:3 字数战略**（坑位 57）：钩子文 1000-1400 字；锚点文 3000-6000 字。一万字长稿压缩到档位，细节放付费/出书。
5. **图文占位**：每大节预告配 `【配图：0X-图名.png】`（占位名要与 `04_配图/` 最终文件名一致，Step 4 密度补齐时对齐）。

**B-009 反幻觉铁律**：
- 素材库没有的数据/引文/案例 → 写 `【待补：xxx】` 占位，**绝不编造**。
- 引用「同系列《XX》」前必须 `grep -r "XX" 素材库/ github/xingtu-vault/ outputs/` 三处核实该文真已发布（坑位 78）；找不到就改写成独立陈述。
- 官方宣传数字与实测分开：宣传口径必须标「公开宣传口径，非作者实测」。

**落盘**：`01_正文/正文_v1.md`，frontmatter 必须含中文 `状态:` 键（坑位 17，如 `状态: 成稿 v1 · 待打磨`）。

### Step 2 de-ai-flavor 去 AI 味（词级）

调用 `de-ai-flavor` skill 扫全文：
- AI 腔词清零：越来越 / 本质上 / 赋能 / 抓手 / 闭环 / 链路 / 颗粒度 / 深度赋能 / 全面提升 等（完整表见 `de-ai-flavor` SKILL.md）
- 空泛口号改真实颗粒：把「极大提升效率」改成「10 次 grep → 3 次图查询」这种数字+场景
- 宣传腔改活人感：去掉「众所周知」「不言而喻」「让我们一起」

**闸门**：`tools/de_ai_flavor_check.py` 退出码 0。

### Step 3 脱敏三查（SAF-004/005/010）

发前必跑：
```bash
python3 tools/privacy_scan.py --fail-fast
```
🔴🟠 计数 = 0 才放行。三查口径：
1. **真名**：中文真名、真实手机号、个人/雇主邮箱**永不上公网**——对外统一「行途 XingTu」；英文名及变体全面禁用（SAF-004/010）。
2. **雇主与业务**：当前雇主名、具体业务名（如「<某电商平台>订单域」这类「平台名+业务域」组合）模糊化 →「某电商平台订单域」（坑位 64，SAF-005/007）。
3. **可反推三元组**：行业 + 精确注册资本 + 管理职位 → 任一组合能定位到具体公司即删改。

### Step 4 PUB-027 量化门禁（成稿必跑）

```bash
python3 tools/de_ai_flavor_check.py
```
量化口径：
- 加粗 `<strong>` ≤ 8 处
- 引用块 ≤ 3 处
- AI 腔词 = 0
- emoji = 0

**坑位 58 同源**：任何重建稿（改数字/改标题/并行产版）都必须整份重跑，不许「只改一处其余沿用」。

### Step 5 信源独立成节（坑位 80，10-10 v3 拍板）

工具与信源**不是**文末无标题一段，而是独立 h2 小节：
```markdown
## N. 工具与信源

**CodeGraph** ｜ 一句话说明 + 链接
（换行）
**数据口径** ｜ 本组量级来自…
```
- 节号接续正文 h2 序号，**目录同步加一条**（坑位 38 同源）
- 外部信源只放链接一行一条（`来源《标题》：https://…`），**不写括号介绍/推荐语**（boss 09-17「不想给别人引流」）
- 同源转载只留一篇；作者一手（参会/白皮书）单列一行不写 URL
- 正文涉及事实已有官方/一手来源时，外部信源控制 ≤ 4 条

### Step 6 首屏结构自检（排版前 MD 自查）

MD 源不需要手写名片/引子图/「关于行途」（这些由 render_wechat.py 自动拼 tail_v5 + inject_profile_card 自动插名片），但要保证：
- 正文 MD 第一张占位 = `【配图：00-封面引子图.png】`（引子图=封面同款，坑位 67/72）
- MD 里**不写** `## 关于行途` / `## 下一篇预告` / `## 欢迎关注` / `## 延伸阅读`（脚本会自动删，手写=重复）
- 无「我是谁」段残留（坑位 69：`grep 我是谁` 全 MD = 0）
- 无「第 X 篇」内部 SOP 术语（坑位 25/55）

### Step 7 交棒

正文 v1 过上述闸门后，交 `mp-publish-sop` Step 2-9 走：事实回源 → 标题撞题 → 图文密度 → 法律合规 → 排版重渲 → 封面三检 → 门禁复跑 → 建稿回查。

## 常见坑（BCI 摘录，详见各下游 skill）

| 坑 | 症状 | 处置 |
|---|---|---|
| 素材没有硬编数据 | 读者追问来源答不出 | Step 1 写【待补】，B-009 |
| AI 腔词残留 | boss 读感「机器味」 | Step 2 de-ai-flavor 清零 |
| 真名/雇主漏脱敏 | privacy_scan 🔴 | Step 3 --fail-fast 阻断 |
| 加粗 13 处超门禁 | PUB-027 不过 | Step 4 把三幕小标题/信源节工具名降普通文本 |
| 信源塞文末无标题段 | boss 要求独立成节 | Step 5 独立 h2 + 目录同步 |
| MD 手写 tail_v5 块 | 与 render_wechat.py 自动拼重复 | Step 6 不手写 |
