# 干系人登记册——建册 · 定名校对 · 存量查错

## 你要解决的事

用户说：

> "帮我建个干系人清单" / "材料里的人名核一下" / "这人的名字对不对" / "全仓查一下人名有没有写错"

**你要把他从「人和名字散落在会议截图、邮件、纪要、转写里，谁是谁全靠脑子记」带到「有一份清单，写任何材料前都能对着核一遍」。**

产物有三种，按他要什么给什么：

| 他要什么 | 你的产物 |
|---------|---------|
| 建册 | 项目文档仓里的**干系人清单文件**（含机器可读的别名索引） |
| 校对 | 材料 vs 清单的**比对报告**（一致 / 别名 / 未登记） |
| 查错 | 全仓**存量错名清单**（文件:行号 + 错写法 + 应改成什么） |

---

## 这个技能为什么存在

- **解决什么问题**：**一个名字写错，后面所有材料都跟着错，而且纠正成本随时间暴涨。**
  三个真实形态（细节已脱敏）：
  ① **拼音猜姓**——从登录名猜人名，把末尾的音节当姓，整个名字反过来（一次错，全仓跟着错）；
  ② **同一人多种写法**——语音转写把一个人转成 4 种拼写，纪要里又是另一种简称；
  ③ **称谓不当**——对外场合把某人的称呼叫错，属于商务事故。
  **错名不会自己暴露**——它只在被人指出来时才暴露，而那时可能已经写进几十份文档了。

- **不解决什么（边界）**：
  - ❌ **不裁定角色和职责**——那是项目周报/项目全景的真相源，本技能只管**名字怎么写**
  - ❌ **不做翻译**——英文名↔中文名互译是 `doc-translate` 的活
  - ❌ **不替人取名**——没查到的人不许猜，标 `[待核实]`
  - ❌ **不改写原文**——逐字稿原文照旧，纠错只体现在**定名**（译文、后续材料、清单）

- **决策依据**：
  - **清单文件放项目文档仓，不放本技能** —— 本技能的 npm 包**公网可达**，
    真实人名进包 = 把项目干系人名单挂公网。技能只提供**方法和脚本**，数据留在项目里。
  - **别名用机器可读的独立一节，不从表格里猜** —— Markdown 表格的列序因项目而异，
    靠解析表格提取别名会在换项目时静默失效。**固定的别名索引节**换哪个项目都读得懂。
  - **否决「拿通讯录/企业微信直接导出当清单」** —— 那只有规范名，没有**常见误写**。
    本技能的价值恰恰在误写列：**没有误写，扫描就无从下手**，防错能力为零。

---

## 三条铁律

1. **不猜**——拼音反推姓名、从邮箱前缀推中文名，是错名的头号来源。**查不到就标 `[待核实]`，不许编。**
2. **误写列是资产**——发现一种新写法（哪怕只出现一次），**立刻补进清单**。这一列越长，防错越强。
3. **校对不改原文**——逐字稿、原始邮件、会议截图原文一律不动；纠错落在**定名**上（译文、材料、清单）。

## 第 0 步：先定位清单（别急着建）

**任何动作之前，先找到项目里已有的干系人清单。已有的比新建的重要。**

```bash
# 按序找——命中即停
ls glossary-people.md 人员名单*.md 干系人*.md 相关方*.md 2>/dev/null
grep -rl "常见误写\|常见误转\|别名" --include="*.md" . 2>/dev/null | head
```

**判据**：找到一个含「规范名 + 别名/误写」的 Markdown → **走第 2/3 步（校对/查错）**；一个都没有 → 走第 1 步（建册）。

找不到但也拿不准时，**问用户一句**「项目里有没有现成的人员名单/词表？」——比建第二份清单强。

> ⚠️ **同时存在多份时**：认「**更新更勤、带误写列**」的那份为主表，其余在表头注明关系，
> 不要建第三份。**两份清单并存 = 下次校验时以谁为准的争论。**

---

## 第 1 步：建册（从痕迹里挖人）

**信息来源按可靠性从高到低**（同一个人在多处冲突时，取靠前的）：

| 优先级 | 来源 | 为什么可靠 |
|:--:|------|-----------|
| 1 | **会议参会名单 / 会议截图头像标注** | 系统生成，名字是本人填的 |
| 2 | **邮件 To / Cc 的显示名 + 邮箱** | 同上，且能反推组织归属 |
| 3 | **项目周报 / 项目全景的编制表** | 有人工确认过 |
| 4 | **会议纪要正文** | 可能已被转写污染 |
| 5 | **语音转写稿** | 最不可靠，只用来**发现**新写法 |

### 怎么挖

```bash
# 邮件：抓显示名与地址
grep -rhoE '"[^"]+"[[:space:]]*<[^>]+@[^>]+>' <邮件目录> | sort -u

# 纪要/转写：抓出现频次高的疑似人名（英文名首字母大写、中文姓名 2-4 字）
grep -rhoE '\b[A-Z][a-z]+ [A-Z][a-z]+\b' <目录>/*.md | sort | uniq -c | sort -rn | head -40
```

### 建表

**每人一行，6 列**（缺的留空，**不要编**）：

| 规范名 | 英文名 / 拼音 | 缩写 | 常见误写 | 角色 | 来源 |
|--------|-------------|:--:|---------|------|------|

- **规范名**：**对外材料只用这一列**。用对方自己填写的写法（邮件显示名 > 会议系统名 > 转写）
- **缩写**：会议截图头像上的标记（如两个字母），纪要用它指代人
- **常见误写**：转写错拼、拼音反写、旧称、错别字、**绰号也放这里**（绰号只在内部用，对外必须用规范名）
- **来源**：这一行的依据在哪（哪个文件/哪封邮件）——**没有来源的行，标 `[待核实]`**

### 同时生成别名索引（**脚本靠它工作**）

在清单文件里加一节，格式固定：

```markdown
## 别名索引（供脚本扫描用，勿改格式）

<!-- 格式：- 规范名 = 别名1, 别名2, 别名3 -->

- 张伟 = Wei Zhang, 老张, 伟哥
- 陈晓明 = Xiaoming Chen, 小明
```

> ⚠️ **规范名写在 `=` 左边，别名在右边**，一行一个人。**别名之间用英文逗号**。
> 这一节是 `scripts/scan-names.sh` 唯一认识的结构——格式变了脚本会报错（不会静默跳过）。

**模板**：`templates/干系人清单.md`，直接拷出来填空。

**放哪**：项目文档仓（人读的那份），**不进技能包**。文件名带日期或不带，按项目文档规范走。

## 第 2 步：定名校对（写材料前 / 出稿后）

```bash
# 用清单比对一份材料
bash scripts/scan-names.sh <清单文件> --check <材料文件>

# 拿不准清单格式对不对，先自检
bash scripts/scan-names.sh <清单文件> --self-test
```

输出三类：

| 标记 | 含义 | 怎么办 |
|:--:|------|--------|
| 🔴 | **命中了「误写」列** | 改成规范名——**这是确定的错误** |
| 🟡 | 命中了**规范名本身**，但在同一文件里**同一人出现多种写法** | 统一成规范名的一种 |
| ⚪ | 出现了清单里**没有的疑似人名** | 查来源；查不到 → 标 `[待核实]`，**别猜** |

**判据**：🔴 归零 + 🟡 归零，才算这份材料的人名干净。

**两种材料，做法不同**：

| 材料类型 | 动作 |
|---------|------|
| **对外材料**（对客/对合作方） | 🔴🟡 必须归零；⚪ 逐个确认——**对外材料出现未登记人名，先问这是谁** |
| **内部材料**（纪要/周报/方案草稿） | 🔴🟡 归零；⚪ 记下来，回头补进清单 |

> 💡 **对外材料额外一条**：称谓也要核——同一人在**内部叫绰号、对外必须叫规范名+职务**。
> 清单的「常见误写」列里，绰号也在，扫出来就是提醒你别把内部叫法带出去。

## 第 3 步：存量错名扫描（全仓查历史欠账）

**误写列建好之后，用它把历史文档里已经写错的找出来。**

```bash
# 扫当前目录（默认不含 .git / node_modules）
bash scripts/scan-names.sh <清单文件> <要扫的目录>

# 只看某个别名（排查某个具体错误扩散到哪了）
bash scripts/scan-names.sh <清单文件> . --alias "某个误写"

# 先看规模，不动手
bash scripts/scan-names.sh <清单文件> . --count-only
```

输出 `文件:行号 → 命中内容`，**按文件分组**，末尾给总数与受影响文件数。

### ⚠️ 改之前的三条

1. **先 `--count-only` 看规模**。几十处直接改；**几百处/上百文件，先报告再动手**（用户可能想先看范围）
2. **确定性排序**：🔴（确定是误写）先改；⚪（疑似）**逐条看上下文**——同一个词可能是
   普通词汇、也可能是另一个人的名字
3. **改完复查**：`--count-only` 应归零。不归零 = 有漏网（可能是大小写/全半角变体）

> **本步不改「原文类」文件**：逐字稿、会议截图、原始邮件、历史归档的**原文照旧**。
> 只改**基于它们产出的材料**（纪要、报告、方案、清单）。
> 判据：**这份文件是"记录"还是"产出"？** 记录不动，产出才改。

---

## 清单文件长什么样

见 `templates/干系人清单.md`。要点：

- **文件头**写清：生成时间 / 真相源是什么 / 与其它名单的关系（谁是主表）
- **主表**（人读）：规范名 / 英文名 / 缩写 / 常见误写 / 角色 / 来源
- **别名索引**（机器读）：固定格式，脚本唯一认的结构
- **版本历史**：每次修正**记下改了什么**——被纠正的错误要留痕，防止改回去

## 排错

| 现象 | 真原因 | 怎么办 |
|------|--------|--------|
| 脚本报「找不到别名索引」 | 清单里没有那一节，或标题被改了 | 加回 `## 别名索引` 一节，格式见模板 |
| 扫描结果全是误报 | 别名是**常见词**（如 `John`、`Summer`） | 把这类词从别名索引里去掉，或只保留**全名**形态 |
| 同一个人的名字死活统一不了 | 清单里**同一个人占了多行** | 合并成一行，旧写法挪进「常见误写」列 |
| 改了材料但读者还是看到旧名 | 改的是**记录类文件**（原文不该动） | 确认目标是产出类文件；记录类只在清单里登记 |
| 扫不到明显写错的 | 该写法**还没进误写列** | 补进「常见误写」+ 别名索引，**再扫一遍** |
| 两个人互相误报 | 两人名字互为对方的别名 | 别名索引里去掉交叉项，改为**全名匹配** |

---

## 红线

- ❌ **不猜人名**——拼音反推、邮箱前缀推中文名，都是错名源头。**查不到就标 `[待核实]`**
- ❌ **真实人名不进技能包**——本技能包发布到**公网可达**的私服；清单数据一律留在项目文档仓
- ❌ **不改原文类文件**——逐字稿 / 原始邮件 / 会议截图 / 历史归档，原文照旧
- ❌ **不擅自批量改**——超过几十处，先给范围和数量，让人决定
- ❌ **不裁定角色**——角色有出入时以项目周报/项目全景为准，本技能只定「名字怎么写」
- ✅ **发现新写法立刻补进清单**——这是本技能越用越准的唯一途径
- ✅ **改完复查**——`--count-only` 归零才算完成
