# 微信群熟人密度安检（mp-group-audience-check）

> 定位：群推话术生成**之前**的受众安检——回答"这个群能不能发公众号"，不是"发什么话术"。

## 范围守卫

读根 `AGENTS.md`，不含「行途」二字则**不执行**——本技能依赖行途专属微信解密库路径，其他项目不适用。

## 快速使用

```bash
PY=${HOME}/.workbuddy/binaries/python/envs/default/bin/python
SCRIPT=${WORKSPACE}/.agents/skills/mp-group-audience-check/scripts/group_friend_check.py

# 按群名关键词查（最常用）
$PY $SCRIPT "PEC"
$PY $SCRIPT "AI Work"

# 已知群 wxid（xxx@chatroom）
$PY $SCRIPT --wxid 49535621631@chatroom

# JSON 输出（供 mp-group-push-copy 等下游技能调用）
$PY $SCRIPT "PEC" --json
```

## 输出说明

脚本自动输出：
- **总人数 / 好友数 / 企微联系人数**
- **熟人密度百分比 + 评级**：
  - 🟢 **<2% 可推**：熟人少，公开推问题不大
  - 🟡 **2%~5% 谨慎**：有少量熟人，用轻量话术、不点名
  - 🔴 **>5% 不推**：熟人密度高，容易被认出，换群或走私域
- **好友名单分两组**：有备注/标签的（你认识且打过标）vs 无标签的（通讯录有但没备注）
- **企微联系人**单独列出

## 编排流程

| 用户意图 | 自动执行 |
|---------|---------|
| "这个群里有我好友吗？" / "能不能在这群发公众号？" | 跑脚本 → 直接报结果 |
| "帮我看看往哪个群推合适" | 对候选群逐个跑脚本 → 按密度排序推荐 |
| 生成群推话术前 | 先跑本技能安检 → 🔴 群跳过或改私域话术，🟢🟡 交 `mp-group-push-copy` |

## 与其他技能分工

- **本技能**：群成员 × 好友交集，回答"能不能推"
- `mp-group-push-copy`：生成群推话术（四版话术+置顶评论），假设已通过安检
- `wechat-channel`：读群消息内容，不做好友交集分析

## 数据精度与边界

| 项 | 说明 |
|----|------|
| 数据源 | `contact/contact_fts.db` + `message/message_*.db` |
| 好友判定（v2） | **有独立单聊消息表 `Msg_<md5(wxid)>` 且消息数>0**。旧版用 local_type=0/1 误把"群里见过但没加的人"算成好友（17→实际3），v2 用单聊表验证修正 |
| 局限 | contact.db 未解密；加了好友但从没聊过天的人可能漏判（无单聊表）；新好友加完后需微信同步+重新解密才识别 |
| 排除项 | boss 自己自动排除；企微联系人（@openim）单列不计入好友密度；群聊表本身（@chatroom）不计入 |
| 时效 | 群成员列表来自本地解密库，新成员入群后需微信客户端同步+可能需 `wechat-channel decrypt` 更新 |

## 铁律

1. **只读**：不修改微信原始库，不写入任何群。
2. **隐私**：本技能输出仅供 boss 本地决策，好友名单**不对外引用、不进发布包、不上公网**。
3. **评级是建议不是判决**：🔴 表示"熟人多需谨慎"，boss 可根据具体人决定是否硬推。
