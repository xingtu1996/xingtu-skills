# 发布包健康检查

> 适用范围守卫（首节，不可移）：读当前工作区根 `AGENTS.md`，正文含「行途 XingTu」才继续；否则输出「pkg-healthcheck 仅适用于行途 XingTu 工作区」并停止，不读任何业务文件。

## 解决什么

发布包分散在多个位置、组件缺东少西无感知。本技能把「组件齐全性体检 + SSoT 全景盘点」封装成可重复管线，跑一次出一份健康度报告 + 待维护者处理清单。

## 组件基线（唯一真源，先读它）

`<工作区根>/产出SSoT/发布包组件基线.md`（必要 10 项 + 完整包必要 4 项 = 14 项）。本技能只编排，基线内容以该文件为准。其他工作区可改用自己的组件基线文件（`scripts/pkg_healthcheck.py` 读取 `references/component-baseline.md`，漂移时同步两处）。

## 触发场景

- 用户说「体检 / 健康检查 / 检查发布包 / 盘点发布包 / 组件齐全吗」
- 月度例行体检、发布前齐套核对、发布包批量治理

## 执行流程（按序）

### Step 1 读组件基线
- 读 `<工作区根>/产出SSoT/发布包组件基线.md`，确认当前 14 项清单（脚本内置清单需与之一致，漂移时改脚本或改基线，两边同步）。

### Step 2 扫工作区发布包位置
- 归档区：`<工作区根>/发布包归档_YYYY-MM/`（按月份归档）
- 待发布驾驶舱：`<工作区根>/待发布/<月>/`
- 轨C待确认区、分发包（标分发物料，不按成稿包体检）
- **排除**：`_废弃副本` 后缀目录（仅备注）、`多平台分发*`、`_archive/_trash/_backup/_调研_*`、`00_*` 规划文件、根级 `*.md`

### Step 3 每包对照体检
- 用 `scripts/pkg_healthcheck.py --root <归档区根>` 扫描，输出每包缺项明细
- 缺项分类：
  - **可自动补齐**（文本组件）：00_README / CHANGELOG / 打磨日志 / 开箱操作单 / 置顶评论 / 标题摘要 / 合集判定 / 群推话术 / 作者素材 / 回流三件套——按包内既有内容与工作区惯例生成
  - **红线待维护者**：封面缺失（维护者偏好只标记不代做）、HTML 需重渲（可代跑 render_wechat）、正文/标题拍板项、口径漂移（如黑底 vs 纯白底）、未排期稿处置

### Step 4 报告落盘
- `<工作区根>/outputs/发布包健康度体检_YYYY-MM-DD.md`：总包数/全齐包数/缺失包数/缺项明细表（包名→缺项→补齐动作→补齐后状态）+ 待维护者处理清单
- 补齐动作逐包留痕（包内 CHANGELOG 或 00_README 版本史追加一行）

### Step 5 可选 SSoT 全景（--full）
- `<工作区根>/outputs/发布包SSoT全景与优化方案_YYYY-MM-DD.md`：分布全景表（位置→包数→是否现行→与现行 SSoT 关系）+ 多真源识别（同名/同编号多处副本，标废弃镜像/修订版/历史归档）+ 优化方案（废弃路径处置、归并建议、检索表建议）——只读盘点 + 方案，不迁移不删除（处置动作等维护者拍板）

### Step 6 留痕
- `${WORKSPACE}/tools/changelog_append.py --type 🆕 --path <报告路径> --desc <一句话> --tool <工具身份>`（行途工作区惯例）

## 红线与坑位
- **封面/配图一律不生成**：维护者偏好封面由维护者拿正文+标题+合集生成，缺封面只标记
- 数据分析一律写「数据待回流」，零编造指标
- 不改正文/排版HTML/既有图片；不碰草稿箱与发布 API
- 禁 `rm` 硬删，涉及删除走 `tools/safety/safe-delete.sh`；批量结构改动先 `tools/safety/backup-before-op.sh`
- 多真源判定：vault 现行归档区为准，local_only 镜像/旧版标废弃不删
- 范围守卫：读根 AGENTS.md 含「行途 XingTu」才执行

## 脚本

`scripts/pkg_healthcheck.py`：核心扫描脚本。`--root <路径>` 扫描该目录下成稿包，对照 14 项组件清单逐包 test -f，输出缺项明细（JSON/表格）。支持 `--exclude-suffix _废弃副本` 等过滤。内置组件清单与基线 SSoT 对齐（漂移时同步修改两处）。
