① 孵化与积累 · 一个技能怎么诞生

这个动作该做成 skill 吗？六步决策树，任何一步「否」就停：
1️⃣ 重复性：本周发生过 ≥2 次？—— 否 → 记笔记，不是 skill
2️⃣ 可描述性：能用「触发词 + 步骤 + 边界」写清？—— 否 → 先写文档
3️⃣ 判断密度：AI 执行需人拍板的点 ≤3 个？—— 否 → 拆成 SOP + 人主导
4️⃣ 上下文性价比：省下的 token > 它的 description 常驻税（预算 <200 字符）？—— 否 → 并入已有技能
5️⃣ 非重叠：检索无同类？—— 有 → 走 evolve「升级」而非「新建」
6️⃣ 边界可写：能写出「它不做什么」？—— 否 → 会被误触发，回炉
✅ 全过 → 走 create-skill：骨架照抄 → 门禁自查 → 发布
💡 孵化提示词模板：「我要把『<动作>』固化成 skill。触发词：<3-5 个口语短句>。它做什么：<一句话>。它不做什么：<边界>。验证方式：<怎么确认做对了>。请按铁律走完骨架→门禁→发布。」—— 边界句和验证句是必填。

② 实践感触 · 踩出来的四条

🛡️ 护城河是治理闭环，不是技能数量。任何人的技能库都会膨胀腐烂——真正稀缺的是「免疫系统」：定期体检（evolve）、反膨胀标尺（5%/200行/16KB）、跨仓蒸馏硬闸门（只读源仓+人审才落地）。「AI 只建议、人拍板」贯穿所有治理动作。
👯 双胞胎要定位，不要共存。仓库里出现过「官方评测版 vs 流程定制版」「外部市场检索 vs 内部池检索」两对同功能技能。解法不是删一个，是在双方 description 里互相声明分工，否则两者都会被误触发。
🧟 僵尸技能是隐形陷阱。把整个仓库误拷进 skills/ 目录（无 SKILL.md）：不生效、不被索引，却让人以为「装了=有效」。体检信号：有目录无 SKILL.md、有 SKILL.md 无触发示例。发现即转正或移除。
💰 安装是有成本的——description 是常驻税。每个技能安装后，它的 description 永久注入每次会话。实测 40 个全装 ≈7.1K token，按场景分包只需 1/4。省 token 的工具反而因为写法不当成为最大税源——最肥的 5 个 description 占了全包 27%。

🔧 脱敏方法论 · 技能出海的可复用资产

技能要跨环境复用（公司→开源、A 团队→B 团队），环境特定信息必须替换为占位符。我们沉淀的统一替换模式（REPL 顺序敏感，先长后短）：

类别模式替换为
个人真名及变体（含大小写、缩写、拼音）regex 全变体${AUTHOR} / 直接删除
组织/项目代号、内部域名词表<COMPANY_REGISTRY> / <COMPANY_GITLAB>
本机绝对路径路径前缀${WORKSPACE} / ${HOME}
平台账号 ID / AppID词表${WECHAT_APPID} 等环境变量占位
产品特定名称（功能性）词表统一品牌词或 <YOUR_*>

替换后必须跑独立交叉验证（词表 grep 归零），不信任单一扫描工具——扫描器会「假绿」。
