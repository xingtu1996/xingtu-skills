# 第一性原理（First Principles）

> - 含义：在指令后追加「从第一性原理出发」，强制 AI 跳过类比推理和现成套路，回归问题本质重新推导
> - 核心机制：常规方案治标，第一性原理方案治本
> - 适用场景：架构设计、故障排查、方案优化、商业模式分析等「想深一层」的问题

## 提示词文本（直接复制使用）

```
请从第一性原理出发，分析/解决：「（这里填入你的问题）」。

要求：
1. 抛开所有现成方案、行业惯例和类比推理，不要套模板；
2. 先拆到最底层：这个问题的根本目标是什么？核心约束是什么？哪些是真正不能动的边界？
3. 从本质重新推导解决方案，而不是修补表面症状；
4. 显式对比两种答案：常规做法是什么（治标）、第一性原理方案是什么（治本）、差异在哪里；
5. 如果必须用类比辅助说明，先交代这个类比成立的前提是什么。

完成后自查：
- [ ] 是从基本事实出发，还是从类比/惯例推的？
- [ ] 隐含假设质疑过吗？「应该这样」是人为惯例还是客观规律？
- [ ] 结论有实测/事实依据吗，还是纯推理？
- [ ] 借鉴了权威观点吗？落地时按本地事实核实了吗（引用≠照抄）？
```

## 反模式（要避免的）

- **类比照搬**：「别人都这么做 / 以前一直这样」当理由，不回到本质
- **惯例当真理**：把惯例当物理定律——人为规则可质疑，客观规律不可改
- **假设未验证**：隐含假设没列出来、没核实就往下走

## 用法示例

- 「请从第一性原理出发，分析：为什么我们的推送服务总是出问题？」（→ 从表面 Bug 挖到底层路由隐患）
- 「请从第一性原理出发，设计：这个功能的成本结构还能怎么优化？」（→ 参考 SpaceX 拆解火箭材料成本重构定价）
- 「请从第一性原理出发，评估：我们该不该自研这套工具链？」

## 使用技巧

- 适合在 AI 给出常规答案后追加一句「从第一性原理重新想一遍」，对比两版差异
- 追问深挖：「你刚才说的边界条件，哪些是行业惯例、哪些是真实约束？」
- 常用于：架构设计 / 故障排查 / 方案优化 / 商业模式判断
