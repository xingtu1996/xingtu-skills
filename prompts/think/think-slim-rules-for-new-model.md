# 为新模型精简既有规则（Slim Rules for New Model）

> - 含义：模型升级后，旧规则里有一批已经过时/重复/过度约束，开一个新会话让 AI 按"四类识别"清单把规则瘦身
> - 核心机制：模型变强后，以前为弱模型写的"分步流程/通用知识/代码可读信息"反而成了负资产——缩小搜索空间、引发字面执行、增加无效 token
> - 适用场景：换了更强模型、新开会话、感觉 AI 变笨了或规则越堆越多

## 提示词文本（直接复制使用）

```
请先搜索并完整阅读【新模型官方 Model Guidance】+【该模型的社区最佳实践】，以其中的建议和实践作为修改依据。

然后检查当前项目中实际生效的规则文件（AGENTS.md / CLAUDE.md / SKILL.md / 其他持久化指令）。

重点识别四类问题：
1. **与新模型不匹配的旧规则**：以前为弱模型写的分步流程、强制自检、必须怎么怎么——新模型本来就会
2. **重复、冲突或过度约束的指令**：同一要求在三处各写一遍；互相矛盾；规定过细导致字面执行
3. **可能导致过度测试/过度搜索/无效委派/额外 token 的规则**：强制每次都跑全量测试、强制先搜索再动手、强制派子代理——新模型可自主判断
4. **已经可以交给模型自主判断、不再需要显式规定的流程**：代码格式、提交规范、目录结构——模型训练语料里都有

在保留必要安全边界、项目私有约束、关键工作流的前提下，直接完成精简与修改。

修改后，简要说明你：
- 删除了哪些（为什么）
- 调整了哪些（改成什么）
- 保留了哪些（为什么不能删）
```

## 反模式（要避免的）

- **把所有规则删光**：项目私有知识（内部平台对接、环境拓扑、主观标准）模型不知道，必须留
- **不看新模型文档就动手**：凭感觉删，删错了更麻烦
- **一次大改不留快照**：改坏了回不去；先备份原文件
- **把"安全边界"也删了**：不可逆动作的门禁（生产部署、删库、发邮件）不能删

## 用法示例

- 换了新模型后：新开会话，不挂工作空间，把这段发过去，让它先读官方 guidance 再瘦身
- 感觉自己的 CLAUDE.md 越写越长：定期跑一次这个提示词

## 使用技巧

- 删之前先分类：L0/L1 平台已吸收的删；L2 项目特有流程保留；L3 价值判断/授权边界必须留
- 判据优于规则：与其写"必须先跑测试"，不如写"合并前测试必须绿"——成功标准可机械验证
- 改完用一次真实任务验证行为没退化，别只看文件大小
- 与 prompt-skeleton-five-elements 的区别：那篇是**写新提示词**的加法骨架（角色/目标/输入/输出/铁律）；本篇是**给旧规则做减法**（识别过时/重复/过度约束/可交模型自主的流程）。一加一减，提示词库两头都要维护。
