# 第一性原理（四层拆解法）

> - 含义：把问题拆回最底层（基本事实/假设/目标/约束），从基本事实重新推导路径
> - 核心机制：方案越打补丁越偏离本质；回到"无法绕开的事实"重新推导，往往得到更简的路径
> - 适用场景：改组织流程、产品架构、修复杂系统、治路径依赖、方案推倒重来

## 提示词文本（直接复制使用）

```
我想解决的问题是：【填写你的问题】。 请用第一性原理把它拆回最底层，区分：1. 已经确认、无法绕开的基本事实；2. 习惯性接受、却没有验证过的假设；3. 真正想实现的目标；4. 现实中的资源与约束。 暂时放下行业惯例和现成方案，只从基本事实、目标和约束出发，重新推导可行路径。 最后请输出：1. 原方案中只在修补表面的部分；2. 从基本事实重新推导出的新路径；3. 这条路径成立的前提；4. 验证它的第一步。
```

## 反模式（要避免的）

- **把惯例当事实**：行业惯例是假设，不是不可绕开的基本事实
- **只拆不推**：拆完四层却没有重新推导路径，等于白拆
- **新路径无前提**：没说清成立前提和验证第一步，容易空转

## 用法示例

- 「我想解决的问题是：团队流程越来越重，文档越写越多但效率没提升」→ 拆出"文档=沟通记忆"事实，重推轻文档+结构化沉淀路径
- 「我想解决的问题是：某功能上线后一直打补丁」→ 回到用户真正目标，可能整条路径都该换

## 使用技巧

- 与仓库内 `first-principles.md`（追加指令版）互补：本篇是完整四层拆解框架，那条是给任意回答追加"从第一性原理重新想一遍"
- 适合在方案纠结时先拆一次，再决定要不要推倒重来
