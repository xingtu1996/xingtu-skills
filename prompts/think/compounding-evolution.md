# 复利进化（Compounding Evolution）

> - 含义：使用→问题→沉淀→反哺→下次更好，越用越强，错只犯一次
> - 核心机制：不靠记忆靠机制——踩的坑提炼成下次自动拦截的规则
> - 适用场景：任何重复性工作、工具链/流程建设、个人知识管理

## 提示词文本（直接复制使用）

```
请按「复利进化」原则处理：「（这次遇到的问题/任务）」。

要求：
1. 使用→问题→沉淀→反哺：这次踩的坑，提炼成下次能自动拦截的机制，错只犯一次；
2. 产出要有落点：功能、调研、复盘都登记到对应档案，不留在会话里；
3. 沉淀落机制不靠记忆：写成规则/清单/检查项，下次自动生效；
4. 只做加法不覆盖：新规则追加式沉淀，不推翻旧规则；
5. 自查：这次做完，系统/工作流比之前强在哪？下次同类问题会被自动拦住吗？
```

## 反模式（要避免的）

- **错了不记**：排查完不落档案，同类错重踩
- **只记不改机制**：写了文档不提炼规则，下次仍靠记忆（靠不住）
- **产出无落点**：做完不登记，经验变黑盒

## 用法示例

- 「按复利进化原则处理：这次线上问题排查」→ 排查完提炼成检查项，下次自动查
- 「按复利进化原则建设：我的提示词库」→ 每用一次发现问题就更新，越用越好用
- 「按复利进化原则处理：这次访谈学到的方法」→ 沉淀成可复用清单

## 使用技巧

- 每个项目/习惯建立「坑→规则→检查」的闭环，用一次长一次
- 判断标准：同样的问题，第二次还靠人记，就是没复利
