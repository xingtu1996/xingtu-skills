# 举一反三（Learn Once Apply Many）

> - 含义：一个坑提炼一类规则，下次同类自动拦截
> - 核心机制：个案修复不算完，抽象成「这类怎么防」并编码成可执行的拦截
> - 适用场景：修 bug、排查事故、写代码时「错只犯一次」

## 提示词文本（直接复制使用）

```
请按「举一反三」原则处理：「（这次踩的坑/修的 bug）」。

骨架：遇错 → 提炼模式 → 同类扫描 → 沉淀规则 → 编码拦截 → 验证拦截

要求：
1. 提炼模式：这个错属于哪一类（并发/幂等/数据一致性/契约/边界）？
2. 同类扫描：全项目搜同模式，找潜伏的同类问题；
3. 沉淀通用规则：写成「这类怎么防」，而不是「这单怎么修」；
4. 编码拦截：把规则落到可执行的检查/门禁/禁止模式；
5. 验证拦截：构造一个同类样例，确认真的被拦住。
```

## 反模式（要避免的）

- **只修个案不推广**：修完即止，同类继续踩
- **每次重新踩**：沉淀不落规则，同类靠人记
- **抽象到实体非模式**：只记「这单咋修」，没提炼「这类咋防」

## 用法示例

- 「按举一反三处理：这个订单超卖 bug」→ 提炼「并发扣减」模式，全项目扫描，加幂等检查
- 「按举一反三处理：这条 SQL 慢查询」→ 提炼「缺索引」模式，扫全库同类

## 使用技巧

- 修 bug 的最后一步永远是：同类还会在哪发生？怎么让机器拦住？
- 「这单咋修」是复利为零，「这类咋防」才是资产
