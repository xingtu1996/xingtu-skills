# 真相第一（Truth First）

> - 含义：实测 > 推断，诚实 > 好看。结论必须有证据，承诺必须落机械验证
> - 核心机制：机器跑出来的才算数；错的数据比没有更危险；撤回想夸大比维护假数字更保值
> - 适用场景：数据汇报、结论判断、承诺兑现、排查问题时把「应该没问题」变成「验证过没问题」

## 提示词文本（直接复制使用）

```
请按「真相第一」原则处理：「（结论/报告/数据）」。

要求：
1. 实测 > 推断：机器跑出来的才算数；没验证的推断必须标注「未验证」，不冒充结论；
2. 诚实 > 好看：结论必须有证据；如果数字错了，撤回夸大比维护假数字更保值；
3. 机械验证：承诺必须落到可执行的验证（命令/脚本/测试/门禁），不靠嘴说；
4. 口径清晰：每个数字标注来源（官方 / 实测 / 估算），没有来源标「待查」；
5. 状态区分：已验证 / 待验证 / 推测，三档分开写，不把推断写成结论。
```

## 反模式（要避免的）

- **臆测代替验证**：没跑就说「应该没问题」
- **推断冒充实测**：推理过程当成实验结果
- **口径漂移**：验证不过关，靠改口径把红灯消掉
- **只报喜不报忧**：藏掉坏数据，让表面指标好看

## 用法示例

- 「按真相第一原则核验：这个性能提升报告」→ 每个数字追问来源和验证方式
- 「按真相第一原则评估：这个方案的效果承诺」→ 把「效果会很好」变成可执行的验证步骤
- 「按真相第一原则排查：为什么这个指标突然异常」→ 回到数据源头核实，不靠直觉下结论

## 使用技巧

- 口头承诺 ×，机械验证 ✓：能落到脚本/测试的承诺才算数
- 看到漂亮数字先问：「这是实测还是推断？口径是什么？」
- 数据误读撑起的指标是负债，越早撤回越保值
