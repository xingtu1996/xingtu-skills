# 声明逐条 VERDICT 审计（Claim-by-Claim Verdict Audit）

> - 含义：面对一份"成效报告/治理方案/推广材料"，对每个量化或定性声明逐条裁决 ✅/⚠️/❌，找夸大、未验证、口径不可比
> - 核心机制：人在写"成果总结"时天然倾向美化；不逐条抠数字口径，就会把估算当实测、把局部当整体
> - 适用场景：评审自己的提效报告、审视一份方法论是否真实有效、识别"营销话术"

## 提示词文本（直接复制使用）

```
你是一位极其严格的审计专家，受命独立核查【这套体系/这份报告】是否真实有效。
你的任务是找出夸大、未验证、逻辑漏洞，而不是表扬。

## 待核查的声明清单
1. **声明：【原文】**
   - 已知实测：【支撑数据】
   - 请判断：
     a. 两个数字的口径是否可比？（一个是估算一个是实测？一个是字节一个是 token？）
     b. 删掉的内容真的是"模型已知"吗？还是特定项目的私有知识？
     c. ROI 数字用的价格档位对吗？有没有缓存命中折扣没算？
     d. 引用的外部论文证据，迁移到当前场景逻辑成立吗？
     e. "功能未退化"是怎么验证的？是配置存在性验证还是行为验证？
2. **声明：【原文】**
   - ...

## 输出格式
每个声明一个 VERDICT：
- ✅ 真实有效
- ⚠️ 部分存疑（哪里存疑）
- ❌ 夸大或未验证
+ 3-5 句严谨理由，必须引用具体数字或逻辑漏洞。

最后给总评：这套体系真实有效的部分 vs 夸大/未验证的部分，以及 3 条最关键的改进建议。
要像最挑剔的审计员，不留面子。
```

## 反模式（要避免的）

- **笼统说"不错"**：不逐条裁决 = 没审计
- **口径混用不指出**："111KB→13KB"里一个是全量内联估算、一个是实测字节，必须点破
- **引用外部证据不审查迁移性**：别人删工具提升表现 ≠ 你删指令提升表现
- **样本量不足还下结论**：治理后只跑了 11 个会话，不能证明"质量不降"

## 用法示例

- 审计一份"精简 harness 后 token 降 8.5 倍、年省 2 万/人"的报告：逐条核对每个倍数的分子分母
- 审视自己写的"AI 提效 40%"：40% 是怎么算的？基线是什么？样本多少？

## 使用技巧

- 把每个声明拆开成"数字 A → 数字 B"，分别问 A 和 B 的口径
- "对比 A/B"类声明，先问有没有真 A/B，还是只有前后自比
- 审计完把 ❌ 的声明从报告里删掉，不然发出去会被人挑出来
