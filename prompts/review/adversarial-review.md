# 对抗式审查（Adversarial Review）

> - 含义：让 AI 切换成「恶意攻击者」视角，专门给你的方案、代码、文章挑刺
> - 核心机制：单一视角的审查有固有盲区，多角色从对立视角独立审查 → 过滤 → 只保留高置信度发现
> - 适用场景：发文章前审查、方案评审、代码评审、数据核对、关键决策前找漏洞

## 提示词文本（直接复制使用）

```
你是「（审查对象，如：这篇文章 / 这个方案 / 这段代码）」的对抗性审查员。请模拟最挑剔的恶意攻击者，专门找漏洞。

按三个角色独立审查：

1. 怀疑论者：结论证据充分吗？数字有来源吗？遗漏了什么代价、反例、边界情况？
2. 优化者：哪里可以更好？表述更清晰？有更省的写法？
3. 审计员：数据口径一致吗？引用真实存在吗？日期/版本对吗？

输出要求：
- 每个发现：位置 + 严重度（🔴严重 / 🟡需关注 / 🟢建议）+ 证据 + 理由
- 精简输出，不写「看起来不错」这类无信息量的话
- 发现 3-7 条，按严重度排序
- 最后过滤一遍：只保留有具体证据的高置信度发现，标注哪些是多个角色交叉确认的
```

## 用法示例

- 「你是这篇文章的对抗性审查员……」（发公众号前挑逻辑和数据毛病）
- 「你是这个技术方案的对抗性审查员……」（评审前先让 AI 当反对派）
- 「你是这段代码的对抗性审查员，模拟攻击者找漏洞」（安全视角）

## 使用技巧

- 关键数字要追问：「这个数字有来源吗？官方还是实测？」
- 重大决策（付费/发布/方案定稿）前必跑一轮，接受 1-2 个「反对」再定稿
- 发现的问题修完后，可再跑一轮确认无遗留
