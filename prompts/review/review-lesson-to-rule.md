# 一次踩坑沉淀为规范（Lesson to Rule）

> - 含义：把一次真实返工/踩坑，结构化沉淀成"规则文件 + 坏案例索引 + 加载指引"三件套，让同类错误不再犯第二次
> - 核心机制：单次教训只留在会话里 = 没沉淀；写进规则文件才是资产；配套坏案例索引让下次开工前能被检索到
> - 适用场景：刚踩完一个坑、返工完一批同类问题、想把"别再这么写"固化下来

## 提示词文本（直接复制使用）

```
你是规范沉淀 Agent。任务：把刚发生的【这次教训】沉淀到项目规范，使后续所有同类工作自动遵循。

## 背景（实战教训）
【什么场景下】，AI 做的【什么产出】出了【什么问题】，对【谁】造成了什么困扰。
已经花了 N 处修正：【列举 2-3 个典型】。需沉淀为规范防止复发。

## 要沉淀的原则（草案，供你整理成正式规范）
- 【原则 1：Do/Don't 一句话】
- 【原则 2】
- 【原则 3】

## 任务
1. 在规则文件【对应位置】加【新章节】，含：
   - 上述原则
   - 正例 vs 反例对照表（一行对一行，一眼看出差别）
   - 引本次教训作为来源
2. 在坏案例索引新增一条：
   - 编号
   - 场景：【什么情况下犯的】
   - 触发：【什么信号出现就是它在犯】
   - 闸门：【正确做法是什么】
   - 关联：[[相关规则文件]]
3. 检查规则加载指引，确认新规则会被命中（没被加载的规则等于没有）。

## 输出
1. 新规则章节内容摘要
2. 坏案例新条目内容
3. 加载指引是否需要动（不动则说明原因）

## 铁律
- 只改规范文档，不动业务代码
- 保持原有文档格式与语气
```

## 反模式（要避免的）

- **只加规则不加索引**：规则写了但开工前不加载，等于没写
- **只写 Don't 不写 Do**："别这么写"不如"应该这么写"有指导力
- **规则写成散文**：没有正反对照表，下次 AI 还是不知道边界在哪
- **教训留在会话里**：下次新会话又从零开始犯

## 用法示例

- AI 写的代码注释里带了一堆内部流程编号，维护同事看不懂 → 沉淀"注释只讲业务逻辑，不讲流程编号"
- AI 总把"管理功能接口"放到"集成接口"路径下 → 沉淀"admin 给前端、integration 给服务间"的分类规则

## 使用技巧

- 正反对照表是核心：一行错例一行对例，AI 下次照着对例写
- 坏案例条目的"触发信号"要具体到关键词/模式，让 grep 能命中
- 一次沉淀不要超过 3 条原则——塞太多规则会被稀释
- 与 review/postmortem-five-questions 上下游：先用复盘五问挖根因，再用本篇把教训固化成规则。与 think/learn-once-apply-many 的区别：那篇侧重**同类扫描+代码级拦截**（全项目搜同模式、写检查/门禁）；本篇侧重**文档化沉淀 SOP**（规则章节含正反例对照表+坏案例索引条目+检查加载指引）。
