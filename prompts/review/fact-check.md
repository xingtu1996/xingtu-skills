# 事实核查（Fact Check）

> - 含义：把任何观点/结论/数据/方案拆成"事实、结论、价值判断"三部分，逐层核查
> - 核心机制：AI 和人类都会产生幻觉；先验证事实，再检查推理链，最后给出"可以相信到什么程度"
> - 适用场景：审查别人观点/方案/数据、成稿前事实核验、防盲从、对抗幻觉

## 提示词文本（直接复制使用）

```
我要核查的说法是：【粘贴观点、结论、数据或方案】。 请先把它拆成：1. 可以被外部验证的事实；2. 从事实推出的结论；3. 其中包含的价值判断。 对于事实部分，请联网核查来源、样本、时间和完整上下文，并标记为：1. 已证实；2. 基本成立，但需要收窄；3. 存在争议；4. 证据不足；5. 明显错误。 在假设相关事实成立的情况下，继续检查：1. 这些事实能否推出当前结论；2. 是否藏着未经验证的假设；3. 是否混淆相关性和因果关系；4. 是否遗漏了其他解释或关键信息；5. 结论在什么条件下成立或失效。 最后请输出：1. 哪些事实可信，哪些需要修正；2. 推理链中最关键的漏洞；3. 补强后的最合理版本；4. 我目前可以相信到什么程度。
```

## 反模式（要避免的）

- **事实与观点混为一谈**：没拆层就直接下判断
- **只核事实不核推理**：事实全对也可能推出错误结论（相关≠因果）
- **忽略价值判断**：把"应该怎样"的偏好当成客观结论

## 用法示例

- 「我要核查的说法是：某工具能省 60% token」→ 拆事实（官方基准）vs 结论（对我也省 60%）vs 价值判断，标出"需收窄"
- 「我要核查的说法是：某某方法论能让人月入过万」→ 拆出宣传话术与可验证证据的差距

## 使用技巧

- 成稿前的最后一道闸：把文中所有数字/机制描述扔进去核查（对症"编造第三方产品机制"类踩坑）
- 输出里"补强后的最合理版本"可直接替换原文表述
