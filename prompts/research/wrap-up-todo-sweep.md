# 会话收口待办搜刮（Wrap-up Todo Sweep）

> - 含义：一个会话聊到一半要切走/收工时，让 AI 把这次散乱聊过的所有事搜刮成一张分级待办清单，不遗漏、能续上
> - 核心机制：长会话里话题是跳着走的——A 聊到一半插 B，B 没说完又跳 C；人脑记不全，AI 有全量上下文，收口时逼它"只干一件事：把待办捞干净"
> - 适用场景：会话变长、话题散乱、准备开新会话、怕上次说的事忘了、需要交接给另一个 AI

## 提示词文本（直接复制使用）

```
准备结束/切换这个会话了。别总结聊天内容，只做一件事：把本次会话里所有"答应要做/提到要做/决定要做但还没做"的事，全部搜刮出来。

输出一张待办表，每行：
- 待办事项（一句话，说清要干什么）
- 出处（这次会话里哪段讨论引出来的，不用贴原文，标"学历 spec / 文章选题 / 工具安装"这类主题即可）
- 优先级（P0 今天必须做 / P1 本周做 / P2 有空再说）
- 下一步动作（具体到"打开哪个文件/给我哪个决策"，不要写"继续完善"这种废话）

纪律：
- 凡是"我觉得可以""是不是该"这种没拍板的，单独列一栏「待我决策」，别混进待办
- 已经做完的事不要列，只列没做的
- 如果发现两条待办其实是一回事，合并并说明
- 最后给我一句"下次开会话，第一句话该说什么"
```

## 反模式（要避免的）

- **让 AI 写会话总结**：总结没用，要的是"没干完的事"；总结留着下次也接不上
- **待办写成"继续优化文章"**：这种话等于没写，必须具体到动作和对象
- **把没拍板的事塞进待办**：你还没决定的事不是待办，是决策项，单列
- **收口时才想起来**：聊到 20 轮以上就该跑一次，别等到 100 轮上下文都快爆了才搜刮

## 用法示例

- 「这个会话聊太散了，收尾一下」→ AI 捞出 12 条待办，分三档，你只看 P0
- 「我要去开新会话了，先帮我把这边没收尾的列一下」→ 拿到清单 + 新会话开场白
- 「这次讨论冒出好几个想法，别让它们飘走」→ 待办表直接落成 spec/看板文件

## 使用技巧

- 这是"离场前"用的，和"入场 recap"配套：离场搜待办 → 新会话开场 recap → 接着干
- 搜刮完让 AI 直接把清单写进一个文件（spec/看板），别只停在聊天里——聊天记录下次就翻不到了
- P0 一般不该超过 3 件；如果 AI 列了 8 个 P0，说明它没认真排优先级，让它重排
- 与 research-handoff-continuation、research/session-recap 配套：本篇只**搜刮待办+待我决策+下次开场白**，轻量；需要完整状态交接（背景/已完成/纪律/关键文件）用 handoff-continuation；新会话入场用 session-recap。离场搜待办 → 新会话开场 recap → 接着干。
