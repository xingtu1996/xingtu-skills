# 私有化模型选型对比（Private Model Selection）

> - 含义：给定硬件/显存/预算约束，让 AI 列出所有可选开源模型并出一张对比表，官网考证，锚定一个对标云平台
> - 核心机制：选型不是只挑"听说最好"的那个，是把约束（硬件卡型、显存、并发、多模态、价格）摊开，横向比完再下结论
> - 适用场景：私有化/本地化部署大模型选型、在不同开源模型之间做决策、评估某块 GPU 能跑多大模型

## 提示词文本（直接复制使用）

```
我们要在自有硬件上跑大模型，请帮我做一份选型对比调研。

【硬约束】
- 硬件：___（如 8 张某国产推理卡 / 合计显存 ___ GB）
- 用途：___（如代码开发辅助 / 多模态问答 / 推理）
- 预算/上线时间：___

【请输出】
1. 候选清单：列 3~5 个满足硬件约束的开源模型（不同档位：轻量 flash 档 / 主力档 / 多模态档），包括——
   模型名、参数规模、上下文长度、是否支持多模态、推理框架（vLLM 等）、对目标硬件的适配情况；
2. 对比表：维度 = 显存占用 / 并发能力 / 生成速度 / 价格或授权 / 硬件生态成熟度，逐项打分或写事实；
3. 锚定一个对标：和我们计划参考的云平台托管版（如某云百炼上的同系列模型）对比，说明私有化能拿到什么、差在哪；
4. 风险与待核实项：哪些数字是官网写的、哪些是我们猜的，列一个"待人工核实清单"，我要留档后自己上官网再确认一遍。

要求：不堆术语；每个判断标来源（官网 / 社区 / 推测）；不要为了推某个模型而藏缺点。
```

## 反模式

- 只推荐一个模型、不给对比——选型的前提是"有得选"，单选项不叫选型
- 把"听说这个新模型很强"当结论——不标来源，官网都没查过
- 忽略硬件约束：拿一个需要 80GB 显存的模型往 512GB/8卡 上套，算都不算
- 不区分"开发主力用的轻量模型"和"偶尔用的大模型"——日常 coding 和重推理需求不是一回事
- 把待核实的数字当成确定结论写进交付物

## 用法示例

> 场景：客户给了 8 张推理卡、合计显存约 512GB，要判断能跑哪个开源模型做开发辅助。
>
> 调研输出：轻量档（某 flash 版，显存够、并发高）、主力档（更大参数版，能力强但推理弱、人要多盯）、多模态档（新出的视觉版，支持图片输入）；对比表把"日常编码谁更顺、显存谁更省、硬件生态谁更成熟"摆开；锚定某云托管同系列，说明"私有化省了数据出域，但要自己扛运维和版本升级"；最后列待核实项（官网价格、并发规格）留给人去查。

## 使用技巧

- "待人工核实清单"是这份调研的安全垫——AI 查来的数字可能过期，必须有人对着官网复核一遍再对外
- 硬件型号本身可以写（如某国产 910B 系列），但不要把它和具体客户项目的部署细节绑在一起写进通用材料
- 如果时间紧，先出"够用且稳"的选项，再附一个"升级后能力提升大"的候选——别一步到位赌最新版
- 并发、显存、上下文长度这三项是硬指标，价格和授权是软指标，先过硬关再谈软
