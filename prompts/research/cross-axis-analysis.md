# 横纵分析法（Cross-Axis Analysis）

> - 含义：用「纵向发展史 × 横向竞品对比」两条轴交叉分析一个研究对象
> - 核心机制：纵轴看"怎么走到今天的"，横轴看"今天跟竞品比有什么区别"；两条轴交叉才能看见历史选择如何演化成今天
> - 适用场景：深度研究产品/公司/人物/技术/行业/事件；需配合 AI 深度研究功能使用效果最佳

## 提示词文本（直接复制使用）

```
研究对象是：【填写产品、公司、人物、技术、行业或事件】。 请使用横纵分析法，对它完成一份可追溯的深度研究。研究截止时间为执行当天。 纵向分析：1. 它在什么背景和需求下诞生，关键推动者是谁；2. 它经历了哪些重要转折、成功和失败；3. 哪些早期选择变成了今天的能力、路径依赖或包袱。 横向分析：1. 选择最值得比较的对象，并说明为什么选它们；2. 用统一维度比较各自的强项、短板和独特性；3. 解释用户、客户或市场为什么选择它，又为什么放弃它。 把两条轴合起来，继续判断：1. 过去形成的能力、路径依赖和约束会怎样影响未来；2. 未来最可能出现哪3条路径；3. 每条路径出现的前提和预警信号是什么。 请遵守这些证据规则：1. 优先使用官方资料、原始数据、论文、财报和访谈等一手来源；2. 重要结论就近标注来源与日期；3. 事实、推断和观点分开写；4. 遇到冲突信息时并列呈现，找不到证据时明确写"暂未核实"。 最后按以下顺序输出：核心结论、关键时间线、横向对比表、详细分析、未来判断、仍待确认的问题。报告需要在10000～30000字之间，语言尽量通俗，不要堆砌资料。
```

## 反模式（要避免的）

- **只纵不横 / 只横不纵**：只看历史或只看对比，都会漏掉"选择如何演化为今天"的关键
- **无来源堆资料**：没标注来源日期的结论不可追溯，违反证据规则
- **事实推断混写**：把推测当事实陈述

## 用法示例

- 「研究对象是：某 AI 编程工具」→ 纵轴拆发展史与架构转向，横轴对比 Cursor/Claude Code 等，判断未来路径
- 「研究对象是：某行业（如出海电商）」→ 历史转折 + 竞品格局 + 三条未来路径

## 使用技巧

- 想半小时建立框架：让它只输出核心结论 + 时间线 + 对比表
- 想深度研究：开启 AI 产品的深度研究/联网功能再贴这个 Prompt，效果是"满血版"
