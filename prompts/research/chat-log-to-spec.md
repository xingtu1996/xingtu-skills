# 聊天记录萃取需求（Chat Log to Spec）

> - 含义：把一堆混乱的多角色聊天记录（微信/会议转述）喂给 AI，让它扮演领域专家，萃取出真正的需求并生成一份可交付的专业文档
> - 核心机制：客户/合作方在聊天里说的话东一句西一句、还夹杂转发和截图，人去读要半天；让 AI 先扮演领域专家识别真实意图，再按交付物标准成文
> - 适用场景：客户在微信里说不清需求要你出文档、会议纪要太碎要转成正式交付物、多方群聊里提取任务

## 提示词文本（直接复制使用）

```
下面是一段混乱的聊天记录/会议转述，里面有多人对话、转发、截图转述，客户/合作方真正想要什么藏在里面。

聊天记录：
【粘贴聊天记录，保留谁在说什么】

请你扮演一名资深的【领域专家，如 API 接口文档专家/解决方案架构师】，完成：
1. 先识别：这段记录里各方真实的诉求是什么？聚焦范围在哪？谁要、用来干什么、为什么急？把"表面说了什么"和"真正要什么"分开；
2. 判断这份记录能不能支撑生成一份【交付物，如接口文档/方案】，还差什么信息、缺的部分要标出来而不是自己编；
3. 基于已有材料，生成一版交付物草稿，面向【读者，如合作方技术评估用】组织内容，以终为始——读者关心什么就侧重什么；
4. 如果材料明显不够，先列缺什么，再给草稿，不要硬编。

注意：对外交付的版本要去掉内部语气和"待确认"式的废话，只留能交付的内容。
```

## 反模式（要避免的）

- **把聊天记录原样堆砌**：不做"表面 vs 真实"的区分，生成的文档就是聊天记录改写，没有专业判断
- **材料不够硬编**：客户只说了三句，AI 自己脑补出一整套接口，交付出去被对面一问就露馅
- **生成内部版当对外版**："本文件为评估框架版""以下为核心方向"这种内部说明写进给客户的文档，很不专业
- **不区分读者**：给合作方看的文档和给自己看的纪要混在一起，对方找不到他关心的点

## 用法示例

- 群里转发："合作方要看接口文档，他们要评估报价，主要是线上下单、产品上传、订单下达，核心是订单/库存/优惠券" → AI 萃出："对方要一份面向报价评估的对接接口清单"，据此出文档
- 销售转述客户需求东一句西一句 → AI 先拆"真实诉求 vs 表面传话"，再补出缺失项清单

## 使用技巧

- 保留发言者身份（谁对谁说的），AI 才能判断这是客户原话还是销售转述
- "以终为始"是关键：先想清楚这份文档给谁看、他拿去干什么，再决定侧重什么
- 缺信息别让 AI 编，让它列"待补充清单"，你拿去问客户比硬编一份安全得多
