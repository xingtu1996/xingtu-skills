# 招聘 JD 信号雷达（Job Posting Signal Mining）

> - 含义：把招聘网站上的真实 JD 当成"行业风向标"，反推出市场现在为什么技能付溢价、你的内容/履历该往哪校准
> - 核心机制：JD 是企业真金白银投票出来的需求——它要求什么，就说明市场缺什么；批量读 JD 比看行业报告更接近一线真相
> - 适用场景：不知道内容账号该讲什么、履历该突出什么技能、判断"人+AI"这类新岗位到底要什么人

## 提示词文本（直接复制使用）

```
我给你一批真实招聘 JD（或岗位截图），请当行业信号雷达来分析，不要只做翻译。

我关心三件事：
1. 这个岗位/这类公司真正想招什么样的人？把 JD 字面要求拆开看——它嘴上写的（技术栈）和真正想要的（独立交付能力？客户沟通？英语？AI 杠杆能力？）分别是什么？
2. 市场信号：这类 JD 集中出现，说明行业在往哪个方向走？哪些能力已经是标配（不再加分），哪些还是溢价项？
3. 对我意味着什么：我是【一句话背景，例如：X 年后端】，这些 JD 里哪些能力是我已经有的、哪些是我缺的、哪些可以直接变成我的内容选题？

输出要求：
- 先给一句结论："这波 JD 在告诉我们……"
- 再分三栏：JD 字面要求 / 真实潜台词 / 我该补或该讲的点
- 最后列 3 个可以直接写的选题，每个选题写一句钩子标题
- 如果 JD 之间互相矛盾（例如都写"AI 原生"但职责还是传统 CRUD），直接指出，别和稀泥
```

## 反模式（要避免的）

- **把 JD 翻译成大白话就完事**：JD 摘要不是雷达，要读出"企业为什么这样招"的潜台词
- **只看技术栈**：JD 里的"独立负责全生命周期""面对客户交付"往往比技术栈更有信号价值
- **看到一个 JD 就下结论**：至少攒 5~10 个同类 JD 再归纳，单个样本会骗人
- **把 JD 当岗位推荐**：这个提示词不是帮你找工作，是帮你校准内容方向和能力地图

## 用法示例

- 粘贴 3 个"AI 原生交付工程师"JD → AI 拆出"嘴上要 Java、实际要一个人扛从需求到上线"，并给你 3 个选题
- 「我参与面试候选人，发现现在都问 AI 工具」→ 反过来用：你的面试经验本身就是一手素材，把"面试官现在在筛什么"写成文章

## 使用技巧

- 每次刷招聘软件时顺手截 3~5 个感兴趣的 JD 丢给 AI，积累成"信号库"
- 选题钩子标题要有"反常识感"：例如"JD 上写 Java，实际面试考的是你能不能用 AI 一周交付"
- 对求职者：这个雷达也能反推简历该突出什么——JD 里反复出现的词，就是你简历里必须出现的词
