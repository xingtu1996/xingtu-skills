# 小改动别重写整个文件（Minimal Edit，不整文件重写）

> - 含义：让 AI 改一处小地方时只动相关行，而不是把整份文件重写一遍
> - 核心机制：新一代模型容易为一处小改动重写全文——结果往往一模一样，但白烧输出 token 和时间；一条规则即可拉回增量修改行为
> - 适用场景：AI 改代码、改文档、改配置时账单偏高、文件被整体覆盖、想保留原文格式与无关段落

## 提示词文本（直接复制使用）

```
对文件做小改动时，只修改相关的那几行。除非文件很短、或大半内容都要改，否则不要重写整个文件。保持其余部分的原文、格式和无关段落不动。
```

## 反模式（要避免的）

- **一处改动整文件重写**：改个函数名结果全文被重排，diff 几百行，谁也审不动
- **为省 token 而该改不改**：文件本来就短、或大半都要动时，硬拆成多次小编辑反而更贵
- **顺手「优化」无关段落**：把这条和「验证完就停」一起用，防止改着改着越改越多

## 用法示例

- 追加到系统提示或每次对话开头一句，所有项目全局生效
- 「只改这个函数里的参数默认值，别动其他地方」→ 配合本提示词，输出 diff 只有几行
- 长文档改一个错别字/一句话，用这条防止整篇被重写

## 使用技巧

- 重写出来的文件通常和原文一字不差，差别只在账单和时间
- 与「自主推进」一起用，长任务跑下来的账单不会因为反复整文件重写而失控
- 文件 < 20 行或目标改动 > 一半内容时，本规则可放宽
