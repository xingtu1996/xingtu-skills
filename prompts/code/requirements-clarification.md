# 需求澄清（Requirements Clarification）

> - 含义：写码前把「模糊需求」烤成「精确约束」，一次问清省返工
> - 核心机制：逐项追问八个维度，答不了标「待确认」，清零才开工
> - 适用场景：接需求、写代码、做方案、建功能前

## 提示词文本（直接复制使用）

```
请先做「需求澄清」，再开始任何工作：「（需求描述）」。

逐项追问，答不了标「待确认」，模糊清零才允许开工：

1. 业务目标：解决什么问题？不做会怎样？
2. 用户故事：谁用？想做什么？为了什么？
3. 验收标准：怎么算做完？可验证吗？
4. 边界：包括什么？排除什么？和别的需求冲突吗？
5. 依赖：依赖谁？谁依赖我？
6. 数据：要动哪些数据？旧数据兼容吗？
7. 风险项：涉及钱/库存/权限这类，退出怎么办？重试？回滚？

追问完给出：已确认清单 + 待确认清单。
```

## 用法示例

- 「先做需求澄清：做一个导出功能」→ 问清导出范围/格式/权限/性能，再开工
- 「先做需求澄清：重构这个接口」→ 问清兼容性/调用方/数据迁移

## 使用技巧

- 最贵的返工来自「不懂就问被跳过」——AI 猜着做，做完不对
- 待确认项清零之前不开工，是省返工的第一道闸
