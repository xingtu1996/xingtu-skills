# 测试左移（Shift-Left Testing）

> - 含义：测试越早越便宜——验证从生命周期末端移到最早可行阶段
> - 核心机制：质量是造出来的，不是测出来的；Bug 越晚发现，修复成本指数上升
> - 适用场景：开发任务、代码评审、需求规划

## 提示词文本（直接复制使用）

```
请按「测试左移」原则规划/执行：「（开发任务）」。

要求：
1. 验证从末端移到最早：能本地验证就不等联调，能单测就不等系统测试；
2. 质量是造出来的不是测出来的：先写验收标准/用例，再写代码；
3. 金字塔自下而上：单测→契约→接口→端到端→安全，底座先铺厚；
4. 反模式自查：有没有全堆到后期测？有没有写完才补测试？
5. 每个验证都要能跑：编译→启动→接口→合并，一步不缺。
```

## 用法示例

- 「按测试左移原则规划：这个接口开发」→ 先写验收用例，本地起服务验证，再提交
- 「按测试左移原则评审：这个功能的测试方案」→ 检查是否都在最末端兜底
- 「按测试左移原则执行：今天的新功能」→ 单测先行，本地全链路验证

## 使用技巧

- 修复成本参考：单测阶段 1x，系统测试 40x，生产 100x+——越早越省
- 验收标准（用例）先于代码写，本身就是最好的需求澄清
