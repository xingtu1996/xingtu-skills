# 架构图可视化评审（Architecture Diagram Review）

> - 含义：让 AI 画技术架构图/网络拓扑图时，先用「连得起来 + 线型编码语义 + 少即是多」三条硬标准验收，而不是画一坨方框
> - 核心机制：图的价值在于"关系"，不是"元素清单"；同样的连接关系，用线型和颜色区分，胜过一堆图例文字
> - 适用场景：交付架构图、网络拓扑图、部署图、流程编排图，尤其是给客户/领导看的一版

## 提示词文本（直接复制使用）

```
请作为资深前端 UI/UX 与技术架构专家，帮我评审/重画这张架构图：

【硬标准】
1. 模块必须真正"连起来"——箭头/连线要表达清楚谁连谁、谁调谁，不要让模块各自孤立悬浮；
2. 用线型和颜色编码"连接语义"，并在图例里说清楚：
   - ⇄ 双向：如私有网络已打通 / 代码双向 push-pull
   - → 单向：如仅从官方源下载依赖
   - ↓ 登录/操作：如用户登录、鉴权动作
3. 少即是多：能不说的注释别写在连线上，连线标签不要压在箭头上盖字；自闭环的中间件（本地 DB、缓存等）也要画进去，别漏。

【输出要求】
- 先出 1 个版本给我看，不要一次出 N 版；
- 文字标签精简，别把"私有网络已打通""secret 扫描前置"这种过程说明留在图上——图上只放关系；
- 如果要交付，中文一版、英文一版。

【兼容提示】如果用 Mermaid：旧版本号只支持一层 subgraph（别嵌套）、不要用双向箭头 <-->、边标签用双引号包起来。
```

## 反模式

- 画了一堆模块框，但模块之间没有连线——变成了"组件清单截图"，不是架构图
- 所有连线都是同一种颜色同一种箭头——看不出来"谁是双向、谁是单向下载、谁是登录动作"
- 把"私有网络已打通""某某前置扫描"这种过程/结论文字写在图上——图是看关系的，注释别喧宾夺主
- 连线标签直接盖在箭头上、字和线叠在一起——看着像 bug
- 自闭环的本地组件（本地数据库、缓存、消息队列）漏掉，只画对外连接

## 用法示例

> 场景：要交付一张"开发环境外部连接架构图"给客户安全团队。
>
> 原始版本：一堆框悬浮、连线乱、所有线同色。
> 套用本提示词后：操作人 ↓ 登录到环境；环境 ⇄ 双向连私有代码仓库；环境 → 单向连官方依赖源；图例里用三种线型+三种颜色说明各自语义；本地中间件画成自闭环节点；过程说明全部去掉，只留关系；最后中英各一版。

## 使用技巧

- "先出一个版本我看"是关键——别让 AI 一口气出三版，沟通成本更高；先看骨架对不对，再调细节
- 颜色编码一旦定了就全篇统一，别同一个语义用两种颜色
- 如果图里信息实在多，宁可拆成两张图（主架构 + 局部放大），也别在一张上堆
- 给非技术读者看的图，节点少、文字大；给技术评审看的，可以多放规格（如部署规格、责任方）
- 每次调完，用浏览器/截图工具实际打开看一眼渲染效果，别只信源码
