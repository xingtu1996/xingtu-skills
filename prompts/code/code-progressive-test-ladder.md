# 由简到繁测试四级阶梯（Progressive Test Ladder）

> - 含义：本地测试按"接口→集成→E2E→部署"四级逐级递进，上一级没绿不进下一级，把部署后的问题成本压到最低
> - 核心机制：越往后修一个问题成本越高（改代码 1 分钟，改完等部署 20 分钟，线上排查 2 小时）；用阶梯强制把问题拦在最便宜的那层
> - 适用场景：新功能联调、多服务链路、部署前自测

## 提示词文本（直接复制使用）

```
你是测试实施员。按"由简到繁"四级阶梯组织本次测试，上一级全绿才进下一级。

## 阶梯
① **集成接口测试**（最便宜）
   - 准备：服务本地启动，确认端口/依赖
   - 执行：curl 逐接口打，单接口响应正确即过
   - 通过标准：每个接口返回预期码 + 关键字段

② **集成测试**（多服务全链路）
   - 准备：造测试数据（虚拟配置/主数据/库存）
   - 执行：走通业务链路，数据在 A 服务→B 服务→C 服务流转
   - 通过标准：每跳都落库/发 MQ 正确，SQL 查得到

③ **E2E**（前端 + 后端）
   - 准备：前端启动 + 后端起
   - 执行：模拟真实用户操作，点按钮/填表单/提交
   - 通过标准：界面反馈正确 + 后端落库正确

④ **部署**（SIT/UAT）
   - 准备：合并到集成分支，触发部署
   - 执行：部署后回归核心链路
   - 通过标准：线上环境真实下单/真实流程跑通

## 每一级都要写
- 准备（数据/脚本/前置）
- 执行步骤
- 通过标准
- 常见坑（上一级踩过的写下来）

## 输出
四级清单，每级标注：已完成 / 阻塞 / 待跑。
```

## 反模式（要避免的）

- **一上来就部署测**：部署后发现接口字段错，来回部署一晚上
- **跳过接口直测 E2E**：前端报错了不知道是前端问题还是后端问题
- **没有通过标准**："测一下"不是测试，"这个接口返回 code=0 且 X 字段=Y"才是测试
- **不写常见坑**：同样的坑每次部署后才发现

## 用法示例

- 新功能跨 5 个服务：先 curl 每个新接口 → 再造数据走全链路 → 再用浏览器点一遍 → 最后部署
- 修 bug：先本地复现 → 改完本地四级跑一遍 → 再提 MR

## 使用技巧

- 造数据是最大隐性成本，提前把"造一条测试订单"的 SQL 固化下来
- 每级的"常见坑"累积成 SOP，下一个功能直接复用
- ③ E2E 这步最容易省，但线上翻车多半省了这步
- 与 code/shift-left-testing 的区别：那篇是**测试左移原则**（验证从末端移到最早、金字塔自下而上、先写验收标准）；本篇是**执行时的四级门禁**（接口→集成→E2E→部署，上一级全绿才进下一级，每级写准备/通过标准/常见坑）。原则+落地 SOP 配套用。
