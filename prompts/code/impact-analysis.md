# 影响分析（Impact Analysis）

> - 含义：改一处之前，先评估对系统其余部分的连锁影响
> - 核心机制：改动点→级联影响（3 跳）→消费者清单→契约变更→风险分级
> - 适用场景：改接口/数据结构/消息/共享数据前的必修课

## 提示词文本（直接复制使用）

```
请按「影响分析」评估这次改动：「（改动内容）」。

1. 改动点：改了哪一层（接口契约 / 业务逻辑 / 数据结构 / 外部调用 / 消息）？
2. 级联影响：改一个地方，下游 3 跳内谁会被影响？
3. 消费者清单：谁调用我？谁消费我的消息？谁读写同一份数据？
4. 契约变更：接口/数据结构/消息体变了吗？旧调用方兼容吗？
5. 风险分级：P0 直接坏/数据错乱｜P1 逻辑偏差｜P2 边缘情况；
6. 建议测试范围：哪些场景必须回归？
```

## 用法示例

- 「按影响分析评估：给这个接口加一个必填参数」→ 找出所有调用方，评估兼容
- 「按影响分析评估：改这张表的字段」→ 找出所有读写方，评估迁移

## 使用技巧

- 单文件小改动（无跨模块出口）不需要；动接口/数据结构/共享数据必查
- 消费者的遗漏是线上事故最常见来源：谁在消费我的消息/数据，逐个列
