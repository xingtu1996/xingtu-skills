# 数据排查（Data Investigation）

> - 含义：从「数据不对」出发，用证据链定位根因，不凭印象
> - 核心机制：先查单点，再查全量——一条记录确诊 ≠ 全部同因
> - 适用场景：数据不一致、金额对不上、状态错乱、报表异常

## 提示词文本（直接复制使用）

```
请按「数据排查」定位：「（数据不对的现象）」。

1. 现象：单号/时间/异常值，先写清；
2. 证据链：每条结论 = 数据查询结果 + 时间戳 + 来源（代码/日志），不凭印象；
3. 先查单点，再查全量：一条记录确诊 ≠ 全部同因，必须查影响面数量；
4. 区分个案与批量：修复要覆盖「这类」而不是「这单」；
5. 只读先行：生产数据先查不改，确认根因和影响面后再谈修改；
6. 输出：根因 + 证据 + 影响面 + 建议。
```

## 用法示例

- 「按数据排查：为什么这笔订单的金额不对」→ 单号→相关表→SQL 证据→影响面
- 「按数据排查：这个报表数字和明细对不上」→ 口径/来源/时间戳逐层查

## 使用技巧

- 「单点当全量」是最常见的坑：修好一条，同类批量漏
- 每条结论都带 SQL/日志证据，复查才有据可依
