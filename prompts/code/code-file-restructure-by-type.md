# 散文件按类型分层整理（File Restructure by Type）

> - 含义：一个产出目录下散了 20+ 个文件（报表/对账/字段映射/测试记录/交接…），按专业类型分子目录归置，同时修所有引用
> - 核心机制：散文件找不到、引错路径；但直接 mv 会断历史和引用，必须 git mv + 全局修引用
> - 适用场景：项目 deliverables/ 目录膨胀、知识文档散放、整理一堆产出物

## 提示词文本（直接复制使用）

```
你是【项目】产出分层整理员。把【目录】下 N+ 份散文件做专业分层（按内容类型归子目录），提升可读可检索。

## 现状
【目录】下现有大量散文件：【列举类型：报表/对账/字段映射/测试记录/接口文档/官方映射/审查报告/交接管理/验收标准/设计思想…】

## 任务
1. **盘点**：ls 完整列出文件（含已有子目录）
2. **设计分层**（按专业类型，参考现有文件语义）：
   - 01-对账与范围（清单/遗漏核对/旧现状/官方映射）
   - 02-设计与映射（字段映射/数据链路/方案）
   - 03-测试验证（测试记录/集成清单/验收标准）
   - 04-审查报告（对抗审查/资深专家审查/一致性盘点）
   - 05-交接与上线（交接管理/上线方案/权限申请/工单描述）
   - db/（SQL，保持或归 db-*）
   - 按需增删层（文件少就合并，勿过度）
3. **移动**：用 `git mv` 移文件到对应子目录（**保留 git 历史**）
4. **修引用**：grep 哪些文档引用了旧路径（execution-log / STATUS / 交接 / 验收标准 / README），**更新引用路径**（防断链）
5. 每层可加 README.md（一句话定位 + 文件索引）

## 注意
- 只动目录内部组织 + 引用更新，**不改内容**、不改代码
- 保持文件名（只移动位置，便于 git 历史追溯）
- 更新后验证：grep 旧路径无残留（除明确的 git 历史）

## 产出
分层方案（目录结构）+ 移动文件清单 + 更新引用清单 + commit。
```

## 反模式（要避免的）

- **直接 mv 不用 git mv**：git 历史断了，blame 看不到
- **只移动不修引用**：别的文档还指向旧路径，全是死链
- **分太多层**：文件少还分 8 层，找文件比原来还慢
- **改了文件内容**：整理就是整理，别顺手"优化"内容

## 用法示例

- 26 个文件散在 deliverables/ 根目录：按"对账/设计/测试/审查/交接"5 层归置
- 一堆 wiki 文章散在根目录：按"业务概念/接口链路/踩坑/测试方法"分层

## 使用技巧

- 分层先设计再动手：想清楚 5 层够不够，别边移边改主意
- git mv 是关键——保留历史比什么都重要
- 修引用后 grep 一次旧路径，确认零残留
- 每层 README 一句话定位，比目录名还重要
