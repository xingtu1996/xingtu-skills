# 质量门禁（Quality Gates）

> - 含义：提交前用检查项强制拦质量红线，未过门禁不进主干
> - 核心机制：门禁 = 强制关卡，不是自觉承诺；每项都要有可复核证据
> - 适用场景：提交代码前、发布前、评审前

## 提示词文本（直接复制使用）

```
请按「质量门禁」检查，提交前逐项过：「（改动）」。

□ 基础测试：单元测试覆盖了吗？
□ 接口验证：关键接口全链路通了吗？
□ 端到端：关键场景走通了吗？
□ 安全：高危漏洞清零了吗？
□ 数据一致性：涉及钱/库存/权限的，退出/重试/回滚想清楚了吗？
□ 影响面：3 跳内下游查了吗？谁消费我的改动？
□ 对抗审查：有人从反对角度挑过刺吗？无严重阻塞项？
□ 证据：每项过门的依据可复核吗（测试报告/日志/截图）？

未过门禁不进主干；禁止跳过检查。
```

## 用法示例

- 「按质量门禁检查：这个功能可以提交了吗」→ 逐项给证据，缺哪项补哪项
- 「按质量门禁评审：这个 MR 能合吗」→ 重点查数据一致性和影响面

## 使用技巧

- 门禁的意义是「机器/清单强制」而非「口头承诺」——每项都要拿得出证据
- 最危险的三件事：跳过检查、空检查、过不了就删检查
