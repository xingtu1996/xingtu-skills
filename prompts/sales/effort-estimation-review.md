# 工作量估算对抗复核（Effort Estimation Review）

> - 含义：先基于功能清单和代码实盘点出人天，再反过来用对抗视角逐行质疑每一项——是不是重复计费、是不是没核代码就拍脑袋、有没有利润空间
> - 核心机制：人天估算最容易"拍脑袋 + 重复算 + 不算利润"；先估一遍，再当敌人挑自己的错，估出来的数才敢对外报
> - 适用场景：售前人天报价、功能清单估算、项目排期评审

## 提示词文本（直接复制使用）

```
我需要给一个【项目类型，如全渠道中台/系统对接】做工作量（人天）估算。材料包括：功能清单【粘贴或引用】、代码仓库【路径/描述】、会议纪要【粘贴要点】。

请分两步做：

第一步，估算：
- 按功能清单逐项拆人天，既有功能可合并，新增功能要写明新增原因；
- 结合代码仓库的真实情况判断哪些能复用、哪些要新做——不要默认从零开发；
- 产出一张表：模块 / 功能 / 人天 / 复用或新增 / 依据。

第二步，对抗复核（用挑刺的眼光再审一遍你自己的估算）：
- 有没有重复计费？（比如测试费已经含在功能里，又单列了一笔测试人天）
- 哪些数是没核代码就拍的？标出来去验证；
- 对外口径和内部成本是不是分开了？对外数能不能站住、有没有利润空间；
- 客户砍需求时，哪些模块可以整体删掉、依赖关系是什么；
- 最后给一个"对外区间"和"内部成本底线"，并说明每项的依据强弱。

输出：一张人天明细表 + 一段估算策略说明，确保这个价我们有的赚。
```

## 反模式（要避免的）

- **不看代码直接拍人天**：说"全部要新做"，核完代码发现复用率很高，报价就虚高丢单
- **重复计费**：测试费单列一遍、渠道对接里又把测试算进去，被客户一拆就穿帮
- **不分对外数和内部数**：把内部成本直接写进给客户的表，或者反过来用对外数当自己底线
- **不留删减空间**：客户一砍需求，整套报价就崩；要提前标出可整体删除的模块和依赖

## 用法示例

- 渠道对接报了 90 人天 → 对抗复核发现"测试已经含在功能里，又收了一遍渠道测试"，砍掉重复项
- 说"4 个渠道全部从零对接" → 核代码发现复用率为 0，这 40 人天是真实工作量，保留
- 对外报一个区间、内部成本更低 → 复核毛利是否真的够，不够就调

## 使用技巧

- 第二步"对抗复核"才是这个提示词的灵魂，别省——自己估的数自己挑一遍
- 每一项人天都要能说出"依据是什么"（复用率/会议纪要/代码核查），说不出的就是拍的
- 对外给区间、对内留底线，两个数分开写，别混在一张表里给客户
