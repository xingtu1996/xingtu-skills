# 向老板汇报稿精简（Executive Status Brief）

> - 含义：把一份事无巨细的工作进展，改写成老板 30 秒能读完的版本——只留进度和判断，删掉风险、臆测数字和"需要您支持"
> - 核心机制：老板在售前/推进阶段只关心"项目到哪了、我方产品合不合适、要不要继续"，不关心你列的风险预案和内部毛利测算；不知道的数字一个都别写
> - 适用场景：双周汇报、给上级的进展同步、项目进度邮件/微信汇报

## 提示词文本（直接复制使用）

```
我有一份工作进展汇报稿，是写给老板看的。老板的关注点是：项目推进到哪一步、我方产品适配度如何、下一步节奏。

请按以下规则帮我精简改写：
1. 只保留：项目定位一句话 + 当前进度 + 我方产品/方案的位置 + 下一步；
2. 删掉所有风险点和预案——售前/推进阶段老板不关心，他有疑问会主动问；
3. 删掉所有我没有把握的数字（毛利、成本、人天区间），不知道的绝不写，不替商务/产品下结论；
4. 删掉"需要您支持/需要您决策"这类列表——老板真要支持会主动找我，写了反而越位；
5. 突出我方在整个方案里的位置和价值，不要把联合方写得比我方还重；
6. 结论先行，一段话说清，语气是"同步进度"而不是"求助"。

原文如下：【粘贴你的汇报草稿】
```

## 反模式（要避免的）

- **售前阶段狂列风险**：老板还没决定投不投，你先把风险说一堆，显得项目不靠谱
- **臆测毛利/成本数字**："毛利空间够的"这种话，商务没确认就别写，被追问就露馅
- **罗列"需要您支持三件事"**：老板会觉得你在推活；他有需求自然会问
- **把合作方写成主角**：汇报里要突出我方产品的位置，不能让客户听完以为主方案是别人

## 用法示例

- 草稿里写了"风险点：某渠道审核周期长、合作方接口配合度、某能力要补强" → 全部删掉，老板不关心
- 草稿里写"内部成本 375 人天，毛利空间够" → 删掉，这是商务口径，技术别替他说
- 草稿结尾"需要您支持三件事" → 删掉

## 使用技巧

- 写完自己读一遍：每句话问"老板不主动问，我该不该写？"——不该写的全删
- 数字只有"有人确认过、可以对外"才留；凡是"我估计""我感觉"一律删
- 这是给上级的"进度同步"，不是"方案评审"，别混淆场合
- 与 executive-briefing-prep 互补：那篇是**动笔前**扒历史纪要摸老板口味、预判追问；本篇是**草稿成型后**删风险/臆测数字/求助，只留进度与判断。先摸口味再删废话。
