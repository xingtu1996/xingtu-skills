# 仓库履历挖掘（Repo Ledger Mining）

> - 含义：让 AI 扫你本机各项目仓库 + git 提交历史，自动提炼一份"经得起背调的项目履历"，不靠你凭记忆吹
> - 核心机制：git 历史不会撒谎——提交时间、代码量、模块数、活跃周期都是硬证据；人回忆自己做过什么时容易夸大或遗忘，用仓库数据校准
> - 适用场景：写个人站项目介绍、更新简历、整理作品集、把散落在各项目的经验蒸馏成可发布内容

## 提示词文本（直接复制使用）

```
请扫描我以下目录里的代码仓库，帮我提炼一份可信的项目履历：
【列出你的项目根目录，例如 ~/work/a 、~/work/b】。

对每个仓库/项目，按这个模板输出：
1. 项目是什么（一句话，面向外行也能懂）
2. 技术栈（从代码里读出来，不要我猜）
3. 规模量级（大概多少模块/代码量，用 git 统计佐证）
4. 我的真实角色和活跃周期（从我的提交记录看，不要写"主导"这种没法验证的词）
5. 有什么可以对外讲的亮点（难题/排障/提效数字，必须是我真实做过的）

纪律：
- 所有"我做了什么"必须有 git 提交或代码文件佐证；我没提交过的别替我编
- 涉及雇主的项目一律脱敏：公司名换成"某零售集团"这类模糊说法，业务数据只留量级不留真实数字
- 规模数字（代码量、模块数）标清楚是估算还是实统计
- 最后汇总一张表：项目名 / 我的角色 / 可对外讲的亮点 / 适合放进简历还是个人站
- 如果某个项目其实是我刚 clone 下来没怎么动，直接标出来，别误算成我的履历
```

## 反模式（要避免的）

- **让 AI 凭空写项目介绍**：没有 git 佐证的履历，面试背调一问就穿
- **把每个仓库都算成"我的项目"**：clone 下来的、别人主导的、自己只改了几行的，要如实降级标注
- **不脱敏直接上公司名**：在职状态下，项目名、行业、技术栈组合起来很容易被认出来，宁可模糊
- **夸大"主导/架构师"**：git 历史里你的提交占比会说话，头衔写小不丢人，写大翻车才丢人

## 用法示例

- 「扫一下我这几个工作目录，更新我个人站上的项目介绍」→ AI 产出带佐证的项目卡片
- 「简历上项目经历全是我凭记忆写的，帮我校准哪些有依据、哪些在吹」→ 逐个项目标"有据/存疑/需删"

## 使用技巧

- 规模数据让 AI 自己跑 `git log --author`、`cloc` 之类的统计，比你口述准
- 提炼完别直接发：自己再过一遍，把"AI 觉得厉害但其实是团队功劳"的部分删掉
- 这套履历反过来就是素材库：每个"难题 4 小时→40 分钟"的排障故事，都是一篇技术文章的骨架
